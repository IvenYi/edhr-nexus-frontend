# React 模板设计器字段设计专项规格

整理日期：2026-07-10

适用范围：`gmp-platform/frontend/src/pages/master-data/template-designer-react/`

## 1. 背景

React 模板设计器已经具备 `字段设计 / 表单设计 / 流程设计` 三个页签，以及基础字段注册、画布拖拽、字段绑定、表格画布、导入画布等能力。当前字段设计仍停留在最小闭环：可以新增字段、修改类型和基础属性，且仍存在不符合追溯要求的删除入口；后续需要调整为只允许启用或停用字段，并形成适合业务追溯、结构化填报、报表分析和版本演进的字段模型。

本规格用于重新定义字段设计的目标、字段生命周期、字段类型、导入生成字段、字段数据报表和画布属性面板绑定规则。后续实现必须围绕该规格收敛，避免把字段定义、画布展示、填报规则和历史数据混在一起。

## 2. 总目标

字段设计的最终目标不是维护一组 UI 控件，而是建立每份表单长期稳定的结构化数据模型。

核心目标：

1. 每份表单拥有一套跨版本共享的字段模型。
2. 字段一旦创建，不允许物理删除，只能启用或停用。
3. 字段类型允许修改，但历史数据必须按照发生时的字段快照解释。
4. 字段模型只描述“数据是什么”，不描述“这个版本中怎么填、怎么展示”。
5. 必填、只读、隐藏、默认值、占位文案等属于画布绑定配置。
6. 导入 Excel/Word 后，用户可以从画布内容中批量生成字段候选。
7. 字段进入字段池后，再拖拽到画布或用于生成可填写 form 表单。
8. 字段设计页右侧提供只读数据报表，支持查看字段产生的数据、操作日志、变更记录和审计日志。
9. 所有枚举、签名、引用、附件、图片等特殊字段都必须保存机器值和用户可读值，不能只展示 `0/1/true/false/id`。

## 3. 非目标

本阶段不做以下内容：

1. 不在字段设计页直接配置必填、只读、隐藏、默认值、占位文案。
2. 不允许在字段设计页修改历史数据。
3. 不做同一字段在同一版本画布中多处展示的复杂能力。
4. 不在导入后自动把整张表单扫描结果直接写入字段池。
5. 不自动把导入识别出的表格区域转换为子表。
6. 不把字段推导类型、推导置信度、推导原因写入正式字段模型。

## 4. 核心概念

### 4.1 字段模型

字段模型描述表单要采集和沉淀的结构化数据。字段模型属于表单本身，不属于单个版本。

同一份表单下，不管有多少模板版本，都共享同一套字段模型。

### 4.2 版本画布

版本画布描述某个模板版本中字段如何展示、放在哪里、用什么控件填写，以及布局、分页、样式等。版本画布可以变化，但字段身份必须稳定。

### 4.3 字段绑定

字段绑定表示某个画布组件或单元格控件使用了某个字段。绑定中保存当前版本的展示和填写规则，例如必填、只读、隐藏、默认值和占位文案。

### 4.4 字段数据报表

字段数据报表是当前表单已经产生的结构化数据的只读视图。它用于查询、追溯、审计，不用于修改数据。

### 4.5 字段快照

字段快照是在填报数据发生时保存下来的字段定义副本。字段后续改名、改类型、改选项、停用，都不影响历史数据解释。

## 5. 数据归属

推荐的归属关系如下：

```text
FormTemplate
  fieldModel
    groups
    fields
  versions
    version 1
      canvas
      workflow
      fieldBindings
    version 2
      canvas
      workflow
      fieldBindings
  records
    record 1
      fieldValues with snapshots
```

字段模型归属于 `FormTemplate`。版本只决定字段如何在当前版本中被使用。

## 6. 字段模型

### 6.1 字段结构

字段模型建议结构：

```ts
interface DesignerField {
  id: string;
  code: string;
  name: string;
  type: FieldType;
  groupId?: string;
  sortOrder: number;
  status: 'enabled' | 'disabled';
  description?: string;
  typeConfig: Record<string, unknown>;
}
```

字段属性说明：

| 属性 | 含义 | 规则 |
|---|---|---|
| `id` | 内部唯一标识 | 系统生成，永远不可改，用于画布绑定、历史追溯、版本迁移 |
| `code` | 结构化数据 key | 系统自动生成，普通用户不需要填写，管理员高级模式可改 |
| `name` | 字段名称 | 业务用户主要维护项，可修改 |
| `type` | 字段类型 | 11 类之一，允许修改 |
| `groupId` | 字段分组 | 可选，默认未分组 |
| `sortOrder` | 排序号 | 系统维护，用于字段列表、生成 form 表单和导入排序 |
| `status` | 字段状态 | 只允许启用或停用 |
| `description` | 字段说明 | 描述字段业务含义 |
| `typeConfig` | 类型结构配置 | 只保存决定数据结构的配置 |

### 6.2 字段状态

字段只允许两个状态：

| 状态 | 含义 | 行为 |
|---|---|---|
| 启用 | 可用于新版本设计和填报 | 可拖拽、可绑定、可进入字段建议确认结果 |
| 停用 | 不再用于新设计 | 不允许新绑定；历史版本、历史数据仍可查看 |

字段不允许物理删除。字段停用不影响历史版本中已存在的绑定和历史数据解释。

### 6.3 字段编码

字段内部保存 `id` 和 `code` 两个标识：

| 标识 | 用途 | 是否可改 |
|---|---|---|
| `id` | 系统内部稳定标识 | 永远不可改 |
| `code` | 结构化数据 key、报表字段、接口字段 | 默认自动生成，高级模式可改 |

编码规则：

1. 新建字段时自动生成 `code`。
2. 导入表单生成字段时，根据字段名称自动生成 `code`。
3. `code` 在同一表单字段模型内必须唯一。
4. 字段名称修改后，不自动修改 `code`。
5. 只有用户主动重新生成或管理员高级编辑时才修改 `code`。
6. 已产生数据、被报表引用或被接口引用的字段，修改 `code` 必须二次确认并进入审计日志。

### 6.4 字段分组和排序

字段分组和排序是字段池管理能力，不是画布样式。

字段分组用途：

1. 管理字段列表。
2. 生成可填写 form 表单时作为区块。
3. 导入字段候选时按表单区域归类。
4. 报表筛选和字段查找。

排序号用途：

1. 控制字段卡片列表顺序。
2. 控制生成 form 表单顺序。
3. 保留导入源文件从上到下、从左到右的语义。
4. 保存后重开顺序稳定。

第一版中，`sortOrder` 由系统维护。用户通过拖拽排序调整，不直接手填数字。

## 7. 字段类型

字段一级类型收敛为 11 类：

1. 文本
2. 数字
3. 日期时间
4. 签名
5. 超链接
6. 附件
7. 图片
8. 单选
9. 多选
10. 引用
11. 子表

### 7.1 字段类型矩阵

| 一级类型 | 典型用途 | 字段本身配置 | 默认画布控件 | 导入推导 | 填报输出 |
|---|---|---|---|---|---|
| 文本 | 名称、批号、规格、备注、说明 | 短文本/长文本 | 输入框/文本域 | 名称、编号、规格、备注、说明 | `string` |
| 数字 | 数量、温度、压力、金额、百分比、检验值 | 整数/小数、精度、单位 | 数字输入框 | 数值列、单位、上下限、数量、温度、压力 | `number` 加单位元数据 |
| 日期时间 | 日期、时间、记录时间、检验时间 | 日期/时间/日期时间、精度 | 日期时间选择器 | 日期、时间、年月日、记录时间、生产日期、有效期 | ISO 时间或格式化时间 |
| 签名 | 操作人、检验员、复核人、审核人、批准人 | 签名值结构、签署方式要求 | 签名控件 | 签名、签字、审核人、复核人、操作人、检验员 | 签名对象 |
| 超链接 | 外部链接、文档链接、系统跳转 | 链接值结构 | 链接输入/展示 | URL、http、https、链接、地址 | 链接对象 |
| 附件 | 文件上传、证明材料、报告附件 | 文件值结构、允许类型 | 附件上传 | 附件、上传、证明材料、报告、文件 | 附件数组 |
| 图片 | 照片、图像、截图、检测图片 | 图片值结构、允许来源 | 图片上传/展示 | 图片、照片、图像、截图、拍照 | 图片数组 |
| 单选 | 是/否、合格/不合格、状态、等级 | 选项列表 | 单选框/下拉 | 是/否、合格/不合格、正常/异常 | 单个选项值 |
| 多选 | 缺陷项、适用项、多个检查项 | 选项列表 | 复选框组 | 复选框符号、多个可勾选项 | 选项值数组 |
| 引用 | 人员、部门、物料、设备、产品、供应商、字典 | 引用对象、显示字段、保存字段、是否多选 | 引用选择器 | 部门、物料、设备、产品、供应商、字典、型号 | 引用对象或数组 |
| 子表 | 检验明细、步骤记录、物料清单、重复行 | 子字段结构 | 子表格 | 不自动推导，用户框选区域后转换 | 对象数组 |

### 7.2 文本

字段配置：

```ts
typeConfig: {
  textMode: 'short' | 'long';
}
```

说明：

- `short` 用于姓名、批号、规格、编码等短内容。
- `long` 用于备注、说明、异常描述等长内容。
- 最大长度、占位文案、是否多行展示属于绑定配置或控件配置。

### 7.3 数字

字段配置：

```ts
typeConfig: {
  numberMode: 'integer' | 'decimal';
  precision?: number;
  unit?: string;
}
```

说明：

- 数字字段必须保证结构化值可用于计算、统计和报表。
- 是否允许负数、最小值、最大值可以作为字段结构配置，也可以在绑定中覆盖为当前版本校验规则。
- 显示单位应进入用户可读值。

### 7.4 日期时间

字段配置：

```ts
typeConfig: {
  mode: 'date' | 'time' | 'datetime';
  precision?: 'minute' | 'second';
}
```

说明：

- 日期时间字段的结构化值建议统一存 ISO 或标准时间字符串。
- 展示格式属于绑定或控件配置。

### 7.5 签名

字段配置：

```ts
typeConfig: {
  signatureMode?: 'electronic' | 'manual' | 'password' | 'mixed';
}
```

签名字段用于责任确认，不等同于人员引用。

导入时以下语义默认推导为签名：

- 签名
- 签字
- 审核人
- 复核人
- 批准人
- 确认人
- 操作人
- 检验员
- 记录人
- 制表人
- 负责人

填报值示例：

```json
{
  "userId": "u001",
  "userName": "张三",
  "signedAt": "2026-07-10 10:20:00",
  "signatureId": "sig001",
  "method": "password"
}
```

用户可读值示例：

```text
张三，2026-07-10 10:20:00 签署
```

### 7.6 超链接

字段配置：

```ts
typeConfig: {
  linkMode?: 'external' | 'internal' | 'document';
}
```

填报值示例：

```json
{
  "label": "检验报告",
  "url": "https://example.com/report",
  "target": "_blank"
}
```

### 7.7 附件

字段配置：

```ts
typeConfig: {
  allowedFileTypes?: string[];
}
```

说明：

- 文件数量限制、大小限制、是否必传属于绑定配置。
- 附件字段必须保存文件名、文件 ID、文件类型、大小等可读信息。

### 7.8 图片

字段配置：

```ts
typeConfig: {
  allowedSources?: Array<'upload' | 'camera'>;
}
```

说明：

- 图片展示尺寸、上传数量、是否允许预览属于绑定配置。
- 图片值应能在报表中展示缩略图和文件名。

### 7.9 单选和多选

字段配置：

```ts
typeConfig: {
  options: FieldOption[];
}
```

选项结构：

```ts
interface FieldOption {
  id: string;
  label: string;
  value: string;
  sortOrder: number;
  status: 'enabled' | 'disabled';
}
```

规则：

1. 普通用户只维护选项名称。
2. 系统自动生成稳定 `value`。
3. 管理员高级模式可修改 `value`。
4. 同一字段内 `value` 必须唯一。
5. 选项不物理删除，只启用或停用。
6. 选项新增、停用、改名、改值都进入审计日志。
7. 历史数据必须保存 `displayValue`。

单选填报值示例：

```json
{
  "value": "qualified",
  "displayValue": "合格"
}
```

多选填报值示例：

```json
{
  "value": ["scratch", "dirty"],
  "displayValue": "划伤、脏污"
}
```

### 7.10 引用

引用字段按通用引用设计，不锁死成人员和部门。

字段配置：

```ts
typeConfig: {
  sourceType: 'user' | 'department' | 'material' | 'equipment' | 'product' | 'supplier' | 'dictionary' | string;
  multiple?: boolean;
  displayFields: string[];
  valueFields: string[];
  searchFields?: string[];
  filters?: Record<string, unknown>;
}
```

第一版 UI 可以预置：

- 人员
- 部门
- 物料
- 设备
- 产品
- 供应商
- 字典

后续如果系统有主数据配置中心，引用源可以由后端下发。

单选引用值示例：

```json
{
  "source": "equipment",
  "id": "eq001",
  "code": "EQ-001",
  "label": "灭菌柜 1 号"
}
```

多选引用值示例：

```json
[
  {
    "source": "material",
    "id": "m001",
    "code": "MAT001",
    "label": "一次性注射器"
  }
]
```

### 7.11 子表

子表用于重复明细，例如检验明细、步骤记录、物料清单。

字段配置：

```ts
typeConfig: {
  columns: DesignerField[];
}
```

规则：

1. 导入 Excel/Word 时不自动推导子表。
2. 表格区域先作为普通画布表格还原。
3. 用户框选连续区域后，可以手动执行“转换为子表”。
4. 转换时系统根据表头辅助生成子字段建议。
5. 用户确认后生成子表字段。

填报值示例：

```json
[
  {
    "index": 1,
    "itemName": "外观",
    "standard": "无破损",
    "result": "无破损",
    "conclusion": "qualified"
  }
]
```

## 8. 字段创建流程

字段创建遵循“先有名称，再有类型”的业务操作逻辑。

### 8.1 手动创建

流程：

```text
点击新增字段
  ↓
输入字段名称
  ↓
系统临时推荐字段类型
  ↓
用户确认或切换类型
  ↓
系统自动生成字段编码
  ↓
用户填写字段说明、分组和类型结构配置
  ↓
保存字段
```

说明：

- 推荐类型只是临时辅助，不写入正式字段模型。
- 正式字段只保存用户确认后的 `type`。
- 不保存 `inferredType`、`confidence`、`推导原因`。

### 8.2 导入后创建

流程：

```text
导入 Excel/Word 到画布
  ↓
用户框选/多选含字段名称的单元格
  ↓
点击生成字段
  ↓
系统取选中单元格文本作为字段名称
  ↓
打开字段建议确认面板
  ↓
系统推荐类型、编码、分组
  ↓
用户二次确认
  ↓
字段进入字段管理列表
```

规则：

1. 选中的单元格代表“单元格文本是字段名称”，不是“单元格是填写位置”。
2. 空白单元格不生成字段候选。
3. 合并单元格按一个字段候选处理。
4. 多选区域中，每个有文本的单元格都生成一个候选字段。
5. 字段名称需要清洗冒号、空格、换行等无意义字符。
6. 重复字段名称需要提示合并或保留多个。
7. 确认后字段进入字段池。
8. 原画布不做标记。
9. 不自动绑定画布控件。

## 9. 字段建议确认面板

字段建议确认面板用于把用户选中的画布文本转换为正式字段。

面板列建议：

| 列 | 说明 |
|---|---|
| 来源位置 | 页码、行列或坐标 |
| 原始文本 | 单元格原始内容 |
| 字段名称 | 清洗后的字段名称，可编辑 |
| 推荐类型 | 系统临时推荐，可修改 |
| 字段编码 | 自动生成，高级可编辑 |
| 字段分组 | 可批量设置 |
| 状态 | 新建字段、绑定已有字段、忽略 |
| 操作 | 确认、忽略、合并重复、定位来源 |

面板能力：

1. 批量确认。
2. 批量修改类型。
3. 批量设置分组。
4. 合并重复字段。
5. 定位到画布来源。
6. 忽略不需要的候选。

字段确认后进入字段池，不自动产生画布绑定。

## 10. 字段设计页

字段设计页分为左侧字段管理列表和右侧数据报表。

### 10.1 左侧字段管理列表

左侧以卡片形式展示所有字段。

卡片展示：

- 字段名称
- 字段类型
- 字段编码
- 字段状态
- 字段分组
- 当前版本是否已使用
- 是否停用

列表能力：

1. 搜索字段名称和编码。
2. 按字段类型筛选。
3. 按启用/停用筛选。
4. 按分组展示。
5. 拖拽调整排序。
6. 点击卡片筛选右侧数据报表。
7. 启用或停用字段。
8. 查看字段审计日志。
9. 高级模式编辑字段编码。

不提供：

- 删除字段。
- 必填、只读、隐藏、默认值配置。
- 直接修改历史数据。

### 10.2 右侧数据报表

右侧是当前表单的数据报表，只读。

未选择字段卡片时，展示当前表单所有字段的数据记录。选择某个字段卡片时，只展示该字段相关的数据记录。

表格列建议：

| 列 | 说明 |
|---|---|
| 发生时间 | 字段值产生或变更时间 |
| 字段名称 | 使用历史快照名称 |
| 字段类型 | 使用历史快照类型 |
| 数据值 | 用户可读值 |
| 表单版本 | 数据来自哪个模板版本 |
| 业务记录 | 所属填报或业务记录 |
| 操作人 | 创建或修改人员 |
| 状态 | 正常、已更正、已作废等 |

查询能力：

1. 按字段筛选。
2. 按发生时间筛选。
3. 按填报人或操作人筛选。
4. 按表单版本筛选。
5. 按状态筛选。
6. 按关键字查询。
7. 分页。

### 10.3 数据行详情

点击数据行打开详情抽屉或弹窗。

详情建议分为：

| 页签 | 内容 |
|---|---|
| 数据详情 | 字段快照、机器值、用户可读值、版本、来源记录 |
| 操作日志 | 谁在什么时候创建、提交、查看、审核 |
| 变更记录 | 值从什么变成什么，原因是什么 |
| 审计日志 | 字段定义、类型、选项、编码等变化 |

数据报表不允许修改数据。历史数据更正应走独立的数据更正和审计流程。

## 11. 画布字段使用

### 11.1 可拖拽字段列表

字段拖拽逻辑：

```text
可拖拽字段 = 启用字段 - 当前版本已绑定字段
```

规则：

1. 启用字段且当前版本未绑定时，出现在可拖拽字段列表。
2. 字段拖到画布后，从可拖拽字段列表移除。
3. 字段从画布移除或解绑后，重新回到可拖拽字段列表。
4. 停用字段不允许新绑定。
5. 同一字段在同一版本默认只允许使用一次。
6. 第一版不做多处展示或只读镜像。

### 11.2 字段绑定结构

画布绑定配置建议结构：

```ts
interface FieldBinding {
  fieldId: string;
  displayLabel?: string;
  required?: boolean;
  readonly?: boolean;
  hidden?: boolean;
  defaultValue?: unknown;
  placeholder?: string;
  helpText?: string;
  widgetConfig?: Record<string, unknown>;
}
```

绑定配置归属于当前版本画布，不归属于字段模型。

### 11.3 属性面板

字段拖到画布后，点选该字段控件，在画布属性面板中配置当前版本的字段使用方式。

属性面板分区建议：

| 分区 | 内容 |
|---|---|
| 字段信息 | 字段名称、编码、类型、状态，只读展示 |
| 绑定关系 | 当前组件绑定哪个字段，支持解绑和切换 |
| 填写规则 | 必填、只读、隐藏、默认值 |
| 展示规则 | 显示名称覆盖、占位文案、帮助说明 |
| 控件规则 | 根据字段类型配置当前控件表现 |
| 样式配置 | 宽高、对齐、字体、边框等画布样式 |

属于画布绑定的配置：

- 是否必填
- 是否只读
- 是否隐藏
- 默认值
- 占位文案
- 帮助说明
- 显示名称覆盖
- 控件展示规则
- 控件宽高和样式

### 11.4 切换绑定字段

属性面板允许切换绑定字段。

规则：

1. 当前组件绑定字段 A 时，允许切换为字段 B。
2. 切换后字段 A 释放，重新回到当前版本可拖拽或可绑定字段列表。
3. 字段 B 被占用，从当前版本可拖拽或可绑定字段列表移除。
4. 如果字段 B 已被当前版本其他组件使用，不允许直接切换，除非先解绑原组件。
5. 切换后保留通用样式配置，例如宽高、字体、边框。
6. 如果字段类型不同，控件规则需要兼容性检查。
7. 类型不兼容时，提示用户切换后将重置控件配置。

提示示例：

```text
已切换绑定字段：产品名称 -> 批号
```

不兼容确认示例：

```text
当前控件配置与新字段类型不兼容，切换后将重置控件配置，是否继续？
```

## 12. 填报数据快照

每笔字段值保存时必须包含字段快照和用户可读值。

建议结构：

```ts
interface FieldValueRecord {
  recordId: string;
  templateId: string;
  templateVersionId: string;
  fieldId: string;
  fieldCodeSnapshot: string;
  fieldNameSnapshot: string;
  fieldTypeSnapshot: FieldType;
  fieldTypeLabelSnapshot: string;
  fieldConfigSnapshot: Record<string, unknown>;
  value: unknown;
  displayValue: string;
  occurredAt: string;
  operatorId?: string;
  operatorName?: string;
}
```

解释优先级：

1. 优先展示 `displayValue`。
2. 如果缺失 `displayValue`，使用 `fieldConfigSnapshot` 解释机器值。
3. 最后才尝试用当前字段配置解释。

## 13. 审计日志

字段相关变化必须进入审计日志。

需要记录的动作：

1. 新增字段。
2. 修改字段名称。
3. 修改字段编码。
4. 修改字段类型。
5. 修改字段分组。
6. 启用字段。
7. 停用字段。
8. 修改字段类型配置。
9. 新增选项。
10. 停用选项。
11. 修改选项名称。
12. 修改选项值。
13. 修改引用对象。
14. 字段绑定到画布。
15. 字段从画布解绑。
16. 切换绑定字段。

审计日志必须使用用户可读语言。

字段类型变更示例：

```text
字段【检验结果】类型变更：单选 -> 文本
```

选项变更示例：

```text
字段【检验结果】选项变更：
- 新增选项：让步接收
- 停用选项：待复核
- 修改选项名称：OK -> 合格
- 修改选项值：ok -> qualified
```

绑定切换示例：

```text
画布组件绑定字段变更：产品名称 -> 批号
```

## 14. 导入推导规则

导入推导只用于临时建议，不进入字段模型。

### 14.1 推导优先级

当名称同时命中多个类型时，按以下优先级推荐：

1. 签名
2. 引用
3. 日期时间
4. 数字
5. 单选或多选
6. 附件、图片、超链接
7. 文本

### 14.2 签名推导

命中以下词语优先推荐签名：

- 签名
- 签字
- 审核人
- 复核人
- 批准人
- 确认人
- 操作人
- 检验员
- 记录人
- 制表人
- 负责人

### 14.3 引用推导

命中以下词语推荐引用：

- 部门、科室、班组 -> 部门
- 物料、原料、包材、物料编码 -> 物料
- 设备、仪器、设备编号 -> 设备
- 产品、产品名称、规格型号 -> 产品
- 供应商、厂家 -> 供应商
- 字典、类别、类型 -> 字典

### 14.4 日期时间推导

命中以下词语推荐日期时间：

- 日期
- 时间
- 年月日
- 生产日期
- 有效期
- 检验时间
- 记录时间

### 14.5 选择推导

命中以下语义推荐单选：

- 是否
- 合格/不合格
- 是/否
- 正常/异常
- 通过/不通过

多项勾选、复选框符号、缺陷项、适用项等推荐多选。

### 14.6 子表推导

导入时不自动推导子表。

用户需要主动框选区域并执行“转换为子表”。系统只在该向导中辅助推导子字段。

## 15. 报表独立化预留

字段设计页右侧数据报表先放在设计器内，但数据结构和接口应按未来可独立成“表单数据报表/数据中心”设计。

预留能力：

1. 独立路由打开某表单的数据报表。
2. 跨版本查看同一表单数据。
3. 按字段分组生成报表列。
4. 支持导出。
5. 支持更细粒度权限控制。
6. 支持从数据行进入完整审计链路。

## 16. 验收标准

后续实现满足以下标准才算闭环：

1. 字段模型只保留 `id/code/name/type/groupId/sortOrder/status/description/typeConfig` 等定义属性。
2. 字段不允许删除，只允许启用或停用。
3. 字段类型允许修改，修改进入审计日志。
4. 必填、只读、隐藏、默认值、占位文案出现在画布绑定属性面板，不出现在字段定义页。
5. 字段设计页左侧以卡片展示字段池。
6. 字段设计页右侧展示只读数据报表，支持筛选、查询、分页。
7. 点击数据行能查看操作日志、变更记录、审计日志。
8. 导入后能通过选择含字段名称的单元格生成字段候选。
9. 字段建议确认面板支持批量确认、修改类型、设置分组、忽略、定位来源。
10. 字段确认后进入字段池，不自动绑定画布，不标记原画布。
11. 当前版本同一字段只允许使用一次。
12. 字段拖到画布后从可拖拽字段列表移除。
13. 字段解绑后回到可拖拽字段列表。
14. 属性面板允许切换绑定字段，并正确释放旧字段、占用新字段。
15. 枚举、签名、引用、附件、图片等字段的历史数据必须展示用户可读值。
16. 单选、多选选项不允许物理删除，只允许启用或停用。
17. 字段值保存时包含字段快照和 `displayValue`。

## 17. 实施建议

建议分阶段实现：

1. 调整字段模型和字段注册表。
2. 改造字段设计页为左侧字段卡片 + 右侧数据报表壳子。
3. 将必填、只读、隐藏、默认值、占位文案迁移到画布绑定属性面板。
4. 增加当前版本字段使用状态和可拖拽字段列表。
5. 增加导入后画布选区生成字段候选和确认面板。
6. 增加字段审计日志和字段快照结构。
7. 接入真实数据报表接口和审计详情。

其中第 6、7 阶段可能涉及后端数据模型和接口，应单独评审后再实现。
