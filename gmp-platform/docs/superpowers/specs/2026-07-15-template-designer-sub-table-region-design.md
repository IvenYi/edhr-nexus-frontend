# React 模板设计器子表区域设计规格

整理日期：2026-07-15

适用范围：`gmp-platform/frontend/src/pages/master-data/template-designer-react/`

## 1. 背景

React 模板设计器已经具备字段设计、表单设计、画布单元格框选、子表字段下钻、子表字段拖拽到子表区域等基础能力。后续子表能力不能只停留在“把一个子表字段框在画布上”，还需要支持业务经理在画布上定义重复数据结构，让一线操作员在填报时按固定行列或动态新增的方式录入明细数据。

子表使用场景可以分为三类：

1. 已知记录数量：用户知道表格由多少行或多少列组成，可以在画布上直接框选固定范围。
2. 未知记录数量：用户只知道一条记录的填写结构，填报时由操作员动态新增行或列。
3. 二维交叉矩阵：先形成一张固定或动态表，再让行维度和列维度交叉填报，例如“检验项目 × SN 号”的结果矩阵。

第一版实现应优先完成场景 1 和场景 2，但底层数据结构必须为场景 3 预留扩展位，避免后续重构子表核心模型。

## 2. 目标

第一阶段目标：

1. 支持用户在画布中框选单元格区域并设为子表区域。
2. 支持普通记录型子表，数据结构统一为对象数组。
3. 支持固定重复：框选多行或多列后，按固定数量生成记录。
4. 支持动态重复：框选一行作为模板，填报时按行新增记录。
5. 支持按行填报和按列填报两种布局方向。
6. 支持子表字段消费式拖拽到子表区域内。
7. 支持将多个子表字段组成一条记录模板。
8. 支持子表区域跨分页。
9. 为二维矩阵子表预留 `mode: 'matrix'` 和 `dimensions` 结构。

非目标：

1. 第一版不实现二维矩阵填报运行时。
2. 第一版不实现检验项目自动带出和 SN 横向动态交叉。
3. 第一版不做复杂公式联动、跨行聚合、跨子表引用。
4. 第一版不允许子表中再创建子表。
5. 第一版不把画布上所有表格线都自动推导成子表，需要用户明确设置。

## 3. 核心抽象

子表不应被理解为普通组件，而应被理解为画布中的一个结构化数据区域。

核心模型：

```ts
interface SubTableRegion {
  id: string;
  fieldId: string;
  mode: 'record' | 'matrix';
  ranges: SubTableRegionRange[];
  repeat: SubTableRepeatConfig;
  recordTemplate: SubTableRecordTemplate;
  dimensions?: SubTableMatrixDimensions;
  presentation: SubTablePresentationConfig;
}

interface SubTableRegionRange {
  pageId: string;
  range: CanvasSelectionRange;
  order: number;
}
```

字段说明：

| 字段 | 含义 |
|---|---|
| `id` | 子表区域实例 ID，同一个子表字段未来允许在不同版本或不同区域使用 |
| `fieldId` | 绑定的子表字段 ID |
| `mode` | 子表模式，第一版只开放 `record` |
| `ranges` | 画布中框选的单元格区域，允许由多个分页片段组成 |
| `repeat` | 固定或动态重复配置 |
| `recordTemplate` | 一条子表记录由哪些字段组成，以及这些字段在区域内的相对位置 |
| `dimensions` | 矩阵模式预留，第一版不开放配置 |
| `presentation` | 展示配置，例如表头、边框、动态新增按钮位置 |

跨分页子表使用 `ranges` 表示多个连续或非连续分页片段。每个片段都有独立 `pageId` 和单页内 `range`，通过 `order` 保持填报和导出的顺序。

## 4. 普通记录型子表

普通记录型子表使用：

```ts
mode: 'record'
```

最终保存数据统一为对象数组：

```ts
{
  "明细表": [
    {
      "字段A": "value",
      "字段B": "value",
      "字段C": "value"
    },
    {
      "字段A": "value",
      "字段B": "value",
      "字段C": "value"
    }
  ]
}
```

无论画布上是按行展示还是按列展示，数据结构都不变化。画布布局只是填写视图，数据语义永远是一组记录。

### 4.1 记录模板

记录模板定义一条记录内部字段如何排列。

```ts
interface SubTableRecordTemplate {
  direction: 'row' | 'column';
  anchor: {
    row: number;
    col: number;
  };
  fields: Array<{
    fieldId: string;
    rowOffset: number;
    colOffset: number;
    rowSpan?: number;
    colSpan?: number;
  }>;
}
```

按行填报时，一条记录通常占一行，字段从左到右排列。

按列填报时，一条记录通常占一列，字段从上到下排列。

### 4.2 固定重复

固定重复适用于用户已知记录数量的场景。

```ts
interface FixedRepeatConfig {
  type: 'fixed';
  count: number;
  stride: number;
}
```

示例：

```ts
repeat: {
  type: 'fixed',
  count: 10,
  stride: 1
}
```

如果方向是 `row`，表示记录按行重复 10 次。如果方向是 `column`，表示记录按列重复 10 次。

固定数量可以由框选区域自动推导：

```text
按行：count = 区域行数 / 单条记录占用行数
按列：count = 区域列数 / 单条记录占用列数
```

如果固定子表跨分页，固定数量按 `ranges` 的顺序累计推导。运行时必须保留所有固定空行，不能因为某一页没有填写内容而隐藏空行。

### 4.3 动态重复

动态重复适用于用户不知道记录数量的场景。

```ts
interface DynamicRepeatConfig {
  type: 'dynamic';
  minCount: number;
  maxCount?: number;
  addPosition: 'bottom';
  allowRemove: boolean;
  removeConfirm: true;
}
```

设计时只框选模板行。填报时，操作员通过“加一行”产生新记录。第一版动态子表不支持按列新增。

示例：

```ts
repeat: {
  type: 'dynamic',
  minCount: 0,
  maxCount: 50,
  addPosition: 'bottom',
  allowRemove: true,
  removeConfirm: true
}
```

动态模式下，设计画布不复制大量行，只保存模板和动态配置。填报运行时根据用户新增动作展开。

动态子表允许跨分页。当当前分页剩余空间不足以继续渲染新增记录时，运行时可以延续到下一个分页片段或自动产生后续分页展示区域，但数据顺序仍以记录数组为准。

## 5. 设计器交互

### 5.1 设置子表区域

用户流程：

1. 在字段设计中创建子表字段。
2. 下钻子表字段，创建子表内部字段。
3. 回到表单设计，在画布中框选多个单元格。
4. 右键选择 `设为子表`。
5. 选择一个未使用的子表字段。
6. 系统生成子表区域虚线框和右侧子表标识。

如果存在多个未使用子表，右键菜单使用二级菜单展示子表名称。如果只有一个未使用子表，直接显示一个 `设为子表` 操作。

### 5.2 数据分组

子表区域创建后，用户可以在区域内继续框选一部分单元格并选择 `数据分组`。

`数据分组` 的作用是把若干子表字段组成一条记录模板。

配置项：

| 配置 | 说明 |
|---|---|
| 填报方向 | 按行 / 按列；动态模式第一版固定为按行 |
| 重复方式 | 固定 / 动态 |
| 固定数量 | 固定模式显示，可由框选区域推导 |
| 最小数量 | 动态模式显示 |
| 最大数量 | 动态模式显示，可为空 |
| 允许删除记录 | 动态模式显示，删除时必须二次确认 |
| 新增入口 | 底部按钮 / 右键菜单 / 两者 |

### 5.3 字段拖拽规则

子表字段列表来源于当前子表字段的 `typeConfig.columns`。

规则：

1. 子表字段只能拖进所属子表区域。
2. 子表字段不能拖到主表普通区域。
3. 主表字段不能拖进子表区域。
4. 一个单元格只能承载一个字段。
5. 如果拖入已有字段的单元格，新字段替换旧字段，旧字段回到字段列表。
6. 子表字段消费状态以当前子表区域和记录模板为准。

### 5.4 视觉表达

子表区域在设计器中使用虚线框标识。右侧显示子表名称，使用紫色虚线连接。

固定模式：

```text
整个框选区域展示为固定表格范围，跨分页时每个分页片段都展示相同子表标识
```

动态模式：

```text
只突出模板行，并显示“动态”标识
```

矩阵预留模式：

```text
未来可显示行维度区、列维度区、交叉值区
```

## 6. 填报运行时

### 6.1 固定子表

固定子表运行时按设计器中的固定范围直接渲染。

操作员不能新增或删除记录，只能填写已有记录单元格。

固定子表不允许运行时隐藏空行。即使某些记录没有填写内容，也必须按设计器定义的固定范围展示。

### 6.2 动态子表

动态子表运行时根据模板渲染第一条记录或空状态。

新增记录时：

1. 复制模板行结构。
2. 生成新的记录索引。
3. 字段值为空或应用字段默认值。
4. 保存时追加到子表数组。

删除记录时：

1. 先弹出二次确认。
2. 用户确认后删除当前记录对应的数据对象。
3. 重新计算展示序号。
4. 保留审计日志中的删除动作。

## 7. 保存数据结构

普通记录型子表保存结构：

```ts
interface SubTableValue {
  fieldId: string;
  rows: Array<{
    rowId: string;
    values: Record<string, unknown>;
    fieldSnapshots: Record<string, ModelFieldSnapshot>;
  }>;
}
```

说明：

| 字段 | 含义 |
|---|---|
| `fieldId` | 子表字段 ID |
| `rows` | 子表记录数组 |
| `rowId` | 单条记录内部 ID，用于审计和动态删除 |
| `values` | 子表字段值 |
| `fieldSnapshots` | 填报时字段快照 |

对外展示或接口可以转换为更业务化结构：

```json
{
  "detailTable": [
    {
      "inspectionItem": "检验项目 1",
      "result": "合格"
    }
  ]
}
```

内部持久化建议保留字段 ID 和字段快照，避免字段改名后历史数据无法解释。

## 8. 矩阵子表预留

矩阵子表使用：

```ts
mode: 'matrix'
```

第一版不开放 UI，但 schema 预留：

```ts
interface SubTableMatrixDimensions {
  row: MatrixDimension;
  column: MatrixDimension;
  value: MatrixValueDefinition;
}

interface MatrixDimension {
  source: 'static' | 'reference' | 'dynamic';
  labelFieldId?: string;
  items?: Array<{
    id: string;
    label: string;
    value: unknown;
  }>;
  allowAdd?: boolean;
}

interface MatrixValueDefinition {
  fields: Array<{
    fieldId: string;
    role: 'value' | 'remark' | 'attachment';
  }>;
}
```

示例业务：

```text
行维度：检验项目 A、检验项目 B、检验项目 C
列维度：ID:1、ID:2、ID:3
交叉值：结果、备注
```

界面展示：

```text
          ID:1      ID:2
项目A     合格      不合格
项目B     合格      合格
```

内部存储仍建议展开为明细行：

```json
[
  { "sn": "ID:1", "item": "项目A", "result": "合格" },
  { "sn": "ID:1", "item": "项目B", "result": "合格" },
  { "sn": "ID:2", "item": "项目A", "result": "不合格" }
]
```

这样可以保持查询、统计、导出、审计的一致性。

## 9. 配置面板

选中子表区域时，左侧进入 `字段配置` 或 `子表配置`。

普通记录型配置：

| 分组 | 配置项 |
|---|---|
| 基础信息 | 子表名称、帮助提示 |
| 结构设置 | 填报方向、重复方式 |
| 固定设置 | 固定数量 |
| 动态设置 | 最小数量、最大数量、允许删除、新增入口 |
| 填写限制 | 必填、只读、隐藏 |
| 查看效果 | 表头显示、序号列、空数据文案 |
| 分页设置 | 跨分页片段顺序、分页延续方式 |

矩阵预留配置：

| 分组 | 配置项 |
|---|---|
| 行维度 | 来源、显示字段、固定项 |
| 列维度 | 来源、是否允许新增 |
| 交叉值 | 结果字段、备注字段、附件字段 |

矩阵配置第一版不显示，只保留内部结构和后续入口。

## 10. 校验规则

设计期校验：

1. 子表区域必须是多单元格。
2. 子表字段不能嵌套子表字段。
3. 动态模式的模板区域必须至少包含一个子表字段。
4. 固定模式推导出的记录数量必须大于 0。
5. 同一个子表字段在同一个记录模板中只能出现一次。
6. 子表字段不能跨出所属子表区域。
7. 删除子表区域时，区域内子表字段绑定一并删除。
8. 跨分页子表的分页片段顺序必须明确，不能出现重复 `order`。
9. 子表内部字段允许使用合并单元格，但同一个字段仍只能绑定一次。

填报期校验：

1. 必填子表至少有一条有效记录。
2. 动态记录数量不能小于最小数量。
3. 动态记录数量不能大于最大数量。
4. 子表内部字段按各自字段规则校验。
5. 删除动态记录必须二次确认并进入审计日志。
6. 固定子表空行必须保留展示，不能运行时隐藏。

## 11. 分阶段实现建议

### 第一阶段：普通记录型子表闭环

实现内容：

1. 子表区域 schema。
2. 固定重复配置。
3. 动态重复配置。
4. 按行 / 按列记录模板。
5. 子表字段拖拽到记录模板。
6. 填报运行时固定记录展示。
7. 填报运行时动态按行新增/删除记录。
8. 跨分页子表区域保存和渲染。

### 第二阶段：子表体验增强

实现内容：

1. 子表表头配置。
2. 自动序号列。
3. 空数据文案。
4. 复制上一行。
5. 批量新增多行。
6. 动态记录上下移动。

### 第三阶段：矩阵子表

实现内容：

1. 行维度配置。
2. 列维度配置。
3. 交叉值字段配置。
4. 矩阵展示到明细行数据的转换。
5. 矩阵导出和审计展示。

## 12. 关键取舍

推荐第一版只开放普通记录型子表。

原因：

1. 固定子表和动态子表都可以复用同一套 `recordTemplate`。
2. 用户最常见需求可以先闭环。
3. 矩阵场景复杂度高，涉及维度来源、交叉值、自动带出和动态列，不适合和基础子表同时实现。
4. 只要 schema 预留 `mode` 和 `dimensions`，后续矩阵不会推翻第一版。

## 13. 已确认决策

1. 动态子表第一版只支持按行新增，不支持按列新增。
2. 固定子表不允许运行时隐藏空行。
3. 动态子表删除记录需要二次确认。
4. 子表内部字段允许使用合并单元格，但同一个字段仍只能绑定一次。
5. 子表区域允许跨分页，schema 使用 `ranges` 保存多个分页片段。
