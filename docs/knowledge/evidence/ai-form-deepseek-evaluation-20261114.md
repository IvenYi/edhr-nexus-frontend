# 2D 表单 Agent 模型验证边界

- `user-confirmed`：继续表单 Agent 验证，换掉打印标签样本，选一张有实际业务的表单。沿用 DeepSeek 和暂不开发页面的范围。
- `original-evidence`：本地《清线记录》原件 Sheet1 包含工单、八项清线检查、清线及复核签字和物料明细。明细表头区分实发、实际使用、不良、退库和报废数量。原件 SHA-256 为 `f0ff29d1d53ac61ef24bebaadce7ab181f4920c235263733697f17d4a051e748`。采用该表替换标签是本轮样本选择。模型输入限定为空白脱敏内容，原件与固定比较基准保留在本地。
- `inference`：清线记录的实际使用量是消耗配置的候选字段。客户仍需确认这份表单是否承担正式统计来源职责。纸面签字栏支持据原表设计控件，真实签署与放行仍适用产品已有配置和授权。

沿用 [DEC-0097](../decisions/DEC-0097-ai-collaboration-runtime-boundary.yaml) 的任务资格、预算和证据要求。Node Worker 接入供应商，DSH 处理对话与工具调用。Java 核对当前资格，保存预留、用量结算、原生表单及业务审计回执。验证任务继续消费受限的内部知识包，权威规则与现有知识成熟度保持 0.3.25/P0/internal。

适配器以隔离模型配置和首次领取为执行条件。每次发往 DeepSeek 前向 Java 预留，按账本限制输出。已有同调用预留遇到未知结果需要先核对；收到完整用量后，适配器按约定费率估算并结算。日志记录实际预算与操作事件，可定位到任务及轮次。

各表单的模型质量依据原表、当前修订读回、原生预览和运行事件分别评估。预算结算记录来自供应商用量的费用估算。工程源码允许核对调用边界，运行结论依据本轮独立验收记录。
