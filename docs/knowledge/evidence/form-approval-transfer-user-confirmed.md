# 普通表单审批转办业务边界与历史纠偏

## 来源

- 2026-09-17 用户在表单管理连续开发讨论中确认：普通表单流程审批转办与表单填报责任转交、记录控制审批转办及管理员重新分配是不同的业务动作；应在普通表单流程审批节点保留转办按钮配置，并由“记录 / 表单管理 / 表单审批”的待办操作栏执行转办。
- 2026-09-17 后续纠偏：转办不是此时才新增的产品方向，而是早期开发表单流程时在业务澄清和实现中共同遗漏的既有预期能力。`DEC-0024-01`和`DEC-0024-03`中“审批节点只有审批/退回、第一版不开放转办”不得继续作为现行产品范围或“曾明确决定不做”的证据。
- 真实时间线必须保留：早期文档确实存在不完整表述，`0.3.22`完成了知识补录和运行缺口修复，本次纠偏不得倒填为“早期已正确确认转办”。

## 已确认规则

- 转办只适用于普通表单流程的当前审批节点；填报节点不提供转办。
- 审批节点可配置转办按钮的显示名称、样式和显隐；转办原因由系统固定要求填写，不提供“审批意见必填”配置，也不参与填充签名字段事件配置。
- 只有当前具有处理权的用户可以转办。已配置审批主体时，目标必须来自节点到达时冻结的候选范围；未配置审批主体的开放节点只允许选择当前有效且未锁定的用户；不得转办给自己。
- 转办只改变当前审批责任人，不推进节点、不修改表单数据，也不产生审批通过或退回结论。原待办移除，目标用户获得同一表单份、同一审批节点的待办。
- 原冻结候选范围保留，受让人后续再次转办时仍受该范围约束。退回到填报阶段并重新初始化表单流程时清除旧节点的转办人投影。
- 转办必须在结构化历史和不可变审计中记录转出人、目标人、原因、表单份、审批节点和时间；密码或其他凭据不得写入历史或审计。

## 明确不在本切片

- 表单填报阶段的责任主体转交。
- 记录控制（表单变更/作废）审批的转办运行时。
- 管理员重新分配、加签、跳过、并行审批或复杂条件求值。
