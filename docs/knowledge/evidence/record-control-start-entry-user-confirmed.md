# 记录控制申请确认与审核开始节点边界

knowledgeModelVersion: `0.3.20`

## 证据类型

`user-confirmed`

## 已确认结论

- 当前审批流程中心首切片只配置表单变更和表单作废申请确认后的审批路径。
- 申请人在记录控制入口准备申请内容、完成申请人电子签名、显式选择匹配的已发布审批流程并点击确认时，业务语义上申请已经发起。
- 确认成功后应创建审批流程实例、冻结所选流程定义与版本引用，并直接进入首个审批节点。
- 审批流程的开始节点只表示流程边界，不是用户任务，不产生待办，也不配置保存或提交按钮。
- 审批节点的审批、退回、转办动作及既有呈现配置边界不因本次决策改变。

## 证据边界

以上内容来自 2026-09-15 当前产品讨论中的用户明确确认，属于业务规则证据。当前切片已经实现审批流程配置和发布校验；公共流程阶段一也已实现候选查询、显式版本启动、流程快照和首审批任务推进。但申请入口、申请人电子签名真实性校验、来源资格、申请与流程原子事务和申请侧回写尚未形成端到端实现与测试证据，因此更广的“申请确认即启动审批”规则仍保持 `specified / internal`，不得解释为申请域运行时已闭环。
