# 物料模板、导入与品牌命名的确认边界

日期：2026-09-15。知识基线：0.3.18。来源工作树：J0WMS/gmp-platform；目标：Zencas/gmp-platform。

用户原话（user-confirmed）：“把当前品牌字段也改成 `brandName`，然后移植F04a、F04b、O01、O02”。F04a 是物料 Excel 模板，F04b 是物料批量导入；O01 是按服务端总数展示物料分页总数，O02 是按既有数组响应展示首页待办和已办。

移植边界来自已批准功能及来源原始代码（original-evidence）：模板使用 `.xlsx`，单次最多 1000 数据行；校验合法的新物料保存，重复料号和版本跳过，无效行返回行号与原因，可在一次导入中返回成功、跳过、失败三类结果。目标已有 DEC-0048 确认物料类型必填、品牌选填，该语义继续适用于导入。物料类型选择来自目标字典，不将来源固定的类型清单作为目标业务规则。

品牌 `brandName` 是字段命名变化，仍指同一物料品牌，不能据此新建第二个品牌概念。追加迁移把旧 `brand` 列重命名为 `brand_name`，保留已有值和空值；既有 0078 迁移和历史审计 JSON 不重写。请求兼容旧 `brand` 别名、新响应使用 `brandName`，属于本切片的兼容实现选择。

来源服务检查位置：`backend/src/main/java/com/zencas/edhr/masterdata/service/MaterialImportService.java` 的 `createTemplate`、`importWorkbook` 和 `parseRow`，于 2026-09-15 核对原始源码。来源允许空类型，移植时必须以目标类型必填规则为准。来源不校验新增版本与数据库既有基础信息的一致性；目标实现对冲突行返回失败，以保护当前基础信息更新路径。此一致性处理、去空格和大小写归一化属于实现解释，不提升为新的通用业务规则。

逐行失败仅指可识别的输入校验失败；数据库、审计或工作簿异常仍遵循控制器事务失败回滚，不能解释为任何基础设施异常都允许部分提交。待办、已办继续由服务端当前登录身份决定，不接受客户端指定他人身份扩大查询范围。生产、库存、BOM 规则与历史快照不在本次变更范围。
