# DHR 汇总与审核配置用户确认记录

knowledgeModelVersion: `0.3.24`

证据等级：`user-confirmed`

确认日期：2026-09-19

用户确认的产品决策：

1. DHR 列表与 DHR 汇总是两个独立菜单；列表负责查询和详情，汇总负责整理、保存草稿和提交冻结。
2. DHR 当前有三类表单实例来源：制程/DHR 目录直接绑定表单、作业表单节点按适用规则形成的实例、生产执行时创建的自定义表单。
3. 基础目录来自首次开工时冻结的 DHR 模板，不允许在汇总中改名、删除或移动；汇总草稿允许在基础目录下增加任意层级目录。
4. 目录直接绑定的已完成实例自动进入对应基础目录项；作业表单和自定义表单由用户选择纳入，未选择即不纳入，不要求逐条填写排除原因。
5. 同一表单模板可以产生多份实例，详情和汇总必须按实例分别查看和处理；同一实例在同一汇总版本中只能归入一个位置。
6. 提交汇总时冻结基础目录、汇总新增目录、完整候选范围、纳入关系、来源快照和校验指纹；已提交版本不可修改，退回后的整理必须形成新草稿/新版本。
7. 拖拽或选择只是交互形式，底层必须保存受控证据关联，不复制、移动或改写来源表单。
8. 产品/产品簇制程版本配置 DHR 汇总审批策略，并在需要审批时绑定一个已发布的 `DHR_SUMMARY` 流程版本；生产开工时随制程版本冻结。
9. DHR 审核需要后续开发独立菜单；当前切片不实现审批运行时、待办/已办、退回和审批结果落地。
10. 历史 DHR 不回填。

以上内容是业务确认，不单独证明源码实现、测试通过或已发布部署。
