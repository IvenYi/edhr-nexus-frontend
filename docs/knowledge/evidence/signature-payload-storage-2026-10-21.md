# 签署原文无损存储的工程纠正

核对基线：`edhr-dev@c3343f45bb79f72368937f0d197ae01f989f0390`；知识 `0.3.25 / schema 1.2.0`。本记录只同步 W3 签署消费链及 DHR 归档的有限实现证据，不新增用户政策、DEC、权限码、角色、规则或执行契约，不提升成熟度或本体阶段。

## 现行依据与实现差异

DEC-0063-05/11/15及`rule.dhr-summary-zip-source-trace`要求审批、详情与导出沿同一冻结版本，并保留来源及审批签署的追溯。DEC-0074/0058分别保留按钮与字段签署资格、身份、密码、图片、内容失效和历史证据边界。本批实际核对的现行资产未把签名载荷的物理JSONB类型规定为业务政策。

原`ExecutionAccess.signTarget/signField`以及个人认证的`AuthController`均对原JSON字符串UTF8计算SHA-256；`Signature.snapshotData`却按JSONB保存，数据库可能规范化空格与键序。`DhrArchiveService.sourceSignatures/signaturesFor`按JDBC读回原字符串重算摘要，语义相同不能代替字节一致。来源签名仅在FULL或选含表单的SELECTED分支读取；仅选汇总附件跳过来源签名。审批签名始终读取，之后SELECTED才移除清单中的原载荷，不能笼统称所有子集都核来源签名或能绕开审批签名校验。

本批将实体载荷改为TEXT并新增0118前向迁移，使后续签署原字符串无损保存；CHECK只沿用原JSONB的JSON输入形状及解析限制，校验结果不替换所存原文，不新增对象形状或键唯一限制。原摘要算法、三个来源写入服务、归档校验及篡改拒绝均保持。该存储选择属于决策包`inferred`工程落实，不提升为新user-confirmed业务政策，也不增加重复载荷列或第二套摘要算法。

## 历史与回退边界

迁移只保留旧JSONB当前能读出的文本、原摘要和其他元数据。已经被JSONB丢失的原始字符不能恢复，不得按读回值重算旧摘要、猜测原键序或把旧记录伪造成原始签署。旧签名若此前已无法复验，迁移后仍可能阻断归档；这不是通过放宽校验处理的范围。TEXT回退JSONB会破坏新签署原文，因此不提供静默有损的自动回退。隔离迁移及回退限制验证不能冒称已在生产库执行或已恢复历史档案。
