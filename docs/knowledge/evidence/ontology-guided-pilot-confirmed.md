## 工程落实与本轮交付边界（inference / implementation-constraint）

- 按已有主开发、本体和质量三类角色承担工作，不为逐步指引增设长期角色或独立审批层。
- 试点分别说明语义基础、关系查询、历史解释、标准映射与校验、通用规则执行的目标。可以组合，但各自按证据验收；引入 JSON-LD 或 SHACL 不能替代运行读取器、动作适配、权限、事务或审计验证。
- 全量审计采用固定基线的 ID 清单防止遗漏，再按领域补充逐项结论和证据。清单的具体字段和实现方式属于工程落实；清单生成只证明盘点，不能提高知识成熟度。
- 当前术语、概念、关系、事实、规则及支撑它们的决策、证据、锚点、执行契约、未决问题、验收场景和实现差异都纳入范围，没有 ID 的 Markdown 证据和说明按文件登记。历史与废弃资产核对其来源、时点及替代链，保留原始含义，不补造过去的契约读取和审计记录。
- 优先处理投影、表单绑定、执行快照、生产阻断及审计相关领域；分别核对表单原始记录、流程工作数据、业务投影、追溯关系、DHR 证据和审计历史的所有权、身份与版本边界。优先级不缩小最终全量覆盖范围。
- 尚未合入的 `form-traceability-projection` 按自身提交和实际集成候选另行核对；`edhr-dev` 清单不能证明该分支已经审计。
- 本轮只完成治理同步、两处已知说明遗漏和审计入口。全量逐条语义对账及运行试点仍需后续执行与相应验收，不能因为本轮契约落地就宣称这两项完成。

实施入口为 [试点与审计说明](../../development/ontology-guided-audit.md)，固定来源的 [记录清单](../../development/ontology-audit-inventory-db8d361.jsonl) 和 [元数据及文件清单](../../development/ontology-audit-manifest-db8d361.json) 分别保存逐项 ID 和无 ID 的说明文件范围。新治理决策与证据按本次增量验证，不把它们写成原基线已审记录；实际核对完成后才依据原始证据推进该项审计状态。
