# 生产表单字段签名确认记录

确认日期：2026-09-17。决策包：`DEC-PACKAGE-20260917-FIELD-SIGNATURE`。读取知识基线：`0.3.21`。

## 用户确认

- 用户反馈生产工作台的“点击签名”无效，并确认恢复此签名功能的 L2 门禁并继续实现。
- 已确认的流程为点击字段签名、验证签署身份、保存该字段签名及审计记录并回显；表单提交仍是独立操作。
- 对“签名后如果修改了本份表单内容，是否让本份已有签名失效并要求重新签名；原签名及其内容快照仍保留在审计记录中”的问题，用户选择“修改内容后，已有签名失效并重新签名”。范围是被修改的这一份表单，不扩大到同表单其他份。
- 对认证方式的确认，用户选择“使用电子签名密码和已认证签名图片”。这指个人电子签名认证已有的密码和图片，并非把现有按钮签署事件的账户密码契约整体改写。

## 原始证据与既有边界

- `AuthController.verifyCurrentUserSignature` 已有个人认证查询、有效期、独立电子签名密码及签名图片返回能力；该能力本身不是生产业务签名落库动作。
- `ExecutionAccess.sign` 现有生产按钮签署验证当前操作者账户密码，并保存生产执行签名和内容快照。`SignatureController.protectExecutionSignature` 阻止通用签名 CRUD 创建、修改或删除生产执行签名。
- 修复前正式运行字段组件把签名视为只读；纸张预览的签名回调为空。模拟签名可点击不代表正式填报已接入。
- `DEC-0025`、`DEC-0035` 的按钮前签署事件配置继续独立有效。本次字段点击签署新增入口，不替代、隐式配置或绕过按钮签署事件；不根据“领料人”“审核人”等字段名称推断签署角色。

## 工程设计及证据缺口

以下为决策包中的工程设计，不提升为额外的用户已确认规则：复用执行动作的资格检查、冻结配置、对象及份归属、修订号和事务；新签名采用结构化值；按字段及必要子表行定位；签署同时保存其内容并沿用已有保存实例号契约；普通保存不能伪造签名；旧文本签名仍可读取。签名、内容、审计应保持原子性，密码不得入审计快照。

规则暂为 `specified/internal`。本文不声称新入口已经实现、测试通过或已部署。成功签名、签后内容修改失效、其他份隔离、既有按钮签署兼容、认证失败、伪造拒绝及审计失败回滚仍需实现与聚焦验证。工序开工时生成实例号、完工后补填、额外审核人身份和独立复核规则不在本次确认范围。
