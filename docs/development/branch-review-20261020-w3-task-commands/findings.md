# 本批确定缺陷及相邻边界

`W3C-INSTANCE-WRITE-AUTH-001`，high，实例管理写入口缺权限声明。原基线 e8ecc 的 `WorkflowInstanceController.create/update/delete` 只受全局 authenticated 约束，随后直接 save/delete。相邻同控制器 terminate、任务控制器的管理 CRUD 已要求种子权限 `workflow.intervene`（流程干预）。三个实例入口遗漏该检查，普通登录者可直接提交状态、节点、上下文或删除请求，绕过专用流程命令的权限入口。

隔离PG/真实JWT复现：运行 `WorkflowInstanceAuthorizationIntegrationTest`，普通账号分别持空权限、仅页面权限、仅任务审批权限，对三个入口发有效请求；九项预期403实际200。其余13项匿名、授权管理、DHR防绕过、读取、候选完成及专用终止对照通过。红证的断言在HTTP状态处停止，因此不把这九项的后续零写断言误称已执行；控制器直写源码和真实200响应是当前红证。修复后同一fixture全部22通过，拒绝请求的实例/任务/日志/审计原件回读不变；授权管理操作、候选审批和DHR保护保持。原始摘要与首次夹具失败均保留。

根因是方法安全遗漏，最小修复为三个已有 `@PreAuthorize("hasAuthority('workflow.intervene')")`。核心提交 fc0980035d717fd1790ac72c907f940390540c4d。主侧89相邻测试通过后仍为 fixed-awaiting-independent-acceptance，不能自行升级验收。

历史去重承接PR20六项已验收结果，其余40问题不改。H009/H010/H012及既有锁刷新修复不重开。当前314旧源码范围和90旧语义记录的原始结论保留，文件/依赖发生变化的项目仍待增量核对；新增范围另列，不称整文件完成。

相邻边界：

- 管理员裸CRUD的内容约束、原因及审计策略尚未在本批裁定。授权正向测试只证明已有行为保持，不认证任意管理员写入全部合法。
- 通用候选审批/转办按DEC-0031/0033及用户确认的DEC-0081；不能仅凭种子按钮权限码新增全局审批限制。本批不改正常处理入口。
- 记录控制P0禁止终止/跳过/直接管理审批已有明确契约，但真实变更/作废调用链尚未接入且用户已暂缓；不以任意伪造实例证明当前已部署链受影响，也不顺便开发该功能。
- 通用可选签名引用不等于普通生产或DHR强制签署契约。专用生成和保护入口分别核对，不新增通用必签政策。
- Signature 的 JSONB 存储与 DhrArchive 读回原字符串重算摘要有独立源码线索；本批未运行该链原生PG复现、未裁定新运行缺陷、未改摘要算法或历史摘要。后续W5应单独验证，不能由旧 AuditEvent 问题推断签名/导出已经验收。
