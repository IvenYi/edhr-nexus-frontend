# PR #4 数量下限知识资格补正

本修订纠正初次内审把 BATCH 数量下限推断写成确定性记录错误的问题。用户于 2026-10-12 明确要求在同一 PR 修复该问题；此次授权没有选择 `>0` 或 `>=1` 的业务政策。

## 当前有效结论

当前前端、后端和 SQL 校验实现为 `>0`，这是实现事实。早期词表与规则自然语言也描述正数量，但 DEC-0012/0014 未明确确认 BATCH 在 `0<q<1` 区间的业务资格；“没有确认 >=1”不能推出“已确认允许所有正小数”。

两个争议组合规则的规范资格撤回，使用现有 `deprecated/internal` 表示历史记录；保留初次内审的 AST 和 result 供追溯，不把它们当作当前数量准入规则，也不把旧 `>=1` 恢复为已确认规范。数量下限通过开放问题保留，后续依赖该决定时再确认。

撤回的是未经充分确认的组合规则记录。DEC-0012/0014 中已确认的数量必填、按批次数／每批数量分配及余数、SN 数量为 1、总量边界继续适用；生产代码和现行检查保持原状。当前 decimal 类型、读取来源与实际校验事实继续保留。
