# 2D 表单 Agent 的 DeepSeek 实测

在 `codex/ai-experiments` 的 `4079a3dfa194112e19aa8daa728eefd02bc198af` 基线上进行 L2 验证。用户授权继续 DeepSeek 验证，并以有实际业务的表单替换打印标签。保留末道清洁和报废处理单，新增清线记录，使用三个原件的首张空白表。模型输入经本机脱敏，移除了文号、原文件名及工作簿身份；客户原件、会话、截图和数据库证据留在本机。

## 代码边界

DSH 管理模型与工具循环、会话和串行工具调用。Node Worker 使用 ECMAScript 模块接入 DeepSeek，在本地导入表格、编译原生表单、渲染 TSX 预览，并通过 Java Worker API 管理预算及数据。Java 继续负责资格、领取代际、预算账本、目录、实际写入、修订、回执和审计。本轮 Java 运行代码只补原生追溯配置的结构校验，拒绝损坏配置而不改变既有业务含义；模型适配和版式处理在 Node。

实验使用固定的 `deepseek-flash-chat-2d` 配置，带内部验证标志。模型请求先预留预算，收到有效用量后估算结算，结算后才向 DSH 交付工具调用。未知响应保留预留，重复请求不再次发送；隔离试验仅接受首次领取。当前用非思考模式以减少变量及避免持久化供应商推理文本。token 单价按 [DeepSeek 官方费率](https://api-docs.deepseek.com/quick_start/pricing/)的峰值估算，不能作为账单金额。

## 运行结果

前两批让模型填任意坐标，合并格和复合区多次校验失败，六轮任务均在 15 次调用上限内无保存。第三批改用从原件人工核对的填写区域和自动布局编译，三张表都生成了原生版本，但末道清洁及报废处理单没收齐当前修订证据。第三批一个畸形追溯补丁触发了原生 500。本轮补充结构拒绝后，HTTP 回归确认无新回执、无修订变化。第四批保留相同版式，明确原生日字段配置和局部补丁格式。

第四批每表 7 次请求，均自主查询知识和目录后完成原生保存、当前修订读回、结构校验与预览。预留、结算、操作回执和截图摘要均可核对。三表当前修订的语义检查均为零错误，预览反馈保留如下。字段覆盖为独立字段类型和来源位置诊断，不能替代业务验收。

| 表单 | 核心字段覆盖 | 追溯项 | 裁切提示 |
| --- | ---: | ---: | ---: |
| 末道清洁 | 15/15 | 5 | 10 |
| 报废处理单 | 14/17 | 3 | 5 |
| 清线记录 | 22/22 | 3 | 5 |

清线记录生成 8 列、15 行区域的子表，原生只读预览显示首行控件与其余空白行；未执行真实行填报。模型区分实发、实际使用、不良、退库与报废，配置工单、物料编码和批号查找。报废单的申请人、处理人和财务确认是普通文本，评分未将它们计作人员引用或签字。人工查看三张 PNG，标为裁切的标题和短标签仍可读，保留测量告警供后续校准。各模板本轮均未配置正式统计，不能从纸面列名认定其正式来源职责，也不能根据缺少该依据断定它只是重复记录。

模型每表列出 4 个问题，均在保存之后。明确可提前完成的配置不必停下来等答复。原表可支撑清线项确认默认空白；扩展查找项、新增原件未有的日期字段或配置额外流程属于后续选择。真正会改变业务行为的是签核身份、两组清线签字的职责区分、正式统计来源、关键批号或日期的确切含义。报废原因可先保留原文的文本配置，实际是否启用标准原因引用取决于主数据及实施范围，不应仅凭业务字典目录为空下结论。

第四批模型用量按峰值估算约 USD 0.032，四批合计约 USD 0.220。运行结果为 `WORKER_YIELDED`，配置成果和证据留存。未见表单的自动识别和排版、生产执行、真实签署、正式来源确认、供应商重启恢复和双模型比较尚需独立验收。

主侧完成 58 项确定性后端检查和一项采集三表实际模型证据的 JUnit 运行，17 项 Worker 测试通过，适配包依赖审计为零。知识角色校验 89 项通过，固定的 18 条内部知识包重建一致。独立质量结果和候选清单随本机证据归档。

## 复现

安装项目锁定的 Worker、前端和无头 Chromium。使用本地 `.env.ai.local` 的 `DEEPSEEK_API_KEY`，固定的 DSH 0.2.2-rc.2 CLI，及专用 JUnit PostgreSQL 数据库。首次运行先用如下命令把三个原始文件转为已审查的脱敏输入，输出到新建的本地批次目录。

```sh
node scripts/ai-form-agent/2d/sample.mjs clean '<末道清洁原件路径>' '<批次目录>/clean.json'
node scripts/ai-form-agent/2d/sample.mjs scrap '<报废处理单原件路径>' '<批次目录>/scrap.json'
node scripts/ai-form-agent/2d/sample.mjs line-clearance '<清线记录原件路径>' '<批次目录>/line-clearance.json'
```

在 `gmp-platform/backend` 目录设置 `AI_TASK_DATABASE_URL`、`PGUSER`、`EDHR_DSH_BIN` 和指向批次目录的 `EDHR_AI_2D_BATCH`，运行 `mvn -q -Dexec.skip=true -Dtest=AiFormPostgresTest#deepSeekBusinessFormsThroughGovernedWorker test`。这会发出真实请求。JUnit采集运行证据，不能根据测试进程退出码判断模型质量。在根目录执行 `node scripts/ai-form-agent/2d/assess.mjs '<批次目录>'` 读取结果。已运行批次在 `output/ai-product-slice-2d/batch-1` 至 `batch-4`，验收记录位于 `output/ai-product-slice-2d`。
