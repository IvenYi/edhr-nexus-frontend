# 实现范围、健壮性与后续

根因是WorkflowOperationsQuery.detail在任务映射内逐条查询当前姓名，任务不同/重复/NULL/缺失均触发SQL。用户已选择只处理姓名；目录getContent未使用total的独立COUNT保持原样，不擅自扩大授权。

## 实际最小实现

保留原实例可见性SQL及节点/边读取，然后调用原tasks.findByInstanceId一次。私有assigneeNames方法只接受该集合，按原String去重并去NULL，以一个varchar数组参数执行CAST(id AS VARCHAR)=ANY(?)，HashMap供原任务映射复用。保持原列表顺序及字段插入顺序，不改taskState或任何责任写入。

选择数组而非每ID一个IN参数，是为避免新引入与不同ID数等长的占位参数列表；并未证明无限量任务或内存无界安全。数组/Map为当前请求所有，额外空间随不同处理人数增长；不读取无关用户，不增加索引或跨请求缓存。文本CAST保留旧比较语义，前导零/空白/超Long文本不归一化；数据库当前姓名读取时点由逐任务合并为一次，不声称每字段时点完全相同。

## A23与具体边界

| 检查 | 处置 |
|---|---|
| 重复/空处理人仍逐次查名 | 请求内去重；无ID直接空映射；原N+1去除 |
| 空Map不接受NULL key | 新增全NULL回归实际捕获初版Map.of异常；采用空HashMap保持原fallback，不移除用例 |
| 非规范文本ID | 不新增数值校验、trim或回填；保持原不匹配fallback，安全参数绑定 |
| 空姓名与缺失账户 | 空字符串不被fallback替换；缺失/NULL沿原提示；不借优化改历史显示政策 |
| 当前名和历史签署混用 | 只改任务assigneeName读取；日志COALESCE、signature原件及snapshot保持，原生用例留证 |
| 可见性/最终写入保护重复 | 读取资格先执行；写入资格/签名/状态/锁/事务/审计/冻结不是冗余防御，本批未动 |
| 人员目录多余COUNT | 已取证仍open，未修改或增加兜底查询 |
| 原候选大IN/用户ID文本计划 | 本次姓名用一个数组参数，不等于已解决原候选查询、CAST计划或生产容量 |

## 抽取与回滚

本批落实上轮方案中的小型私有姓名读取方法，输入原任务集合，输出原文本ID到当前名的映射。领域授权、任务/日志投影及只读事务仍由WorkflowOperationsQuery拥有；不建公共策略框架或把历史签署解释交给目录。回滚只需撤回本批姓名读取及其相应优化预算，不触碰已有签署/审计或恢复历史数据。后续普通表单独立详情复用前须分别核其授权、来源版本及fallback，不能按字段同名合并领域。
