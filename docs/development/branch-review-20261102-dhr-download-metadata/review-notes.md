# 局部实现、A23及相邻边界

三个产品文件是DhrAttachmentService及两个下载Controller。downloadableFile的Java内部返回类型变为Download，全部typed生产调用只有两个Controller；Path与originalName是内部值，不作为JSON返回。最后一次元数据查询增加original_name，完整SHA通过才构造返回载体。移除唯一消费者已消失的originalName查询方法；HTTP路由、参数、类型和安全头原样保留。

原件名的读取从“摘要后再独立查询”合并到“摘要前的末次原件元数据查询”，这是本次有意调整的工程边界；资格、两次DHR检查和完整SHA顺序保持，不能笼统声称所有字段读取时点完全相同。

file()作为Summary/Archive内部原件路径入口，继续原DHR检查和原两列SQL。原完整性代码提取为私有verifiedFile(Map)，只核存在/完整流式SHA及原IOException错误转换；调用者仍负责各自资格。没有将当前active强加给历史file访问，也不把Summary持锁论证搬给无同一外层事务的Archive。上传/核验/解除关联代码及事务补偿不改。

| A23范围 | 判断 | 本轮处置 |
| --- | --- | --- |
| 两次DHR检查 | 既有不同时点，本轮授权要求保持 | 保留，原生测试核两个实际SELECT |
| 当前active与冻结成员 | 分别控制两种读取资格 | 保留含id+SHA，不复用前端声明 |
| 完整原件SHA、缺失/损坏拒绝 | 数据库元数据存在不能保证磁盘正确 | 私有方法保留原完整流式校验后再输出 |
| 独立原件名查询 | 最后元数据读取可同取、现有接口不改原件名 | 已获用户选择，局部合并，不缓存 |
| 私有完整性方法与内部载体 | 3调用点职责明确，避免为名字复制校验或外露路径 | 局部提取，不造通用解析/权限框架 |
| Summary/Archive重查 | 超出本次用户选择，锁/参照对象不同 | 保持，继续单独量化讨论 |

本轮实际方法范围重审不计全文件或全项目A23完成。后续若新增原件改名/路径重绑接口，需重新审查时点；“当前没有修改入口”不是永久业务政策。大模块后续拆分继续按原query目录的父锁内附件核查/独立导出资源方案推进，本轮只落实已确认的内部Path+名字返回载体。

原生夹具是四canonical表及PK，未完整安装所有索引/FK；现有tenant/DHR/ID和版本谓词负例只保护当前读取，不宣称完整多租户系统。修改前相同11例预期仅两项查询目标失败，其余资格/字节等为正控；以实际原件为准，编译或环境错误不计代码红。

50MiB容量沿原测试的12组/84请求，暖缓存稀疏PNG、2GiB JVM、Hikari池，真实Controller/服务代理/PG/Resource，无HTTP认证或全冻结过程；JFR是逻辑读取，heap不含RSS/直接内存。名字复用只省一次往返，不承诺单次延迟必然更快，不改两遍完整摘要/输出读取。
