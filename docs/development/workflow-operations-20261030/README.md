## 已确认范围

- 「流程实例」菜单显示名改为「流程日志」，保留 `/workflow/instances` 及既有详情、日志深链接。实例身份与日志概念不合并。
- 新增「流程干预」，只查询运行实例、当前任务并执行重新分配，不提供终止、跳过、强制批准或新DHR通用动作。
- 重新分配要求会话干预权限、实际签署人干预资格、合法目标、原因和有效电子签名。只改变当前处理责任。
- 记录控制转办由当前有处理权人员发起，保持原授权候选范围、排除申请人，原因必填；签名和按钮可见性按冻结节点配置执行。普通任务的既有租户内委托策略保持。
- 受限撤回只允许申请人、本轮尚无批准/退回决定；在同一事务内失效全部待办、生成稳定结果并由记录控制域落地，保留旧有效表单、修订及申请历史。

## 实现与兼容

公共流程拥有任务责任、签署证据、日志和撤回运行时；记录控制域拥有申请状态与业务结果。不引入另一套审批引擎。实例锁和任务锁与现有批准/退回串行化，任务状态指纹拒绝陈旧改派，责任快照含新代次，避免改派后又改回造成旧请求重放。

运行任务、实例和日志的历史通用CRUD写接口关闭，保留受控域既有错误保护；该修复落实原分工契约的运行时唯一写入要求，避免直接改数据库式接口绕过签名。正常业务发起、批准、退回及已有专属路径保持。新干预签名从通用列表及单条/写删接口排除。

流程日志查看权限不扩大审批中记录控制申请的可见范围；计数和分页前过滤，仅申请关联人或具备专门干预权限的人可查看对应运行详情。DHR仍走其专用证据入口。迁移0090仅调整既有权限的显示名与干预页面类型，不新增角色授权。

页面复用现有应用壳、ListTableShell、DetailDrawer、标准流程节点、FormDialog、ConfirmDialog和签署凭证组件，不改变全局主题或其他模块布局。详情按冻结流程版本查询；时间以原本地业务时间展示，不转换后截掉UTC时区。
