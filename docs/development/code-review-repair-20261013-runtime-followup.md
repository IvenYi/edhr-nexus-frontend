## 两项缺陷与修改

### RUNTIME-F003-001：存在的新版本被工作区旧缓存误判缺失

打开工作区时始终重新请求版本列表；新建、复制、编辑或删除批记录模板版本后，使对应模板工作区缓存失效。缓存尚未重新核实时提示正在核实，不把暂时缺项显示为已确认缺失；请求完成后仍找不到明确目标则拒绝读取/保存，不选择其他版本。缺失与加载错误均可在原窗口重试。

范围限定为对应模板的查询键，不清空全局缓存，不修改表单模板页面的删除规则，不采用轮询或无界重试。

### RUNTIME-F003-002：同一目标后台读取失败导致未保存草稿消失

使用最后一次成功读取的版本数据保留编辑目标，并将草稿身份与临时请求状态分开。显式模板/版本或窗口边界变化仍隔离本地状态；同一目标后台失败不清除目录草稿、修改标记或离开确认。重试成功后不以服务器旧内容覆盖未保存输入。

只有本次窗口已核实版本、两个读取均不在重取、草稿/响应与目标一致时才允许保存。工作区或设计读取失败时提供原地重试；保存失败原有保留输入逻辑不变。目标确实删除时仍禁保存，同时保留已经输入的草稿与放弃确认。

失效版本仍可设计。缺失 ID、版本失效、被引用 FORM 有效性与生产使用约束保持区分；不改后端、事务、审计、快照、签署、产品制程引用或生产阻断规则。
