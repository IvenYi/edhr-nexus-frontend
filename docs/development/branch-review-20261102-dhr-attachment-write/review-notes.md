# 源码核对与后续边界

## 根因及修复

原Files.write在创建、写入、关闭阶段都可能抛IOException，而事务补偿在它成功返回后才登记。仅PR53的回调结果修复不能清理这个更早阶段的残片。新代码只有CREATE_NEW返回流后才拥有当前新文件，try-with-resources同时覆盖写入和关闭；创建碰撞失败发生在catch外，不能误清理原有文件或目录。

发生写入/关闭IOException后清理当前未登记路径；若清理也失败，把该异常加入原错误suppressed并记录ID/path。调用仍失败，不补造登记、LINK审计或历史恢复。清理失败可留下残片，不声称所有失败零残片或跨资源原子。进程崩溃仍不能靠进程内catch闭环。

保留8KiB分块是沿用实际JDK21 Files.write行为，原始javap字节码已归档；没有新增任意缓冲配置、重试或磁盘事务抽象。局部catch只针对本阶段IOException，不为未观察到的可能性增加全局异常处理。创建碰撞保护、checked错误及关闭语义均由用例覆盖。原业务校验/事务回调/冻结与HTTP入口字节不变。

## 测试及原始阶段

故障测试只有登记前SQL资格查询使用替身，真实文件写入并显式注入流IOException；验证实际16字节残片、关闭错误、真实非空目录清理失败、两类既有路径碰撞和未登记/无LINK审计。它不代表真实磁盘满或完整事务/HTTP测试，既有原生事务11、附件/归档13、汇总8、生命周期6及文件84仍实际回归。

首轮CALLS_REAL_METHODS静态stubbing执行真实open，导致提前创建文件；其3fail是夹具错误，未当产品红。改conditional Answer后才得到3个真实旧红；随后仅移除unused import，另留exact最终测试的旧控制。每阶段命令/XML/日志/源或哈希与分类保留，不重复累加。最终独立质量必须复制受测提交的精确最终测试字节到真实旧e3。

## A23与调用边界

文件大小预检和真实bytes.length、格式、摘要和冻结成员各有证据用途，保持。CREATE_NEW返回才进入补偿，以及原错误/suppressed处理直接对应失败用例；不增加是否拥有文件的全局布尔框架或扫描清理。

有限源码调用核对发现生产upload只在DhrAttachmentController的注入service.upload；DhrSummaryService/Archive/Review是读取消费者，未发现生产new服务或内部自调用upload。现有原生代理测试证明受测配置事务激活。因此不把“可能无事务直接调用”继续登记成已确认生产缺陷，也不为其新增运行阻断；未来新入口按W7增量核查，未认证动态调用或部署拓扑。旧isSynchronizationActive保护保持，不为了单元夹具或精简目标修改业务资格。

## 性能与具体抽取

本批无新增集合N+1、内存分页或循环SQL；8KiB循环仅写当前文件字节。上传已有byte[]继续供检验/写入/摘要使用，没有额外再读取Multipart内容。下载实际观测见performance.md，不以性能指标修改当前业务实现。

后续可将upload的当前文件创建/写关失败补偿放入DhrAttachmentUploadService，并保留本服务事务与登记/审计边界；读取提取DhrAttachmentReadService.resolveDownload返回已核路径/原文件名/版本上下文，先核对重复资格检查与并发变化，再复用元数据；verify/unlink由关联服务负责历史保留。解析仍归DhrOfficeAttachment。先逐方法委托并以当前测试固定接口，不整类搬家或新增全局ACL策略。
