## 8. 如何复核与验收

逐 ID 清单分为 [共用本体](records-foundation.jsonl)、[表单与身份](records-forms.jsonl)、[主数据与配置](records-master.jsonl)、[生产与 DHR](records-production.jsonl)。每行保留固定提交的 ID、JSON Pointer、类型、原状态、原记录 SHA256、实际语义审阅、结论和 finding ID。所有行共用 `baseline.json` 的固定提交；原声明可由该提交和 Pointer 重建。

为避免重复复制来源，每行的 `evidenceReferenceIds` 连接 [evidence-index.jsonl](evidence-index.jsonl)，得到路径、定位、证据性质和已知限制；这只是去重，不是新设业务知识 ID。`resolutionAtBaselineReview` 保留发现时的状态，整改结果读取 `remediation.json`。52 份全文记录在 [files-without-ids.jsonl](files-without-ids.jsonl)。

以下命令仅核对盘点、原文身份、证据连接和候选摘要；语义结论来自实际审阅，不由脚本根据文件存在自动生成。需要 Python 3、PyYAML，以及本地可读取固定 Git 提交。

```bash
python docs/development/ontology-internal-audit-20261012/verify_audit.py
```

正式本体校验使用现有独立 Maven 入口。当前候选的实跑日志和 89 个用例结果由 [verification.json](verification.json)、[knowledge-validation.log](knowledge-validation.log) 记录。没有修改校验器来迁就修复；DIRECT/PROCESS 类型与使用处是在校验反馈后统一的。

```bash
mvn --batch-mode --no-transfer-progress --file tools/knowledge-model/pom.xml clean test
```

独立质量角色没有参与知识修改，分别检查完整分母、来源身份、关键源码含义、候选变化和报告。复核中纠正了错误 DEC 导航、DHR 回退分支的过度简写、两行审计证据的错误组件路径，并补齐无 ID 文档整改到实际修正文档的直接链接；结论与具体内容摘要见 [quality-result.yaml](quality-result.yaml)。主智能体最终知识交接为 [ontology-result.yaml](ontology-result.yaml)。

**验收边界：**本体结构校验通过、审计证据完整、L1 文档质量通过，均不等于业务运行、数据库迁移、浏览器交互、部署或法规符合性验收通过。后续实现修复要在实际候选上取得自己的证据。
