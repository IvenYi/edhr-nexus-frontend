# 报表导航分栏错位修复

执行级别 L1；提交基线为 `edhr-dev@0e16363e9fc1ccb876d6ef96a1b15dc1c9cc145d`。提交前重新获取远端，目标未变；当前布局代码、回归测试及决策包的 SHA-256 与独立验收记录完全相同，因此复用同一功能切片的构建和实际页面验收，不重复启动质量门禁。

## 问题原因

用户录屏及3000复现显示：刷新工作台后进入其他模块，再打开表单追溯，正文与面包屑正确，左栏却回到首页。`AppLayout.getModuleIdByPath` 漏掉了报表路径，返回默认 `home`；正文及面包屑通过菜单树找到正确页面，两种匹配方式导致显示不一致。五个报表共用该逻辑，均受影响。

另一个关联问题是分栏同步只依赖推断出的模块 ID：用户手动浏览其他模块菜单，再选择同模块另一标签或重复选择当前标签时，模块 ID 没变，同步不会触发，左栏可能停留在之前浏览的模块。

## 修改内容

- 复用已有 `isProjectionReportPath`，将表单追溯、DHR追溯、报工记录、报废记录、消耗记录及旧报表入口识别为 `records`。
- 同步 effect 依赖加入实际导航的 `location.key`，覆盖跨模块、同模块、重复当前标签及浏览器前进后退。
- 保留仅点击模块图标浏览菜单的行为；未发生导航时不强制切回当前正文所属模块。
- 新增8项回归，直接执行从实际源码提取的路径解析器和已有报表注册表；一并保留原因分析、独立质量报告、截图和导航观察证据。

业务代码仅修改公共布局两处，不改变报表查询、权限、API、业务数据或生产执行规则。本体门禁不适用，知识基线保持 `0.3.25 / schema 1.2.0`。
