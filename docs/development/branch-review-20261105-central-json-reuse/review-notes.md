# 实现、资源与验证边界

## 最终实现

`WorkflowOperationsQuery.list`仍对原两源计算精确COUNT和数据库排序分页；将同一份已归一化关键词及字面转义pattern交给表单源，外层原筛选保持。HTTP/前端契约不变，100仍是单页上限，不是实例或人员总量上限。

`FormWorkflowOperations.source`增加列表专用 `LIST_CONTEXT`，按execution相关LATERAL逐对象处理：

1. `record_scope`只取default租户且对象/工单连接有效、匹配关键词的列表必要字段；运行干预的对象/工单和DHR摘要锁等独立谓词在此检查。
2. `parsed_state`仅在有相关记录时解析一次state；`progress_records`按operation/copy提取进度，并保留原object类型和运行ACTIVE条件。
3. `parsed_snapshot`只在有合格progress时解析一次执行冻结snapshot。
4. `form_catalog`按被引用作业展开表单，只保存operation/form编号及flow/sourceType；不将完整snapshot/state复制到目录行。作业选择去重，不折叠原快照里的重复form条目。
5. 原visibility、CUSTOM/ROUTE作业/对象资格及当前APPROVAL检查在最终投影继续执行，进度与history仍按copy身份。每个对象的物化上下文随相关扫描重用/清理，不先物化整个租户的完整快照。

共享 `FROM`及visibility之后的全部详情/姓名/目录/改派/load/签名/锁/事务/审计实现字节保持。没有引入当前配置取代冻结依据、状态回写、总量截断、缓存、额外网络SQL、索引/新表或迁移。未把COUNT null兜底等与本修复无关的清理混入。
