# 主数据删除保护的确认与证据边界

来源：2026-09-16 当前用户需求与范围回复（user-confirmed）。

用户要求补充删除保护或条件约束；删除被阻断时，弹框列出对应关联，告诉用户到哪里找到约束关系，先解决下层关联才允许删除。范围明确为“覆盖所有主数据模块，分模块推进”。

因此确认：有关联约束时禁止删除；呈现可理解的关联记录、所属模块和处理位置；各现有主数据模块分模块接入。这里的“所有”是交付范围，不是自动发现未来新增模块或任意 JSON 关系的能力声明。

同一切片追加确认（user-confirmed）：先检查关联，有关联直接显示“暂不能删除”，无关联才弹删除确认。预检查未完成或失败不能视为无关联；预检查本身不删除数据，取消确认不执行删除。真正删除仍需复核当时引用，不能将较早的预检查成功当成删除授权或并发完整性保证。

同一切片再次追加确认（user-confirmed）：展示完整模块及菜单路径、逐条关联的业务名称和所属位置，支持直接跳转定位实际记录；处理后在弹窗刷新关联，不必刷新整页。逐条入口仍遵守目标模块权限；没有现行页面的历史记录如实说明，不以模块首页伪装成记录定位、不新增管理页面。刷新重新检查同一删除目标，不自动删除；失败不代表关联已解除，仍沿用先预检、再确认和实际删除时复核的顺序。

同一切片截图追加确认（user-confirmed）：顶部当前删除对象的名称、编号、所在菜单可去掉以节省高度；逐条“位置”不重复业务编号。关联需要说明数据性质，业务数据与快照或追溯记录不混在同一个待处理列表，不能用含糊的追溯提示让用户判断应如何处理。

分类实现与保留边界（实现选择，非新法规结论）：只读投影使用 BUSINESS、RETAINED、ORPHAN。实际工单和生产对象属于业务关联；实例、历史生产记录及执行快照引用单独列为保留记录；业务配置所有者链缺失单独列为异常遗留，而不是仅因无法定位便认定其具有法规追溯性质。同源表按实际记录分类拆组，默认业务关联，另有保留及异常视图。分类不改变现有真实引用阻断、权限、生产对象及历史保留契约，不授权删除生产对象、忽略快照依赖、自动清理孤立记录或修复缺失父数据。纯审计记录不新增进入关联目录。

现有权威约束另行保留：`docs/knowledge/rules/production.yaml` 中 `rule.production.object-lifecycle` 明确既有生产对象不删除数据，`rule.production.object-cancel-before-start` 明确取消仍保留对象和审计；`DEC-0036` 明确已引用的表单流程不可删除以保护历史追溯。本需求不授权为了删除主数据而清空生产记录、快照或审计，也不新增强制删除或级联清空入口。

实现选择与未验证边界：分组布局、统计、分页、URL 参数、筛选展开与高亮机制、权限下的详情可见性、事务复核、外键兼容策略和引用目录由实现及测试说明，不单独提升为用户新增业务规则。菜单路径、逐条记录定位和弹窗刷新已在本切片追加确认。仍沿用原删除权限、生命周期、版本所有权和审计契约；无引用不等于绕过其他既有约束。旧孤立记录不在本需求内自动删除或补造。

本记录及对应新规则为 specified/internal。实现、并发、浏览器和发布证据未闭环前，不得将其解释为所有模块已覆盖或已上线；实际覆盖须逐项核对代码与测试。系统管理与生产状态转换不属于此次主数据删除入口扩展范围。

预检查增量的源码核对：`DeletionCheckController` 的 GET 接口复用 `DeletionProtectionService.check` 和目标权限，返回 allowed/impact；其事务可能锁定读取目标，但不执行业务删除。`AppDialog` 在检查完成前隐藏原确认内容，有关联转入保护弹框，失败只提供重新检查；关闭会中止在途检查。`DeletionProtectionIntegrationTest` 已包含只查询不删除/不写审计、预检后新增引用仍阻断及权限用例。本次仅核对源码，不代替接口、浏览器或测试运行证据。该预检查增量不新增数据库迁移，前一阶段删除保护迁移不受影响。

定位与刷新增量的源码核对：`DeletionImpact.Item` 增加 path/location，目标投影保留 targetType/targetId/targetModule；`DeletionProtectionService` 按现有业务所属关系构造位置及定位参数。`DeletionProtectionDialog` 展示逐条业务名称、位置、定位入口或无页面说明，并使用目标标识重新调用预检查；成功无关联仅提示已解除，不发送删除请求。各目标列表的参数解析、筛选、展开、高亮及真实记录定位仍须逐模块验证；仅有链接参数不构成定位成功或浏览器验收证明。本增量不修改数据库、删除事务或审计契约。

分类增量的源码核对：`DeletionImpact.Group.dataType` 是解释性只读字段；保护服务对同源记录按类型分组，并沿业务所有者链识别缺失关系。历史标识及执行快照引用的分类不能用“暂无页面”替代判断，也不能用前端默认页签的业务数量替代全部阻断数量。当前核对保持 specified/internal，不把代码存在当作跨模块验收或法规保留期的证明。
