## 传递影响

- **DHR**：首次开工实例与目录仍按同一事务快照创建。单批提前结束仍终止自身 DHR；工单命令仅在子对象都处理完后改变工单状态，不再次终止表单或 DHR。DEC-0069 中旧阶段“不新增工单命令”的表述已直接纠正。DHR 目录/汇总/终止快照不因本次审计查看新增而重建。
- **执行补录**：工单提前结束后仍遵循原上级终态的补录限制；本次不放开结束后补录。批次已经结束但工单还有剩余计划时，工单继续活动。
- **删除保护**：删除退役工单制程边及 FK；生产对象、DHR、冻结证据对制程的删除保护保持，使用干净基线测试实际阻断。不能为了取消工单锁版而允许删除已被对象引用的制程。
- **版本身份**：版本号 V1 仅是引用标签，不能证明内容相同。审计冻结对象包括 context、processReference、routeNodes/routeEdges、工序及其表单/文档等实际执行配置。DHR 目录另有自身冻结原件，不伪称已在本入口展示所有子系统快照。
- **审计事务**：批次编辑前后值在父工单→对象锁后读取；命令及审计同事务。首次开工/全部完成引起的工单状态变化有单独 WORK_ORDER 事件。审计失败回滚业务数据，不留下只有新引用而无历史记录的状态。
- **权限**：批次管理权限需要读取所属工单单条详情及可选制程，已明确开放这两个读取接口；工单写入、列表、拆分、关闭和提前结束仍要求工单权限。没有新增签名或审批绕过。

## 初始化与兼容处理

用户明确此次为 MVP，可废弃旧开发数据。采用 `product-core` 路径：直接维护现行模型及初始化 SQL，无兼容列、双读、旧锁版分支或新增迁移链。`work_order.process_version_id` 与 `fk_delete_guard_013` 在新库均不存在。两个任务专用 PostgreSQL 库用于初始化及真实事务测试，未覆盖用户已有开发库的数据。旧库若运行新基线应重建，不用 clearCheckSums 假装旧结构与新模型一致。

## 不受影响与暂缓

- 产出、良品、NG、报废的统计口径不改；工单正常完成不依赖产出等于计划。
- 已开工批次身份、制程内容及表单/DHR历史证据不被主数据变化重写。
- 既有作业动态匹配工作树改动保留并纳入执行回归；无关流程画布改动保持原状，不作为本轮交付内容。
- 不增加已开工批次再拆分、批次/SN互转、自动升级最新版或自动补做历史作业。
- 其他冻结详情候选只盘点：作业实例、生产表单、DHR初始目录与上下文、DHR汇总提交版本、DHR终止证据。原始源码定位见 `docs/knowledge/evidence/batch-process-2026-10-27.md`。
