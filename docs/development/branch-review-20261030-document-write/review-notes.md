# 健壮性、容量与具体拆分方案

基线2e24711a。只记录实际读到的范围；并发分类排序、唯一约束争用、引用删除、实际磁盘文件与完整多租户未认证，不能因权限矩阵通过而关闭。

## 当前容量候选（未实施优化）

分类/父文档/版本都可随配置历史增长，不能只按当前小数据假设。与PR44列表风险去重：原`PERF-DOCUMENT-PAGE-VERSION-MATERIALIZATION-001`及`PERF-DOCUMENT-VERSION-FILE-LOOKUPS-001`仅列表范围已独立解决，以下为其他入口/同族剩余范围，不反填旧报告、不计多个已修成果。

| 范围/触发 | 已证机制与反证 | 候选方案与代价/下一步 |
| --- | --- | --- |
| 分类改名，文档存量D增大 | `countDocumentsByCategory`三处调用各findAll后内存计数，O(D)结果处理；同一事务L1缓存可减少重复实体实例，不能据调用次数宣称3D新实体。当前合法1文档夹具，两引擎总8 SQL；未跑规模/堆峰值。 | 专用countByCategory一次并复用同事务内不变计数；需先讨论，保留审计变更前后真实含义与并发视图。 |
| 删除自定义分类，D大而所属n小 | findAll全量加载再筛选，逐文档写不可变审计；不能用批量UPDATE省掉每文档证据。测试1文档8 SQL是隔离方法路径，未装真实删除Aspect，不能外推生产允许删除已引用分类。 | 先核实际删除保护与“转未分类”规则边界，再评估按分类有界读取/锁及分批审计。未核前不修改。 |
| 文档详情含V个有文件版本 | 旧单记录投影仍逐版本findById文件；PR44只把列表改为map。不含fileId时无此查询，事务/L1缓存与请求上下文会影响实际次数。当前1个无文件版本详情3 SQL，不是大V N+1的运行证明。 | 复用列表的请求内文件上下文/纯投影，可减少重复往返；先量化详情实际增长及权限/身份反证，再讨论实施。 |
| 删除文档，V个版本均未被引用 | 控制器anyMatch逐版本countByDocumentVersionId，最坏V次；发现首个引用会短路，上游删除保护图还可能先阻断，不能只计源循环为生产成本。 | 整体引用exists或批读是候选；先以完整生产guard取证，保留数据库FK最终防线/锁/审计，不在此批实现。 |

这些为source-confirmed/待讨论候选，不宣称生产延迟、OOM、p95或可承载数量；默认页长不能限制详情完整版本历史。既有设备/物料三性能风险仍开放。

## 结构与所有权

文档控制器约500行，当前读取已由PR44局部读服务接管，剩余较大职责是分类命令、文档/版本写入以及带仓储IO的审计快照。当前两个确定性根因只需授权和映射，不为行数搬迁。

W6具体候选：

1. `DocumentAuditSnapshotFactory.document(master, categoryName)`及`.version(master, version, categoryName, fileMetadata)`只返回现有中文业务键Map，不依赖仓储；序列化/不可变AuditEvent写入留同一原业务事务，不新建审计体系。收益是让隐含文件/分类读取可见，风险是缺元数据、null与“未分类”历史解释改变；用真实前后快照、缺文件ID保留、时间/状态、操作者和DB失败回滚保护，需保留目前未决缺文件政策。
2. 若后续分类命令持续增长，再由`DocumentCategoryCommandService`拥有分类资格、写入、相关文档与每对象审计、事务；Controller只做传输。删除保护当前位于HTTP Aspect，抽取前必须明确保护仍覆盖服务调用和正常API，不能把业务规则随方法搬丢。输入/输出沿当前DTO或独立命令记录，不反向依赖Controller DTO，不把整控制器搬到同体积service。
3. 请求内`DocumentWriteContext`是否值得抽取需先证明真实消费者和重复IO；只读查找可复用，锁内资格/冻结时点不可删除，不加跨请求缓存。没有真实复用价值时直接局部参数即可，不先造框架。

以上仅结构建议，未实施；可在原入口保持委托以便分步回滚，不改变外部API、生产/DHR快照、版本身份或历史数据。排序未知ID兼容/审计规范先核来源，独立列待取证，不因现代码存在而自动视为确认。
