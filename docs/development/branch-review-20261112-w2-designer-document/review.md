## 确认的缺陷与修复边界

`W2-DESIGNER-DOCUMENT-LOAD-001`：持久化设计读取失败被当成成功空白设计，或直接抛异常。位置是“表单建模”打开某个版本的 React 设计器，三片内容分别为模型、画布和工作流 JSON。

旧 `safeParseJson` 对非空损坏 JSON 返回 null；协议判断只检查 schema，无法识别的非空来源返回 undefined；后续规范化用空文档补齐。Shell 不区分失败和真实初始空白，继续 `setDocument`、`markSaved` 并允许保存。因此损坏工作流或不支持协议可以显示可编辑空白并提交默认内容。部分非数组画布结构则在规范化时抛异常，页面没有受控错误状态。错误对象类型不是“成功读到一个空设计”。

同最终维护脚本选取旧 `0dd6e882` 的真实 document/Shell 模块：Node 27 项中 11 通过、16 失败；1440 和 390px 每宽 8 项中 2 正对照通过、6 失败。浏览器原件记录了实际 onSave 写出默认内容，以及 canvas 结构错误的 pageerror；没有把构建或依赖失败当作产品反例。这里证明的是实际组件及宿主写回调风险，不声称已在生产库覆盖数据。

修复只涉及两个产品文件：

- `document.ts` 为编辑入口提供显式读取模式。非空损坏 JSON、无法解释的 schema/协议版本/顶层 payload 和实际使用的结构数组不能被静默当成空白。每片只 JSON.parse 一次。协议 version=1 不是业务模板的 V1 标签。
- Shell 只在当前来源成功读取后展示编辑内容、开放保存/字段保存/导入/预览；失败显示沿用 MUI Alert 的中文提示，保留关闭、重新打开。失败不修改旧 store、undo/redo、保存基线或源内容，也不以 markSaved 假装成功。切换等待期间和持有旧上下文的写回调同样不可写错来源。

真实空白 null/undefined/空字符串、当前后端三个原始空初始格式 `{"fields":[]}` / `{"layers":[]}` / `{"nodes":[],"edges":[]}`、空对象及当前协议的不完整 payload 保持可编辑。正常文档保留字段/页面身份、零值、用途绑定和工作流往返。不是增加发布前完整性门禁。

后台保存入口本来可接受 bare nonempty JSON，本批没有将其定义成全局“业务非法数据”。当前编辑器无法解释该非空来源时停止错误覆盖；没有新增后台 schema 规则、自动迁移、补造或恢复历史数据。默认两参数只读消费者的原兼容行为保持；保留原行为不等于已认证所有历史格式均能正确显示。

## 源码映射与历史去重

`TemplateModelingPage` 的两个 mutation → `TemplateDesignerReactShell` 的当前来源读取/保存/导入 → `document.ts` 解析、规范化、序列化 → 原保存 API → `TemplateModelingController.saveFormTemplateVersionDesign`。只读相邻入口核对了 `FormInstanceDetailDrawer` 和 `WorkTemplateEditor` 的默认两参数调用。`templateImport.ts` 保留当前页面 ID/名称，分发 Excel/Word；Shell 原导入结果身份检查和旧异步结果隔离保留。

历史 `branch-review-20261028-designer-import` 的 XML parsererror/旧导入结果保护、`designer-save-context` 的保存上下文，以及前期共享选项/子列同步都属于不同触发路径。本批不以新 ID 重算旧缺陷。持有旧字段保存回调是生命周期压力用例；当前 ModelTab 在第一个 await 前调用持久回调，未声称这里又发现了一个真实延迟调用缺陷。

固定候选树机械清单 8,267 路径，其中 5,813 为历史审计证据、353 为知识文件。清单只盘点，不自动设为一致。六条方法范围记录说明实际阅读/运行和局限，不增加整文件完成数，也不声称得到去重后的全审计完成比例。

本批没有发现并量化新的 N+1 或数据库分页风险，也没有将常规 JSON 全量读取直接定性为生产性能故障。大文件解析/整文档规范化容量需另设样本、测 CPU/累计分配/峰值和响应阻塞，再按用户要求讨论；不能从“最多三次 parse”推断大文档 SLA。
