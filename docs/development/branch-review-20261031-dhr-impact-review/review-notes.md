# 本轮源码判断与后续边界

## 已核对的链

记录控制 submit 在工单→生产对象→执行→记录锁下重新检查当前修订/状态；待审DHR阻断记录控制申请。批准实际创建新修订或作废，切换当前贡献/执行态及统计投影，并在同事务登记冻结版本影响及个人提醒。DHR批准先锁工作流、对象、DHR，再核本人候选、当前版本摘要、人工完整核查、在审记录控制、来源变化及冻结附件原件；允许明确人工退回而不因变化自动退回。

冻结版本包含完整候选、逐来源证据及 checkResult，DhrFrozenEvidenceIntegrity 校验成员、逐条摘要与全版本摘要，不能误报“完全没有摘要检查”。来源变化比较覆盖表单快照、字段值、状态、模板版本、当前修订、成员新增/缺失、实际生效事件和附件；checkResult 是提交时人工作出的检查凭证，不是自动质量结论。

普通账号验收新增7组角色/权限组合：匿名、无菜单、只有动作、只有菜单、当前候选、同页权限非候选、提交人。读取前后和拒绝动作前后核工作流任务、审计、签名、表单、执行、冻结版本及审批状态不变；候选具备菜单+动作才成功批准。另两例验证本人提醒与同名他人隔离，以及已办人变更后仍读冻结旧值、不重复批准。当前账号均ACTIVE；这不是停用、锁定、跨租户、所有候选规则/全部收件人/附件权限及完整浏览器矩阵。

## 健壮性与 A23

版本摘要、冻结证据交叉核验、任务身份重查、来源锁和签署身份核验分别防止过期批准、替换原证、越权、并发生效及签署错人，有具体业务依据，不能作为“过度防御”删除。提醒按收件人ID隔离；同名不能作身份依据，通知列表可读不授予业务页面权。保留记录控制旧记录与当前有效贡献分离，不把存在历史记录直接解释为当前贡献仍有效。

确认存在冗余读取候选：DhrReviewService.detail 调用 summaries.version，其中已取得影响列表，随后再次 evidenceChanges；现生命周期测试明确观察到两次。先登记，未调整事务/一致性边界或实施性能优化。DhrEvidenceImpactService.changes 仍一次读该版本证据；附件摘要读取及 sourceEffective 逐版本/收件人写入也需容量实验。不能把必要逐目标审计写入一概算成坏循环SQL；应区分重复读取、业务必需写入及可批处理候选。

## 已确认的性能机制

DhrReviewService.list 虽采用64行 keyset分批，仍读全部人的全部DHR任务，在Java判断候选/已办、关键词、累计总数及取页。返回20条不限制总工作量。受控 H2 实测个人总数始终21：系统21/521/5021任务需2/10/80次SQL和21/521/5021行。没有证明全量对象同时驻留内存；准确风险是随历史增长的往返、扫描、反序列化和CPU开销。未做生产规模SLA、PG执行计划、实际峰值内存测量。

建议下一批保持既有权限真值表（unrestricted、非空userIds优先、空集合回退assignee；已办只看实际处理人）、大小写/空白关键词与ID降序，把筛选、COUNT及LIMIT/OFFSET下推数据库。先用正反矩阵证明等价，尤其候选JSON空/缺失和多人、已办与待办、页归一化；再测大历史PG SQL/计划，不降低保护或伪报容量认证。已提出讨论，未获明确答复前不实施。

## 具体拆分方案

本轮不做大重构。若后续授权，可从 DhrReviewService 抽 `DhrReviewQueryRepository`，只拥有个人筛选谓词、count/page SQL和行映射；任务候选规则保持可验证的单一来源，事务锁、审批与签署仍留 service。DhrSummaryService 可分 `DhrFrozenVersionReader`（版本成员/摘要及冻结附件读取）与 `DhrSummarySubmission`（冻结/工作流创建的事务编排），先固定读写行为再分步迁移，不同时改变业务规则。RecordControlService 可抽 `RecordRevisionApplier`（修订/作废及当前投影切换），申请/办理及锁顺序保留原服务；DhrEvidenceImpactService 可分来源差异读取和收件人投递，必须保持同一生效事务。以上是有具体责任边界的后续方案，不是已实现结果。

## 两项旧 high

`discrepancy.dhr-review-complete-evidence-impact-gap`：明确的来源内质量字段变化已覆盖；来源之外的质量/异常权威事实与触发点缺精确契约，且完整矩阵未完成。不能创造自动质量判定来关闭。

`discrepancy.dhr-review-effective-source-integration`：变更/作废生效、双向待审阻断、影响提示和个人提醒已有实现，本轮补有限真实PG/JWT/MVC验收。全部普通UI、账号状态和所有收件人/权限组合仍待覆盖，保持open。不能再写“记录控制尚未实现”，也不能因9个场景全过将整项关闭。
