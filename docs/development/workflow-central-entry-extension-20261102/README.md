# 集中流程入口与签名重新分配

本轮在主目录 `edhr-dev` 补充普通表单与 DHR 汇总审批。正常开发入口继续为 <http://localhost:3000>，后端 8081；无需切换工作树。

## 范围

| 业务 | 流程日志 | 流程干预 | 处理人主动转办 |
| --- | --- | --- | --- |
| 表单变更、表单作废 | 现有记录保留 | 现有签名重新分配保留 | 保持已有配置 |
| 普通表单流程 | 已保存且有运行流程的表单实例 | 当前审批节点可签名重新分配 | 保持原有处理人转办 |
| DHR 汇总审批 | 审批流程及历史 | 审批中可签名重新分配 | 本轮不开放 |

作业与工艺路线不扩展到这两个入口。填写阶段可以出现在普通表单日志中，管理员改派不扩大填写资格。没有流程节点的旧表单不补造流程记录。

## 人工验收

1. 刷新页面，在「流程日志」核对业务类型、业务编号及详情。DHR 编号同时显示汇总版本；普通表单以具体表单实例号区分。
2. 在「流程干预」使用操作列的重新分配图标；并行时先选当前任务。选择新处理人、填写原因，输入有干预权限人员的签署账号和电子签名密码。
3. 用原、新处理人核对待审批入口：原处理人失去该任务处理权，新处理人从原业务审批页面继续处理。节点、表单内容、冻结汇总和已有审批决定保持。
4. 查看流程日志中的重新分配记录，再分别查看对应表单详情的数据审计、DHR 详情及对应汇总审批版本的数据审计，核对原/新处理人、原因、实际签署人和签名标识。

正常库已有审批中样本 `DHR-UAT-1030-DHR-REVIEW · V1`，可以用此前验收账号进行 DHR 改派验收。本轮没有重置这些样本。此前 8 份源表单已完成且无普通流程节点；验收普通表单改派需使用已保存、已经进入审批节点的普通表单实例。

自动检查的数据写入在隔离测试库进行；正常开发库只做登录和业务读取，登录会产生正常登录审计。详细验证和独立门禁见 [validation.md](validation.md)、[ontology-result.yaml](ontology-result.yaml)、[quality-result.yaml](quality-result.yaml)。
