# 本轮用户直接确认

来源：当前会话，2026-11-05（Asia/Shanghai）。以下为原话，先前审计取证及实施选择不回填为旧业务政策。

> 好的，我认同你说的，第一和第二项，我觉得都可以现在修复。第三项我觉得一个公司暂时不会有6.5W级的员工，但是我比较关心你说的100这个数字，前面多次提到了？现在我们的人员查询是最多只会返回100人吗？如果是这样的话，我觉得这个不行，我们页面应该满足所有满足权限的人员选择，至于是否通过懒加载还是说分页加载的形式是我们来设计的，而不是我们只最多返回100个满足权限展示的人员

> 我记得之前也有提过100名匹配人员的，那边其实也要统一设计，我们不能最多只能返回100名，但可以分批懒加载，而不是限制最多100

“第一项”为普通表单详情当前处理人姓名的条件性N+1；“第二项”为原冻结候选逐ID绑定参数增长；“第三项”为6.5万合成账户下文本ID条件的索引/扫描风险。授权前两项整改，第三项索引不在本批实施。

全部可达指各入口既有资格集合：通用/普通表单本人转办的租户范围、记录控制原候选与申请人回避、各类管理员改派资格和DHR专属禁止动作保持。用户未指定每批大小、页码、续页字段或组件；这些属于主审工程选择，不写成用户逐字段确认。

主审实现选择：服务端分页窗口，不计算未消费总数；前端共享人员选择器分批继续加载，单批大小只控制一次请求工作量。任务签名密码链和生产管理弹窗样式继续按原要求暂停，仅同步其人员选择入口以满足本轮明确范围。
