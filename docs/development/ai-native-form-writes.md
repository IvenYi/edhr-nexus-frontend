# AI 原生表单写入切片 1B

本切片建立 Java 确定性写入边界，供后续 DSH Worker 使用。当前不新增 AI 页面，不运行付费模型，不声明完成商用验收。依据：已批准产品设计、AI运行契约、DEC-0097及[1B决策包](../architecture/ai-collaboration-slice-1b-decision.yaml)。

## 业务与调用边界

创建表单、保存设计是业务动作；表单创建、设计保存是动作提交后的事件；Agent 工具是受控动作的调用入口。生产过站是另一个领域动作，不属于当前配置能力。首版任务只能创建一个原生模板及初始版本，之后仅能编辑本任务创建的版本；不提供绑定任意已有模板的入口。

`TemplateModelingService` 复用原模板控制器中的领域逻辑、追溯配置校验与原生审计；控制器保留 REST 路由和权限。原单体同时含 DHR 与表单方法，共用分类和辅助方法，因此按原结构提取为应用服务；DHR 方法业务含义未调整。AI 模块不复制这套领域规则。

Worker 使用服务凭据，不能提供业务用户或替换任务目标。服务每次重新检查部署启用、能力启用、真实发起人的现行权限、任务和执行轮次、租约代际及限额。原生审计归因真实用户、来源为 AI，补充 `AI_FORM_OPERATION` 审计连接任务、轮次、操作回执、目标版本与修订。模型声称检查通过不能跳过领域检查。

## 接口与事务

| 接口 | 用途 |
| --- | --- |
| `POST /api/v1/ai/internal/forms/read` | 读取任务自己的原生目标并取得编辑占用，记录本轮读取修订 |
| `POST /api/v1/ai/internal/forms/write` | 受控 `create` 或 `save-design`；传入 taskId、runId、leaseEpoch、operationId、form |
| `GET /api/v1/ai/internal/forms/receipt` | 按 taskId、operationId 查询历史提交回执；停止后仍可按现行授权读取 |
| `POST /api/v1/ai/tasks/{id}/actions` | 沿用任务动作接口；`stop` 或 `takeover` 结束本轮并释放占用 |
| `GET /api/v1/ai/tasks/{id}/events` | 按 after 游标读取可读运行事件 |

创建必须指定存在的 FORM 分类；缺失名称用“新建表单”、版本用“V1.0”、编码由任务 ID 确定生成。新建原生模板与初始设计、目标关联、审计、事件和操作回执在同一事务提交；任一环节失败整体回滚。任务已有目标后不允许再次创建。命名冲突或真实业务歧义交由后续 Agent 处理，不静默写到其他分类。

`operationId` 在任务内唯一；相同规范化请求返回原回执，不重复执行；同 ID 不同请求拒绝。超时后先查回执再决定下一步。回执描述该次提交时的修订，当前原生状态必须通过 read 再读，不能将旧回执当成当前事实。创建/保存回执不使任务进入 `SUCCEEDED`；完成证据、预览与问题状态属于切片2。

## 原生并发与人工接手

父模板与版本响应返回 `revision`；修改和删除请求携带明确的 `expectedRevision`。缺失、过期或占用冲突返回409，禁止服务器自动替换为最新修订。现有页面的模板、版本编辑及删除已经适配；设计器自动保存和手动保存共用单个打开会话的串行队列，每次使用上次成功响应的修订。失败或结果不明时停止后续队列，重新打开并读取后才能继续。

`FormEditGuard` 属于原生表单领域，不依赖 AI 模块。父模板先于版本加锁，分类批改和追溯解除按父 ID 排序；当前有效的版本占用阻止人工设计/元数据写入、父模板修改/删除、新版本及相关追溯解除。`takeover` 返回后，旧执行代际不能再写；已经提交的原生成果保留。租约过期后人工可编辑；Worker 重新领取或继续任务必须重新读取当前原生修订，不能沿用旧上下文覆盖人工修改。

后端与现有前端需要协调部署：旧客户端没有修订号的原生修改将收到409。这是显式并发协议变化，不是对旧写请求透明兼容。普通原生使用不依赖 AI 启用开关。

## 可读运行日志与展示契约

运行日志是持久化的用户协作记录，与原生合规审计通过标识关联。它不记录或展示模型隐藏推理、密钥、完整附件或任意工具原文。模型解释是解释文本，不能作为已执行事件或成功证据。

| 阶段 | 持久化内容 | 用户呈现 |
| --- | --- | --- |
| 1A/1B | 排队、领取、停止/失败、预算预留/结算、表单创建/设计保存；包含 actor、task/run、序号/时间、操作与审计及目标修订 | 服务端根据已提交类型生成 summary、level；如“已保存表单设计，修订 3” |
| 切片2 | 知识查询及版本、工具开始/结果/失败、确定性检查、预览修复、待问项与恢复依据；结构化安全摘要 | 如“查询了批号追溯规则”“为12个字段配置类型”“校验发现2处未完成，正在修复”；数字必须来自结果 |
| 切片3 | 消费上述事件接口，不依赖浏览器保留日志 | 默认紧凑时间线；可展开详情、按轮次定位、继续加载；成果项直接打开对应原生对象 |

每条可执行步骤后续必须带稳定 stepId/toolCallId，区分 started、committed、failed、interrupted、result-unknown；请求重试不得重复显示为完成。准备执行不等于已提交，预算预留不等于模型已回答，保存不等于任务已完成。原子回滚不得留下“已保存”事件。停止后的晚到响应不得生成业务成功事件。用户能看到谁发起、发生了什么、作用于哪个对象、结果及下一步可做什么；权限按任务归属和现行能力校验，不向其他用户泄露日志。

事件按递增序号分页，当前每页最多100条，通过最后序号继续；历史轮次留存。切片2再补工具过程事件结构、长度限制、重试展示、保留与清理策略；首批商用前必须验证日志缺失、断线重连及导出/保留要求。本切片不把上述后续能力描述为已实现。

## 验证与部署边界

真实 PostgreSQL 测试覆盖建表幂等、事务失败回滚、当前权限、原生修订和占用、接手/保存竞争、过期重领、人工修改保留、回执和可读事件、Worker与用户认证隔离。迁移测试覆盖旧主表与设计及审计保留、0094只执行一次。前端队列测试覆盖自动/手动保存竞争及未知失败阻断。

完整运行证据见独立质量结果及1B验收记录。DSH工具接入、三张表单双模型质量、原生预览证据、生产选用边界、实际容量与新页面均未由这些测试覆盖。部署默认保持 AI 关闭；回退前停用能力、停止任务并释放占用，不删除原生成果、回执或审计。
