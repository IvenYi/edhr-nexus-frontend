## 对照我们的当前实现

1. 记录控制的申请、审批/退回、真实生效及 DHR 联动已有代码和上轮独立验收，本轮不重做。
2. 通用流程转办已有任务锁、资格、原因、日志、前后状态审计，并保留同一逻辑任务；记录控制任务仍明确拒绝从通用入口转办。应复用已有能力并按业务边界接入，不能把“普通转办已有”算作“记录控制转办已完成”。O02/O03。
3. 撤回仍是 `RecordControlWorkflowWithdrawalPort` 声明；重新分配仍只有 `WorkflowIntervention` 实体等基础，尚无完整专用运行链。已有表或 DTO 不能计为已交付。O01/O05。
4. 实例、日志已有读取及历史局部修复，但当前详情仍期待 `templateName/businessKey/startUserName` 等投影，后端实例接口返回实体且图另走 `/graph`；日志还保留有干预权限的通用增改删。权限收紧不等于日志只读或正式干预动作。这里只静态核对，不把投影不一致外推为本轮已运行复现的所有页面故障。O04/O06/O07。

## 建议怎样借鉴和改善

### 1. 保留集中查询，清楚区分三类动作

- 转办：当前任务处理人在任务详情操作。
- 受限撤回：申请人在申请详情操作；任何并行分支已经批准或退回即不可撤回，成功终结本轮并同步处置待办、申请、拟数据和业务锁。
- 重新分配：有专门权限的人员在流程干预页操作；按本次确认必须签名，不变成代审批。

这是沿用我们的现有责任边界。冠骋的干预页“转办/撤回”不直接复制过来；P0 干预台继续只提供当前范围内的查询与重新分配，不顺带增加管理退回、终止、跳过或直接批准。DHR 现行专属处理边界保持，集中查询不能自动授予它通用干预动作。

### 2. 从“换个人”改善为可核对的重新分配确认

建议一个沿用 MUI 的紧凑动作对话框，展示申请/业务编号、当前节点和任务、原处理人、新处理人、必填原因，并复用现有电子签名交互。签署对象应固定本次动作及原/新处理人、原因和任务版本；修改目标或原因后不能沿用旧签名。执行人、会话人和签署人按现有共享终端规则分别记录，签名不能替代动作授权。

后端不能仅信任前端提供的 `signatureId`；需要核验签署主体、动作、对象及内容绑定，且新签署目标不能被通用签名修改/删除入口绕过。当前记录控制已有专用签名保护，不代表未来重新分配目标类型天然受到相同保护，实施时须明确复用边界。

确认时服务端重新核对任务仍有效、当前处理人/版本没变、管理者权限及目标资格；目标停用、跨租户、非法自审等按现行领域规则拒绝。所有状态、待办、签名、流程日志和不可变审计由同一受控事务提交。若任务已被批准或别人重新分配，明确提示状态变化，不沿用旧弹窗继续覆盖。

这些是后续方案建议，不是本轮已经实现或完整确定的接口契约；具体签署 payload 与并发策略在实施切片核对现有签署能力后确定。

### 3. 保留同一任务身份，分别解释原资格与当前责任

借鉴冠骋即时更新旧/新待办及流程图，但继续复用我们已有的同一逻辑任务模型；保留节点到达时原候选来源和冻结版本，当前受让人另行记录。针对一个 taskId 重新分配，其他并行分支保持原状。历史清楚标注转办/重新分配，避免把处理人变动显示成审批通过。

### 4. 干预台首先帮助定位问题，页面沿用现有规范

建议按申请号/流水号/批次或SN、业务类型、处理人和状态定位；列表优先展示业务编号、当前节点、当前处理人和等待时间，侧栏查看冻结版本、来源记录、任务历史和签名。只显示已开放且有权的动作。参考冠骋按业务筛选和详情联查，但不为未支持业务复制一排空标签。

查询、详情和日志沿用既有列表/抽屉/图组件；不要为了建设流程基础重做配置画布、表单渲染器或现有审批页。此处仅是建议，没有页面代码变更或新的视觉验收结论。

### 5. 日志用于解释，审计用于保留证据

流程时间线清楚展示谁在何时因何原因把哪个任务从谁交给谁，以及之后是否审批；同时写不可变审计并可关联签名和业务申请。收口通用日志的新增、修改、删除及任务/实例任意 CRUD，不能把这些接口当作重新分配的捷径。正式写入只经标准动作，页面读日志；历史缺信息明确标识，不补造。

## 建议的最小接续顺序

1. 先收敛共享动作及投影：复用现有授权/签署/锁/审计，补专用重新分配与记录控制转办/撤回协作，不新造第二套流程引擎。
2. 做“流程干预查询 → 单任务重新分配 → 原人失去处理权、新人取得待办 → 日志/签名/审计可读回”的最小纵向切片。
3. 接通记录控制转办与申请人撤回，验证并行任务、原资格保留、业务锁与幂等、失败回滚。
4. 补任务/实例/日志互查及普通角色、并发、签名失败和旧页面回归。范围内完成才算流程基础交付；本轮调研通过不等于这些运行功能完成。

上述顺序为 `inference`，供后续实施取舍。批量交接、离职全部任务迁移、超时升级及补偿暂不扩展；归档及其他已暂缓范围保持。
