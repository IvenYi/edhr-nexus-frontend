## 实际调用与复用边界

1. DhrAttachmentController.download：调用downloadableFile获取路径，再独立originalName获取响应文件名。实际当前附件链有5个显式Jdbc查询，冻结链多一个版本快照查询，共6个。这是PR54已实际容量观测的结果，本批源码重新核对；不冒称本批已重跑50MiB容量试验。
2. downloadableFile：先查DHR、附件active/SHA，再检查指定版本id+SHA成员或当前active，之后file又查DHR及原件路径/SHA并完整验证文件。两次DHR检查发生在不同时点，不能仅看SQL相似就删除；原始资格及校验时点保持。
3. DhrReviewController.attachment：先service.detail核当前用户对任务/版本的资格，再走上述冻结附件链；任务读取的查询额外存在，不能把6称为整个任务HTTP请求总查询。文件名复用不能绕过任务detail或版本成员判定。
4. DhrSummaryService.submit：先锁生产对象，再锁DHR、核草稿身份/修订/来源摘要。snapshot已获取全部有效附件元数据，但其公共JSON不暴露stored_path。循环每个附件要求VERIFIED后调用file，每次再次读DHR和原件元数据、完整SHA。父锁内的重复读需要独立量化，不通过把服务器路径塞进响应来复用。
5. 附件upload/verify/unlink都先锁父DHR。新测试以实际公开submit前缀和实际unlink观察pg_stat_activity的Lock等待；事务管理/SQL/锁/文件为真实，detail/impact/forms/workflow替身及人工guard停点必须保留在报告中。它不认证所有写者、所有账号及部署并发。
6. DhrArchiveService.export没有类/方法事务。附件循环先file，随后readAllBytes，再与冻结快照size/SHA比较，才加入ZIP；单附件仍有整数组，另有formPdfs累计和combined PDF。不能把Summary持父锁的论证直接套到导出，更不能认为PR54流式摘要已使整个ZIP/PDF内存有界。

生产源码检索到附件UPDATE只更新核验或解除关联字段，未见改original_name/stored_path/sha256的现有接口。这是当前实现观察，不是新增永久不可变政策。新入口和迁移需继续增量反查。

## 性能规模与索引边界

本处N是“DHR汇总附件数”，不同于生产表单数量。即使一份DHR的表单不超过300张，也不能据此推定附件数、字节总量、并发数或PDF页数上限。50MiB是单附件上限；极端300个满限附件约14.65GiB，每次汇总仍必须完整读取。该数只是容量推算，本批不制造/测量该规模，也不声称真实业务常见。

当前file循环每个附件增加两次数据库往返，即使索引命中也不消除次数；完整SHA的O(总字节)成本和持锁时间另算。后续若优化，应优先考虑在已有父锁下重用一次内部读取上下文，保证租户/DHR隔离、active集合、核验状态、顺序、完整SHA及缺失拒绝；不要加永久缓存、跳过SHA或把所有调用方换成批处理。

原生baseline已有dhr_attachment主键(id)、idx_dhr_attachment_active(tenant_id,dhr_instance_id,active)，DHR/生产对象主键和草稿(tenant_id,dhr_instance_id)唯一约束。按id读取已有主键候选，按当前DHR活动集合有组合索引候选。本批查询次数诊断的隔离夹具只加载canonical七表及PK，未完整安装索引/FK/迁移，不能用它判断生产扫描计划。本批不添加重复索引；若后续调整批量集合/ORDER BY，应在真实混合分布和完整索引上EXPLAIN ANALYZE，另看排序/行宽与深历史成本。

## A23：必要防御与简化候选

| 范围 | 结论与理由 | 处置 |
| --- | --- | --- |
| 当前active或冻结成员id+SHA检查 | 两种访问资格不同，解除后的历史文件仍可按原版本取用 | 保留；不是可删的重复防御 |
| file存在/完整SHA | 防丢失/篡改；数据库元数据存在不代表磁盘正确 | 保留流式完整校验 |
| 两次DHR存在读取 | 调用复用产生重复，但不同时点，不凭静态相似性推定冗余 | 当前保留，批量上下文须证明边界 |
| 最末单独originalName | 路径/SHA读取时可内部携带名字，省一次查询 | 提案待用户选择，未实施 |
| 汇总VERIFIED和来源hash/人工三确认 | 分别保护核验、草稿范围及人工结论，不能互相替代 | 保留；测试刻意停在三确认guard |
| 导出当前原件hash与冻结size/hash | 两者参照对象不同，防当前与历史不一致 | 保留；不能为省IO直接删除一层 |

这只是上述方法范围有限复查，不计整文件完成、全项目A23完成或新增历史唯一覆盖。
