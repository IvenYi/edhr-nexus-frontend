## 当前实现

依据 DEC-0023-08 的“清理或阻止保存”，按 DEC-0035 现行权限组键、真实 fieldId 和声明按钮事件核对。后端在写作业草稿之前，只检查可解析当前活动绑定中已经提供的引用，失效时阻止保存并保留原图和审计；不自动删除配置。没有引用的空配置不读取多余元数据，缺失ID、记录不存在、未发布或错类型的未完成上下文仍由原发布完整性门禁处理。服务端元数据损坏或查询异常不吞掉，不按空集合处理。

原完整 `validate` 的主体、按钮、签署和可用签名字段要求保持；草稿不会被要求完成所有必需签名绑定。共享引用集合只避免两条检查重复解释键，不新增规则引擎或客户条件分支。休眠模式不检查、不清理，已有冻结/历史读取与 CUSTOM 不改。

原字段权限弹窗无法删除隐藏旧组，现有明确“保存配置”命令增加 `pruneFieldPermissions`，与原事件prune一起保留有效例外、默认权限和签名绑定；只有当前key的元数据请求成功才允许纠正确认。没有打开effect，不用不含nodesJson的流程列表选项清理配置，加载、失败和取消不制造写入。产品workspace与产品/产品簇完整Dialog继续使用同一组件和原后端完整保存校验。
