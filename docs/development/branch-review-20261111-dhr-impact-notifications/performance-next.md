# 通知生产读取的性能线索与建议

`PERF-DHR-IMPACT-NOTIFICATION-READ-001`。来源生效时，一个原表单可能被多个历史冻结汇总版本引用；每版本都需要影响记录和通知。主侧真实1/10/100个版本分别2/11/101 SELECT，另各2/20/200写命令；100版本source阶段约123ms、调用线程累计分配622664B，不是全部审批耗时、锁时或峰值。版本数不是人员或表单数量限制。

根因是sourceEffective先取全部受影响版本，随后每版本查询一次当前DHR审批任务；已结束且无当前任务的版本仍需一次读取。这是线性往返风险，不是通知发错人。实际本机100版本未证明紧急容量故障；建议先继续整体其他入口审查，不因发现循环就自动改产品。

若后续决定整改，最小方案是本事务一次批读这些版本的当前任务元数据，按版本分组传给原收件集合算法。原提交账号恢复、改派及冻结候选、无限制实时资格、每版本影响／通知、去重、同事务回滚及个人已读都保持；不能改变通知条数、改成异步、加总数上限或跨请求缓存。需同16组合、真实多版本、已读重投、失败回滚及SQL预算回归，并由新独立实例验收。

索引单独评估：现有recipient+impact DESC、影响唯一键、review主键保留。版本来源定位可考察tenant/source_record/version组合索引，但本批集中同来源的小库计划不足以决定；应先加入大量无关来源、ANALYZE、比较真实选择率／buffers／写放大，不因批读顺带上线索引。当前未实施任何新性能优化，也未请求用户重新批准本已授权且PR83已完成的流式SHA与结果复用。
