## 具体检查项

1. 无真实输入/历史依据的空值处理、默认对象、默认账号/版本/状态；错误输入被改成看似有效的值，是否掩盖错误或跨身份。
2. 过宽catch、空catch、失败返回空列表/成功、静默continue或错误降级；原件/审计失败能否被发现及正确回滚。
3. 下层刚校验/已有可信上下文却重复查库、解析或全量遍历；区分无意义重复与锁内新鲜度、权限或外部输入二次校验。
4. 不可能状态的多层null分支、可被前置调用不变量证明的死兜底、同一模块多种不一致的默认策略。
5. 无当前消费者或明确兼容责任的旧格式/多模式旁路；以真实用户确认和旧合法快照区分开发遗留与必须保留的历史。
6. 过度重试/补偿/通用包装器，以及以fallback绕过流程阻断；结合幂等、资源释放、可诊断性和代码复杂度评估。

每条记录必须给出固定commit、具体方法、保护对象/前置不变量、原始依据、正常与错误路径、反证、结论和适用测试。结论区分 `necessary-protection`、`simplification-candidate`、`evidence-gap`、`needs-decision`；未查保持pending。模式搜索只定位，不能自动判断过度防御。

权限/租户、签署、锁内实时资格、提交前快照重核、审计/原件校验、数据库最终约束、可信边界两侧校验不能因“重复”直接删除。确认可简化时用最小修改与正反回归证明；性能优化继续先取证讨论，业务政策不由代码简化替代。
