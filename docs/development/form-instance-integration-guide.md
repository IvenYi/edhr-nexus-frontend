# 表单实例全场景对接与开发规范

文档版本：2.0　核对日期：2026 年 9 月 16 日　知识基线：0.3.20

适用对象：统一表单列表、生产与非生产填报、表单变更与作废、公共流程、数据查询、DHR 及测试开发伙伴。

**表单实例是各模块共同引用的一份业务记录。**统一实例目录应覆盖生产工单、批次、SN、设备点检、清场和独立发起等所有来源。伙伴通过目录查找实例，通过详情了解模板与业务背景，通过操作上下文进入填报或变更；无需先知道模板，也无需自行拼接其他模块的数据。

本文给出业务场景、统一数据契约、查询规则、完整调用链及交付验收标准。第 1 至 12 章为目标设计；第 13 章单独列出当前实际接口。**所有新接口、DTO 字段和新增存储设计均为设计建议，尚未实现或冻结；不能直接当成当前后端调用。**用户已确认的需求和既有业务决策另作明确标记。示例数据只用于说明。

## 1 需求范围和阅读方式

### 1.1 已确认的业务要求

- 全局表单列表应查询当前用户有权访问的全部表单实例，模板名称、模板编码、模板版本、创建人、创建时间等摘要随列表返回。
- 表单变更管理可按工单、批次及其他条件查询关联实例，选定具体实例后进入变更流程。
- 所有来源统一实例管理，包括生产、设备点检、清场及独立发起表单；不能将统一能力限定在生产执行模块。
- 实例号由服务端在首次成功保存实际记录时生成，同租户跨模板唯一、不可修改、不复用。普通保存、提交、审批、退回不换号，新份新号，子表行归属主实例。
- 已完成表单的正式变更形成新修订；作废使有效记录失效且保留历史。申请、修订、审批流程各有独立身份和状态，沿用 DEC-0037、DEC-0041、DEC-0043。

“全部”指全部授权来源和模板，默认分页查询，不是一次返回全库。全局列表包含已保存未完成、已完成及作废等记录；不同状态可以筛选。尚未保存且未取得实例号的待填任务另列入口，不伪装成已编号实例。

### 1.2 三种结论的效力

| 标记 | 意义 | 伙伴使用方式 |
| --- | --- | --- |
| 已确认要求 | 用户明确要求或现行决策规定 | 纳入产品验收，不因旧接口缺少而删除 |
| 目标设计 | 本文提出的具体接口、字段和实现约定 | 作为联合开发方案评审和冻结，不能声称已上线 |
| 当前实现 | 本次核对的源代码行为 | 只按第 13 章真实接口与限制调用 |

列表伙伴重点读第 2 至 6、10、13、14 章；填报伙伴重点读第 3、7、10、11 章；变更伙伴重点读第 3、6、8、9、10 章。各方共同执行第 15 章验收，真实待决事项集中在第 16 章。

## 2 场景清单与产品入口

### 2.1 统一列表和查找

| 场景 | 用户要做的事 | 必须得到的结果 |
| --- | --- | --- |
| S01 全局实例列表 | 不选模板，查看所有来源记录 | 一份实例一行，跨模板摘要、来源、状态、创建信息、分页总数 |
| S02 模板下记录 | 从模板管理进入某模板的记录列表 | 同一目录附加 templateId，可筛选不同冻结版本 |
| S03 编号直达 | 粘贴或扫描完整实例号 | 精确得到唯一授权实例，不取模糊搜索的第一条 |
| S04 工单追溯 | 输入工单号，找此工单相关表单 | 所属批次或 SN 的实例，以及明确关联的清场或点检记录；显示关联原因 |
| S05 批次或 SN 追溯 | 按具体批次、SN 查表单 | 区分直接归属和相关引用；同工单其他生产对象的实例不串入 |
| S06 非生产来源 | 按设备、点检任务、区域、清场任务查 | 同一列表结构，生产字段可为空，不伪造工单 |
| S07 独立表单 | 查询独立发起的填报记录 | 有实例身份和模板摘要；业务关联为空也可查询及授权操作 |
| S08 组合查询 | 模板编码、版本、人员、时间、状态组合 | 服务端组合过滤；空结果、无权限、失败明确区分 |
| S09 字段值查询 | 查某模板下产品、检验结果等值 | 按稳定字段 ID 和类型过滤，不将跨模板同名字段视为同一字段 |
| S10 导出与打印 | 导出当前筛选结果或打印选定内容 | 保留实例号、冻结模板版本、内容修订和导出时点，权限同源 |

### 2.2 填报与记录控制

| 场景 | 用户要做的事 | 必须得到的结果 |
| --- | --- | --- |
| S11 首次填报 | 从任务或独立入口填写并保存 | 校验来源与模板版本，首次成功后获得实例号并出现在目录 |
| S12 继续填报 | 从目录打开未完成记录 | 定位原来源中的同一份，读取最新可用动作与并发版本 |
| S13 多份与复用 | 同模板填多份或同份被多处引用 | 多份不同号；同份多关联仍只一号、一条列表记录 |
| S14 变更选择 | 从工单、批次等筛选结果选一份 | 保留上下文，明确实例号、冻结模板和来源修订，展示资格及原因 |
| S15 变更审批 | 提交差异、签名、选择流程并确认 | 独立申请，审批期间原有效内容不被候选修改覆盖 |
| S16 作废 | 对选定记录发起作废 | 独立作废申请；通过后保留编号和历史内容并标识失效 |
| S17 修订追溯 | 查看变更前后内容及签名 | 按不可变修订 ID 读取，区分模板版本与内容修订 |
| S18 并发与重试 | 多人编辑、重复点击、网络超时 | 不重复发号、不重复申请、不静默覆盖，保留未保存内容 |
| S19 历史与停用 | 查旧记录、模板停用、来源归档 | 可授权只读追溯；不重写历史名称、不补造未知人员和关系 |
| S20 下游联动 | DHR、报表、其他业务引用记录 | 固定证据引用具体修订；查看最新值的投影明确版本与刷新状态 |

场景清单是共同验收目录。新增来源必须补齐来源注册、关系、动作、权限和测试，不仅是在下拉选项里新增一个名称。

## 3 实例身份与业务关系

### 3.1 一份实例是什么

一份实例对应一次实际填报记录，可有多次保存和后续内容修订。一个模板版本可产生多份实例；一个实例固定使用其创建时绑定的模板快照。一个实例可以关联多个业务对象，一个业务对象也可以关联多个实例。

**目标设计：**跨模块统一使用字符串 `formInstanceId` 作为逻辑主键，使用 `instanceNo` 展示和搜索。实例标识与内容修订分离，建议正式变更后沿用逻辑实例和实例号，增加独立 `revisionId/revisionNo`。沿号方案待第 16 章确认，当前实现不能证明正式变更闭环。

| 标识 | 代表什么 | 不可替代的对象 |
| --- | --- | --- |
| formInstanceId | 统一逻辑实例身份 | 不是生产 objectId 或执行 copyId；是目标字段 |
| instanceNo | 可读表单实例号 | 不是模板编码、工单号、批次号或修订号 |
| templateId | 模板身份 | 不是某一发布版本 |
| templateVersionId | 实际冻结模板版本身份 | 不是记录内容修订；当前旧接口名为 versionId |
| revisionId 和 revisionNo | 内容修订身份和显示序号 | 不等于模板版本或执行并发 revision |
| sourceType 和 sourceId | 唯一写入来源的类型及身份 | 不等于所有相关业务对象 |
| objectId 和 operationId | 生产对象及冻结工序节点 | 不等于工单或工序主数据 ID |
| formId 和 copyId | 来源中的表单绑定及具体份 | 旧执行 API 使用 instanceId 表示 copyId |
| requestId 和 workflowInstanceId | 变更或作废申请及其审批流程 | 不等于表单实例；流程 businessId 在此关联 requestId |

当前 `form_instance_record.id` 是索引主键。目标可将其迁移为统一 `formInstanceId`，但必须保留与旧接口 `id` 的明确映射并完成验证，不能让各模块自行假设已经等同。记录控制 `sourceRecordId` 需由服务端从统一实例身份解析到正式来源记录；不能未经映射直接代填。

### 3.2 唯一写入来源与多重关联

**目标设计：**每份实例只有一个负责保存和执行动作的来源域，同时可以有多个用于查询与追溯的业务关联。例如设备点检任务拥有一份实例，该实例可关联设备 E01、工单 WO01 和批次 B01；查询这三个对象都能找到同一实例，但不能因此把点检数据交给生产执行服务保存。

来源类型建议首批注册 `PRODUCTION_EXECUTION`、`EQUIPMENT_INSPECTION`、`LINE_CLEARANCE`、`STANDALONE`。这些是目标枚举，不是当前已有枚举。来源注册由服务端维护；后续质量、仓储等来源按同一契约接入，不接受客户端任意构造来源类型。

统一关系项建议包含：

| 字段 | 类型与要求 | 说明 |
| --- | --- | --- |
| relationId | string，必有 | 可追溯关系身份 |
| businessType 和 businessId | string，必有 | 如 WORK_ORDER、PRODUCTION_OBJECT、EQUIPMENT；类型和 ID 成对使用 |
| businessSubtype | BATCH / SN / null | PRODUCTION_OBJECT 的子类型，来自来源 objectType；其他类型为 null |
| businessNo 和 businessName | string 或 null | 关联建立时的显示快照；不能作为外键 |
| relationKind | OWNER / CONTEXT / REFERENCE | 所属来源对象、上下文关系、其他明确引用 |
| provenance | DIRECT / DERIVED | 直接关联或经受控关系路径派生 |
| viaRelationIds | string 数组 | 派生路径证据；DIRECT 时为空 |
| boundAt 和 validTo | 带时区日期时间，后者可空 | 记录建立与失效时点；历史关系保留 |

业务对象类型与填报来源类型是两个目录。生产对象的规范 businessType 一律为 PRODUCTION_OBJECT，批次和 SN 分别通过 businessSubtype=BATCH 或 SN 表示；不再把 BATCH/SN 用作并列 businessType。businessId 对应 production_object.id，不与 `masterdata.Batch` 的 ID 混用。来源适配器将 objectType 映射成子类型，历史无法证明时为 null 并标明缺失，前端不得按号码猜测。

### 3.3 工单与批次查找的精确边界

当前生产来源可验证的链路是：`form_instance_record.object_id → production_object.id → work_order_id`；生产执行快照 `context` 也包含 objectId、objectNo、objectType、workOrderId、workOrderNo、productId、productCode、productName 等冻结信息。

**目标设计查询规则：**

1. 查询工单所属实例时，纳入该工单下生产对象的直接表单；经明确关系关联此工单或这些生产对象的其他来源表单，在“全部关联”范围纳入并标明路径。
2. 查询批次或 SN 时，只按该对象身份与显式相关关系匹配，不自动扩展到同工单的其他对象。当前 ProductionObject 没有可直接证明 SN 归属于哪个批次的父子字段，不能凭号段推算；未来建立真实谱系关系后才支持相应查询。
3. 工单号输入先按有权业务目录解析工单 ID；无匹配返回空，多匹配展示候选。相同显示编码跨业务类型不能自动选第一项。
4. 同时指定工单和批次时，必须校验关系一致；不一致返回可说明的参数错误，不能放宽为任一条件命中。
5. 关联表连接产生多行时按 formInstanceId 去重；分页和 totalElements 均按实例计数，详情再展示全部有权关系。
6. 产品、设备、区域等普通表单引用字段不会自动成为实例级关联。只有来源服务显式登记、带语义的关系才参加关联查询，避免同名字段或任意文本误关联。

关联新增、移除或更正应经过所属业务服务授权并留下审计，不允许前端直接修改目录关联。已签署的历史关联保留；当前关系与历史关系查询通过明确的时态范围区分。

## 4 列表返回字段与快照规则

### 4.1 列表必须一次返回什么

**目标 DTO：FormInstanceSummary。**前端一次分页请求即可渲染列表。以下各表为同一 DTO 的字段分组，不要求前端再查模板、用户、工单和详情来补列。所有 ID 为字符串；不可用值用 null，不能用空字符串、0 或“当前用户”冒充。

| 字段 | 类型 | 来源及口径 |
| --- | --- | --- |
| formInstanceId / instanceNo | string | 统一身份与显示号，必有 |
| templateId / templateVersionId | string | 实际绑定的模板及版本，必有；损坏历史记录单独标识不可操作 |
| templateName / templateCode | string 或 null | 冻结模板名称和编码，历史不随模板改名变化 |
| templateVersion | string 或 null | 如 V1.0 的冻结显示版本，不用于标识比较 |
| templateCategoryId / templateCategoryName | string 或 null | 分类引用及冻结名称；无分类不伪造 |
| sourceType / sourceTypeName | string | 填报来源类型及中文展示名 |
| sourceId / sourceNo / sourceName | string 或 null | 唯一写入来源；独立来源需内部来源身份，名称可空 |
| recordStatus / recordStatusName | string | 归一化主状态及文案，见第 9 章 |
| sourceStatus / sourceStatusName | string 或 null | 来源原始状态，保留以解释业务差异 |
| completionMode | string 或 null | WITHOUT_FORM_PROCESS / WITH_FORM_PROCESS；未完成为 null，见第 7.5 节 |
| activeRequestType | CHANGE / OBSOLETE / null | 申请标记，不覆盖表单主状态 |
| activeRequestId / activeRequestStatus | string 或 null | 当前活动申请；不可见申请不泄露其详情 |
| currentRevisionId / currentRevisionNo | string 和 integer 或 null | 当前内容修订；尚未形成正式修订时为 null |
| contentVersion | string | 该实例内容与状态的并发标识，目标服务生成，不用更新时间代替 |

`recordStatusName`、`sourceTypeName` 等为可本地化显示文字；代码按稳定枚举判定，不能按中文文案做业务逻辑。

### 4.2 人员与时间字段

| 字段 | 类型 | 口径 |
| --- | --- | --- |
| createdById / createdByName | string 或 null | 首次成功保存该份记录的人及当时姓名快照，不是模板创建人 |
| createdAt | 带时区日期时间或 null | 首次成功保存实例的时间，不是流程启动或导入时间 |
| updatedById / updatedByName | string 或 null | 最近成功更新当前内容或主状态的操作者 |
| updatedAt | 带时区日期时间或 null | 业务更新时点；重建索引不修改 |
| submittedAt / completedAt | 带时区日期时间或 null | 本实例首次有效提交、首次完成的业务里程碑；退回重提和后续变更时间保留在事件历史 |
| numberedAt | 带时区日期时间 | 发号时点；历史补号可能晚于原填报多年 |
| legacy / metadataComplete | boolean | 历史补录标记及摘要是否完整 |
| missingMetadataFields | string 数组 | 如 createdById、createdAt；供缺失说明，不能伪补 |
| projectionUpdatedAt | 带时区日期时间 | 目录投影刷新时点，与 updatedAt 分开 |

姓名用于显示，用户 ID 用于精确过滤。账号停用或改名不覆盖原签署身份快照。旧 `createdBy/updatedBy` 只是名称或标识文本，不能可靠拆出账号 ID；迁移能证实才补，否则保留原文本和缺失标记。

### 4.3 业务关联摘要

**目标 DTO：**列表返回 `businessRefs[]`，每项包含第 3 章关系中的 businessType、businessSubtype、businessId、businessNo、businessName、relationKind、provenance；数量较多时可只返回摘要并带 `businessRefCount`、`businessRefsTruncated=true`，详情关系接口返回全部。后端过滤始终基于完整关系，不基于摘要数组。

常用列可从摘要显示工单号、批次或 SN、产品编码和名称、工序编码和名称、设备编号、区域名称。**一对多字段使用数组或“首项 + N 项”展示，不设计单值 workOrderNo 去承载多工单关系。**单一生产来源的工单和对象可以额外提供便利字段，但不得取数组第一项冒充唯一关系。

每条结果另带 `matchedRelations[]`，说明本次筛选命中的业务对象及 DIRECT/DERIVED 路径，并返回 businessSubtype，便于直接显示“批次”或“SN”。没有关联筛选时为空。只有有权查看的业务对象才可出现在摘要和计数；实例读取授权并不自动授予所有关联对象读取权限。

### 4.4 操作摘要与列表列顺序

列表返回 `capabilities`，包含 view、continueFilling、change、obsolete、viewHistory、export。每项包含 `allowed`、稳定 `reasonCode`、显示 `reason`。这是当前查询时点的提示，点击动作仍须重取操作上下文，提交仍须服务端重新校验。

建议默认列顺序：表单实例号、模板名称、模板编码、模板版本、来源类型、关联业务、表单状态、变更或作废标记、创建人、创建时间、更新人、更新时间、操作。实例号固定左侧并支持复制、点击；额外列可配置。导出与接口可提供全部有权元数据，不强制所有字段同时挤在屏幕上。

### 4.5 冻结数据与当前数据的分界

模板结构、模板名称编码版本、字段定义及业务上下文采用创建或绑定时冻结值。来源适配器需明确各字段冻结时点；生产来源优先复用执行快照，而不是从当前主数据覆盖旧快照。

字段值、主状态、当前有效修订、可用动作和活动申请反映当前实例状态；原创建人时间不随之变化。若产品还需显示当前模板名称或当前设备名称，另外返回显式的 `current...` 字段，不复用历史快照字段。时间统一返回带偏移的 ISO 8601 字符串，页面按用户时区显示；旧无时区数据在确认原时区前不得直接补 Z。

## 5 统一查询契约

### 5.1 全局查询入口

**目标接口，未实现：**`GET /api/v1/form-instances`。选择独立路径承载统一语义，保留旧 `/form-instance-records` 的参数与响应供现有设计器兼容。

templateId 在新接口是可选筛选项。不传模板、不传来源，查询所有已接入且当前用户有权查看的实例。正常返回沿用 `ApiResponse<PageResult<...>>`，分页字段为 content、page、size、totalElements、totalPages。page 从 0 开始，size 默认 20、最大 200；新接口对非法值返回参数错误，不能静默解释成另一组条件。

| 查询参数 | 匹配语义 | 约束 |
| --- | --- | --- |
| instanceNo | 完整号精确匹配 | 去首尾空白；编号只按规定 ASCII 格式规范化 |
| instanceNoContains | 包含匹配 | 与 instanceNo 互斥，明确区别搜索和定位 |
| templateId / templateVersionId | ID 等值 | 同时传时验证版本属于模板 |
| templateCode / templateName | 编码等值、名称包含 | 均按冻结显示字段，不按当前模板名替换 |
| sourceType / sourceId | 类型及来源身份 | sourceId 必须带 sourceType |
| recordStatus | 主状态等值 | 支持重复参数，多个值为 OR |
| activeRequestType | CHANGE / OBSOLETE / NONE | NONE 专门筛无活动申请 |
| createdById / updatedById | 用户 ID 等值 | 不用姓名模糊匹配代替身份过滤 |
| createdFrom / createdTo | 创建时间区间 | 左闭右开，必须带时区；支持单边条件 |
| updatedFrom / updatedTo | 更新时间区间 | 与创建时间条件独立，不能都叫发生时间 |
| businessType / businessId | 一组业务对象等值 | 成对传入，通过受控关系检索 |
| relationScope | OWNED / ALL_RELATED | OWNED 为归属链，ALL_RELATED 加显式其他关联；默认 ALL_RELATED |
| relationTime | CURRENT / HISTORICAL | 默认 CURRENT；历史包括曾经有效的有权关系 |
| workOrderId / productionObjectId | 常用生产关系过滤 | 两者为 AND，并校验归属；不混用工单 orderNumber |
| productionObjectType | BATCH / SN | 可单独筛选关联的生产对象子类型；带 productionObjectId 时必须一致 |
| purpose | LIST / CHANGE / OBSOLETE | 默认 LIST；请求相应操作资格，不自动过滤不可操作行 |

| sort | 字段和方向 | 默认 createdAt,desc，追加 formInstanceId,desc 保证稳定 |

不同参数之间为 AND；同一多选参数的值为 OR。通用业务对象筛选与工单等便利筛选同时出现时仍为 AND。同一条关系的 type、subtype 与 id 必须配对匹配；多个不同对象条件可由同一实例的不同关系满足。productionObjectType 始终限定 PRODUCTION_OBJECT 关系，不能匹配另一份关联来掩盖 productionObjectId 的类型不一致。禁止生成“类型匹配一条关系、ID 匹配另一条关系”的误关联 SQL。

排序只接受 createdAt、updatedAt、instanceNo、templateCode 白名单；空时间排末尾，不能因数据库默认空值排序让未知创建时间成为最新记录。查询过滤、权限约束、去重计数、分页必须在服务端同一口径完成。

### 5.2 查询条件如何获取

模板选择器返回 templateId，版本选择器限定所选模板；用户选择器返回用户 ID；业务对象选择器按类型检索并返回稳定 ID。生产对象候选同时返回 businessType=PRODUCTION_OBJECT、businessSubtype、businessId 与业务号，显示“批次”或“SN”；工单输入应展示工单号、产品、状态帮助辨认，生产对象在工单已选时可限定范围。清空工单时同步检查并清除不再有效的子级筛选条件。

高级关系查询需要多个同类对象或多组类型时，目标另提供 `POST /api/v1/form-instances/search`，请求体使用 `relationFilters:[{businessType,businessSubtype,businessIds,relationScope}]`。各组 AND、组内 IDs 为 OR；同一 businessType 只能有一组。businessSubtype 可省略，只有 PRODUCTION_OBJECT 允许传 BATCH/SN，且必须与同组候选 IDs 的类型一致；其他类型传子类型报参数错误。该接口与 GET 共用过滤实现和响应 DTO，不再维护第二套列表口径。

业务号模糊搜索用于候选发现，精确业务 ID 用于最终过滤。不能让前端先下载全部实例再按工单过滤，不能逐条请求详情获取模板名，也不能用 keyword 搜索 JSON 文本冒充关系查询。

### 5.3 字段值和跨模板查询

统一 keyword 的目标范围应明确限定为实例号、冻结模板名称和编码、已授权关联业务号；不默认搜索全部字段值、附件正文或签名。后端文档应列出具体搜索列与转义规则。

字段值查询使用目标 search 请求的 `fieldFilters`，每项为 templateVersionId、fieldId、operator、value。支持的运算符按字段类型白名单校验；不同模板同名字段不能合并比较。跨模板分析只有显式配置公共语义映射后才开放。数值按数值比较，日期按时区区间比较，不用字符串 LIKE。

## 7 不同来源的填报流程

### 7.1 统一实例创建时点

已确认实例号在首次成功保存真实记录时分配。为兼容这个规则，目标新建流程先获得无正式实例号的 `draftHandle` 或来源已有副本标识；用户首次保存或允许的首次提交成功后，原子建立实例身份、编号、冻结摘要、来源定位、关系和审计。

预先创建的待填任务、未保存的 ADD_FORM_COPY 副本与实例目录分开。页面可显示“保存后生成”，不能用占位 FR 编号。失败重试使用同一来源草稿身份及幂等键；新建另一份才申请新身份。幂等键绑定用户、来源和请求内容，重复相同请求返回同一结果，键相同内容不同则报冲突。

### 7.2 各来源接入责任

| 来源 | 首次进入与冻结时点 | 保存和业务关联 |
| --- | --- | --- |
| 生产执行 | 从真实工单下批次或 SN 的冻结工序及绑定表单进入 | 沿用执行服务；登记生产对象、工单、产品、工序和有依据的 DHR 关系 |
| 设备点检 | 从点检任务或有权设备入口选择允许模板版本并冻结 | 点检域保存；登记任务和设备，关联生产对象须有显式依据 |
| 清场 | 从清场任务绑定区域、产线或设备及冻结模板 | 清场域保存；可明确关联前后工单或批次，不擅自只保留一个 |
| 独立发起 | 用户选择有权且可新建的已发布模板版本并冻结 | 通用填报域持有来源身份；没有工单也能保存，可显式增加允许的业务关联 |

后面三类属于目标能力。每个来源注册器必须提供创建上下文、保存事务、来源定位、权限与字段策略、冻结快照、关系快照、动作可用性和正式记录资格；不能只注册查询数据而缺少后续填报入口。

独立填报需要专用的创建与动作服务，不能创建虚假工单或生产对象来复用生产 API。所有来源遵循统一编号与目录协议，来源特定校验仍由所属模块决定。

### 7.3 从统一列表继续填报

1. 选中 formInstanceId，打开详情并请求 intent=FILL 的 operation-context。
2. 检查 allowed；若来源不可用、已完成、正在受控处理或无权限，显示对应原因。
3. 对生产来源，用 locator 读取最新执行视图；获取对应工序、副本、字段权限、签名要求和 execution revision。非生产来源调用对应适配器。
4. 使用同一实例冻结模板渲染，保留未保存内容；提交精确副本及来源并发值，服务端再次校验。
5. 成功后返回稳定实例号、最新内容和状态、并发值；刷新当前行或列表，保持已有查询条件和位置。

关闭有未保存内容的页面需提示；超时不能自动跳转新建，也不能盲目覆盖重试。读取当前状态后根据幂等结果判断是否已成功。生产整体 revision 可能因同一对象其他工序动作更新，因此列表缓存不能充当提交时的最新 revision。

### 7.4 多份与来源复用

同模板在同一工序填两份，或者两个工序各填一份，均为不同实例号。当前执行 `fulfilledBy` 别名代表由同一真实份满足另一配置引用，不能再次发号或重复统计。子表新增行不创建新主实例。

复制内容开始新记录时产生新份和新号，重新冻结合法模板与业务上下文；原签名、审批结果、创建人不能作为新记录的已签署证据复制。是否允许从作废或已完成记录复制由新建来源规则决定，不能由“有查看权限”推出。

### 7.5 提交与完成的两种分支

**已确认设计，DEC-0037-09：**表单流程绑定是可选的。未绑定表单流程时，提交校验通过即进入 COMPLETED，不创建表单流程实例或审批任务；同时应形成有效初始修订及提交审计。绑定表单流程时，提交后按该冻结流程推进，流程完成后才进入相同的 COMPLETED 终态，并形成有效初始修订和完成审计。当前编号实现尚无正式初始修订库，不能把已实现完成状态等同于已完成修订持久化。

此规则同样指导独立和非生产来源，不能因为接入统一实例管理就强制每份表单审批。目标上下文返回 formProcessVersionId 和 formProcessInstanceId（未绑定或尚未启动时可空）；完成摘要增加 completionMode=WITHOUT_FORM_PROCESS 或 WITH_FORM_PROCESS，未完成为 null。这里指原表单填报流程，正式变更仍另行选择 CHANGE 审批流程。

## 8 按业务条件定位并发起变更

### 8.1 伙伴可以直接实现的页面链路

**目标链路：查询条件 → 实例候选 → 唯一实例详情 → 变更上下文 → 差异编辑 → 申请确认 → 审批 → 新修订生效。**

候选页与全局实例列表共用摘要 DTO 和筛选组件。默认可展示查询命中的全部记录，不能变更的记录置为不可选择并说明原因；可切换“仅可变更”。批量框选只用于发现候选或查看，本文建议第一阶段一份申请只对应一份实例，批量变更不隐含在本接口中。

用户从 WO01 查到 B01、B02 相关的多份记录，应能用批次、模板、版本、工序、状态进一步收窄。选中时显示实例号、模板名与编码、冻结版本、创建信息、关联业务和当前有效修订，避免同模板多份误选。详情、申请页面返回候选列表时保留筛选和分页。

### 8.2 变更上下文和确认

1. 根据 formInstanceId 请求 intent=CHANGE 的上下文，由实例与记录控制后端联合检查权限、完成状态、来源有效修订、冲突申请及 P0 范围。
2. 固定 sourceRecordId、sourceRevisionId、templateVersionId 和 contentVersion。用户修改草稿时不自动改绑后来出现的新修订。
3. 在来源修订快照上编辑允许变更字段，输出差异与变更原因；不得编辑实例号、模板身份、原创建信息、原签名或业务归属来伪装“字段变更”。业务归属更正需独立的受控契约。
4. 查询有权、已发布且类型为 CHANGE 的审批流程候选；显式选择版本，完成真实签名。无候选不能确认。
5. 点击确认时后端原子校验来源修订、版本、权限、签名和业务锁，建立独立申请并启动审批；再次点击或超时重试返回同一申请。
6. 审批中列表主状态保持原值，显示变更审批标记。申请详情展示原修订、候选修订和差异；普通实例详情继续显示原有效内容。

### 8.3 审批结果与来源落地

既有决策要求批准后新修订成为唯一当前有效修订；旧修订及其完整内容、签名、哈希只读保存。退回或受限撤回不切换有效修订。候选修订的保存与审批不应提前修改 `form_instance_record.values_json` 或生产 state_json。

目标由记录控制业务事务处理结果：依据 eventId 和申请身份去重，再次校验源修订与锁；切换有效修订、更新来源可见投影、释放业务锁、记录审计并发布下游更新事件。公共流程只决定审批结果，不直接修改表单字段。

跨来源服务不在同库时使用持久化事件及幂等回写，保留重试状态。页面区分“审批通过，业务结果处理中”和“变更已生效”，不能在消息尚未落地时显示完成。重试不再新建修订、不再次累加产量或重复签名。

### 8.4 作废与后续影响

作废同样先查询关联实例，再取 intent=OBSOLETE 上下文，使用独立申请和 OBSOLETE 流程。作废申请不携带字段 changes。通过后标识失效并保留实例号、历史修订、签名、附件、关系、DHR 成员和审计。

来源记录若已进入放行或归档后关键控制，不能仅凭 COMPLETED 自动认定可变更。既有记录控制 P0 不覆盖记录本变更和放行后变更，资格服务必须识别此边界并返回原因。活动表单的作废资格仍是已登记待决项，见第 16 章。

## 9 状态 修订和动作资格

### 9.1 分开保存三个维度

**目标统一主状态建议：**ACTIVE 表示已保存且未完成，COMPLETED 表示已完成，VOIDED 表示已作废；来源更细的状态另存 sourceStatus。未接入或无法映射时展示 UNKNOWN 并关闭写动作，不能把未知状态默认为可填报。待审批、退回等细节由来源状态说明，不凭空改写现有状态机。

活动申请以 activeRequestType、activeRequestStatus 表示；内容修订以 revisionId、revisionNo、修订有效性表示。不能把“变更审批中”代替 COMPLETED，也不能把模板 V2.0 当作记录第二次变更。

| 记录情况 | 填报动作 | 记录控制行为 |
| --- | --- | --- |
| 未保存待填任务 | 来源允许时首次保存 | 尚无正式实例号，不在已编号实例候选中 |
| ACTIVE | 按来源节点与字段权限继续 | 正式变更不替代原填报；作废资格待既有问题确认 |
| COMPLETED 且无活动申请 | 普通 SAVE 不可绕过完成状态 | 具备有效修订、权限、范围资格时允许申请 |
| COMPLETED 且变更审批中 | 原有效内容只读 | 不允许冲突申请；候选内容在申请侧处理 |
| VOIDED | 历史只读 | 不通过重新保存恢复；恢复策略不在当前决策中 |
| 来源缺失或元数据无法定位 | 只读已保留证据 | 说明缺失原因，禁止猜测来源或修订后执行 |

### 9.2 内容修订和字段差异

初次完成形成有效初始修订属于已确认设计，但当前生产编号功能尚未实现正式修订库。后续需保存 revisionId、revisionNo、formInstanceId、templateVersionId、不可变字段值与附件引用、签名及哈希、形成事件、申请关联和有效性。

目标差异定位使用稳定 fieldId；子表使用 subTableFieldId、rowId、columnFieldId，并明确 ADD_ROW、REMOVE_ROW、SET 等操作。行排序变化与字段值变化分开。当前填报子表是对象数组且无统一稳定行身份，不能用数组下标实现正式变更追踪；历史行映射必须先完成并验证。

模板迁移和内容变更属于不同操作。普通变更保持原模板结构，不能为了显示新字段悄悄绑定最新模板；跨模板升级的字段映射、校验、签名和历史展示另行设计。

## 10 权限 失败与并发处理

### 10.1 统一目录的授权边界

**目标设计：**读取目录、读取内容、继续填报、变更发起、作废发起、历史与导出分别授权。全局列表应允许业务角色在有权范围使用，不能继续要求所有用户拥有模板设计权限和生产执行权限。权限码和来源数据范围需冻结；当前旧接口权限不在本次文档中直接放宽。

租户与组织数据范围由服务端认证上下文得到，不能接受请求中任意 tenantId 扩权。实例行、总数、候选条件、编号解析、关系、字段值、附件、导出均使用同源权限过滤；缓存键包含用户权限范围和条件。

角色有变更发起权不代表有权读取所有实例；可查看实例也不代表可查看其关联工单的全部详情。来源域提供业务范围策略，目录统一组合和过滤。签名服务验证真实操作者、用途、时效、内容绑定，只有 signatureId 字符串不构成签名验证。

### 10.2 目标错误模型

| 情况 | 目标 HTTP 与业务码示例 | 页面处理 |
| --- | --- | --- |
| 筛选格式或关联矛盾 | 400 INVALID_FILTER | 标明具体条件，不自动清空并查全部 |
| 未登录 | 401 UNAUTHENTICATED | 保留页面条件，进入平台认证流程 |
| 无功能权限 | 403 FORBIDDEN | 明确无操作权限 |
| 实例不存在或无对象读取权 | 404 RECORD_NOT_FOUND | 不泄露其他范围内记录是否存在 |
| 内容或来源版本已变化 | 409 VERSION_CONFLICT | 保留草稿、重新加载并比较，不静默覆盖 |
| 已有冲突申请或重复键内容不同 | 409 ACTIVE_REQUEST / IDEMPOTENCY_CONFLICT | 显示有权申请入口或冲突原因 |
| 缺有效修订或字段校验失败 | 422 REVISION_REQUIRED / VALIDATION_FAILED | 指明原因；不使用假修订继续 |
| 来源服务暂不可用 | 503 SOURCE_UNAVAILABLE | 保留只读摘要和草稿，提供重试 |

以上错误码是目标建议。当前项目很多业务错误仍返回 400，第 13 章按现状描述；不能用目标码编写声称当前 API 已通过的断言。网络失败不能渲染为“暂无数据”。错误保留 traceId，日志不得包含密码、token 或不必要的字段敏感值。

### 10.3 读写一致性

目录可使用投影提高检索速度，但提交动作必须回到权威来源和修订服务，不能依赖缓存中的 allowed。首次保存成功响应应返回新实例身份；如果跨服务目录尚未完成登记，不能假装全局列表已立即可见，需提供投影状态并确保最终补齐。

同库优先将来源保存、发号登记、关联、审计置于同一事务。跨库使用来源业务事务中的持久化事件、消费去重、失败重试和对账；来源幂等键、实例唯一键、事件唯一键和申请唯一约束共同防止重复。

目标业务时间区间采用左闭右开。例如本地 9 月 15 日查询为带时区的当日 00:00 至次日 00:00，不用 23:59:59 排除毫秒。普通分页允许数据更新后总数变化；导出必须固定结果快照或截止时点，不能以连续翻页凑出重复或漏行的报表。

## 11 存储投影与来源接入规范

### 11.1 逻辑职责划分

以下为目标逻辑对象，不限定必须创建同名物理表：

| 对象 | 保存职责 | 维护方 |
| --- | --- | --- |
| 实例身份与摘要 | 统一 ID、编号、模板摘要、人员、时间、来源定位和当前状态 | 实例域 |
| 实例业务关系 | 多业务对象关联、关系种类、有效时段和来源证据 | 业务来源授权写入，实例域索引 |
| 来源工作内容 | 未完成阶段字段值、来源流程和并发状态 | 各填报来源域 |
| 内容修订 | 不可变内容、签名、哈希、有效修订指针 | 记录与修订域，来源服务协作 |
| 申请与审批 | 原因、差异、申请状态、流程引用、业务锁 | 记录控制域及公共流程域各司其职 |
| 查询投影 | 可重建的摘要和检索索引 | 实例域，不成为第二个可随意编辑的业务源 |

源定位唯一键必须包含租户、来源类型、来源根 ID 和来源内具体份定位，不能只按 templateId 或 formId 唯一。生产来源兼容现有 tenant_id、object_id、operation_id、copy_id 唯一键；新来源不要套用 production_object 外键。

### 11.2 冗余字段如何维护

列表摘要按首次绑定或保存的权威快照物化，省去前端逐行补查。后续业务保存只更新可变值、状态与更新信息，不覆盖创建元数据。模板名称和编码从生产冻结 form 的 name/code/version 或其他来源等价快照取得；工单和产品等优先从来源冻结上下文取得。

单个字段丢失时，只能从可证实的同版本历史证据补齐；从当前主数据取得的信息需标明 current-reference，不能伪称原始快照。关系和投影重建只重建派生数据，不发新号、不改实例创建时间、不改历史签名。

查询使用授权实例作为基表，业务关联通过 EXISTS 或去重子查询过滤，避免连接多值字段放大分页。列表禁止每行解析完整模板和附件。实例号唯一索引、模板版本与创建时间索引、类型化关系反查索引按实际数据库设计验证；包含搜索与字段过滤按数据量专门评估，不能承诺任意 JSON LIKE 都快速。

### 11.3 新来源接入清单

1. 注册来源类型、中文名称、业务所有者、稳定来源根与份定位键；明确支持只读、填报、变更和作废中的哪些能力。
2. 提供模板冻结与来源上下文生成，定义创建人、创建时间及业务关系来源；无适用值明确返回 null。
3. 首次保存与重复保存均返回同一实例身份，建立可重放的登记机制；不允许来源模块自行生成 FR 编号。
4. 实现读写授权、字段与签名校验、并发和幂等；把操作结果投影到统一目录。
5. 完成初始修订、变更资格及结果回写适配后，才开放正式变更；只接入列表的来源 change.allowed=false 并说明原因。
6. 提供正常、重复、失败、权限、关联去重、历史和修订场景夹具，通过第 15 章验收。

### 11.4 历史数据与兼容迁移

保留旧实例号和旧索引 ID；新增逻辑身份的映射唯一可追溯，不重编历史编号。扫描已保存记录，跳过未保存副本与 fulfilledBy 别名；将可信快照与业务关系回填到新投影。旧 createdBy 无法匹配账号 ID 时保留文本，createdAt 未知时保持 null。

原始执行 JSON、冻结模板、审计和签名不可被补齐脚本重写。回填需具备幂等键、分批断点、失败清单及可对账计数；校验每来源、每模板、每业务对象的实例数量与关系去重。回滚只撤销本次派生投影，不删除既有实际记录和新近业务写入。

正式修订回填必须基于可信完成证据。无法证明旧记录何时完成、内容和签名对应哪次修订时，标识 LEGACY_REVISION_UNVERIFIED，保留只读并阻断正式变更，不能机械给每条记录补 revisionNo=1 当作已验证历史。

## 12 下游引用 导出和跨模块影响

### 12.1 两类引用不能混用

“查看这份记录当前内容”保存 formInstanceId；人工沟通附 instanceNo。“证明某次审批或放行依据的内容”必须保存 formInstanceId 和 revisionId，并记录模板快照版本、签名或哈希等证据引用。实例号本身无法唯一确定历史内容。

变更批准后，普通列表显示新有效修订。既有签署证据不得因“跟随最新”自动被替换；DHR 当前投影、产量汇总、质量判断等由各自业务域评估并消费明确版本的结果。作废不物理删除 DHR 成员和历史投影，按既有受控规则显示失效与影响。

### 12.2 导出与打印目标

元数据导出复用全局查询条件和权限，区分“选中实例”与“全部筛选结果”；默认导出元数据，字段值和附件另行授权。跨模板字段结构不同，不将同名字段强行拼为一列；选择同一模板版本或批准的公共字段映射后才导出业务字段。

大批量导出采用任务：目标请求保存规范化过滤条件、选中 IDs、导出列和结果快照时点，返回任务 ID；下载重新鉴权并限时有效。打印单份记录标注实例号、模板名称编码版本、内容修订和状态，历史或作废内容有明确标识。

### 12.3 影响与边界

直接影响为统一列表、业务关联查询、实例上下文、来源登记和变更候选；传递影响为 DHR、附件签名、报表、产量投影、权限和审计。新增来源的复杂业务校验仍归来源模块，统一目录不接管所有工作流。

本方案建议使用产品内核统一身份和查询契约，使用事务编排处理来源保存与受控变更。扩展来源通过注册适配，不在每个前端页面堆设备或生产的条件分支。本次交付不修改运行代码、数据库、现有权限或线上流程；实际实施需按这些影响分别验证。

## 13 当前实际实现与差距

### 13.1 当前可调用接口

本章为原始源码核对结果，基于提交 `e5772f81184e708a6b023f5112700be6820cb1be` 及本次文档改动。当前实际只支持生产执行已保存表单的编号与索引，查询固定使用 default 租户。新统一接口路径尚不存在。

`GET /api/v1/form-instance-records`：templateId 必填；instanceNo 为包含匹配；keyword 对 values_json 文本包含匹配；operator 对创建或更新人文本包含匹配；occurredAt 为 YYYY-MM-DD，筛更新时间当天。page 默认 0，负数归 0；size 默认 20，限制 1 至 200。排序 numbered_at DESC、id DESC。

`GET /api/v1/form-instance-records/{id}?templateId=...`：id 是索引主键；无记录或不属于模板当前返回业务错误 400。两接口都要求 `master-data.form-templates` 与 `production.execution`，不能用记录控制发起权限自动替代。

当前列表返回 id、instanceNo、status、templateId、versionId、createdBy、createdAt、updatedBy、updatedAt、legacy、fieldValues；详情额外返回 snapshot。snapshot 中有 name、code、version、model、canvas、fields。model 与 canvas 是 JSON 字符串。**列表没有模板名称编码版本显示值，也没有工单、批次、设备关系和操作定位。**

### 13.2 当前生产执行入口

实际接口为 `GET /api/v1/production/execution/scan?barcode=...`、`GET /api/v1/production/execution/{objectId}`、`POST /api/v1/production/execution/{objectId}/actions`。scan 按生产批次或 SN 查找，不能扫描 FR 实例号直接填报。

读取 snapshot.operations 中的工序和表单，读取 availability 对应份的允许动作、字段权限和签名要求。当前 SAVE 示例：

```json
{
  "action": "SAVE",
  "revision": 3,
  "operationId": "a",
  "formId": "form-51",
  "instanceId": "form-51:copy:2",
  "values": {"temperature": 22}
}
```

生产请求 instanceId 是执行副本键，不是目标 formInstanceId。values 必须是对象，审批或退回等不改字段动作也传空对象。顶层字段按键合并，未传保留旧值，null 仅在字段权限和校验允许时清空；子表字段按整个数组替换，不能当作稳定行 ID 的补丁接口。

成功后从 data.state.operations 对应工序和副本中读取 instanceNo，从顶层 data.revision 读取下一次执行并发版本。当前前端 ExecutionFormState 类型尚未声明可选 instanceNo，后续需同步类型。执行保存不是正式记录控制申请接口。

### 13.3 当前发号与历史补号

当前编号格式 FR-YYYYMMDD-序列号，序列最少六位且不按日归零，日期为服务端分配日期，事务回滚允许跳号。START、ATTACH_FORM、ADD_FORM_COPY 本身不发已保存记录编号；首次成功 SAVE 或允许的首次 SUBMIT 才建立记录。普通保存、提交、审批、退回保持原号。

0082 历史补号保留执行原 JSON，跳过未保存副本与 fulfilledBy 别名；legacy=true，未知创建人时间为空，updated_at 来自 savedAt，新增 BASELINE 审计。编号日期不等于原填报日期。数据库列保存 object_id、operation_id、form_id、copy_id，但当前接口不返回它们。

### 13.4 公共流程和变更现状

已有 `GET /api/v1/workflow/record-control/candidates?businessType=CHANGE` 或 OBSOLETE 查询已发布候选；内部 Java `RecordControlWorkflowPort.start` 定义并实现了显式流程版本启动阶段。它不是前端可直接调用的正式申请确认接口。

候选、流程端口及 WorkflowResultEvent 类型存在，不表示申请保存、签名验证、业务锁、初始修订、结果投递和来源回写已闭环。当前没有统一编号来源解析、正式变更申请与全修订查询接口。结果 businessId 关联申请身份，不能传 FR 编号。

### 13.5 按场景判断完成度

| 能力 | 当前覆盖 | 必须补齐 |
| --- | --- | --- |
| 模板下生产记录列表 | 部分覆盖 | 列表模板摘要、规范人员 ID 和时间口径 |
| 全局所有来源目录 | 未覆盖 | 可选模板、来源注册、统一身份和授权分页 |

| 负责模块 | 必交付能力 | 对外依赖 |
| --- | --- | --- |
| 实例后端 | 全局目录、元数据、关系查询、精确号解析、统一详情、来源路由 | 来源快照与策略；修订和申请摘要 |
| 各填报来源 | 创建与冻结、保存、来源权限、并发、实例登记、业务关系及回写 | 统一发号与登记协议 |
| 统一列表前端 | 查询、列配置、筛选候选、详情、动作跳转、导出 | 一个稳定摘要 DTO 和 operation-context |
| 记录控制业务 | 来源资格、初始与候选修订、差异、申请、业务锁、确认事务及落地 | 实例身份、来源适配、签名、公共流程 |
| 公共流程 | 已发布候选、冻结流程、任务和签名动作约束、幂等结果契约 | 独立申请身份与受控业务详情投影 |
| 下游与联合测试 | DHR 与报表引用口径、关系和修订验证、跨角色联调 | 事件版本、来源关系及实际环境 |

建议交付切片：

1. 冻结统一身份、列表 DTO、来源和关系目录、人员时间口径、查询语义及权限。用至少生产、点检、清场、独立四种夹具共同审阅，不用只有一个模板的样例验收。
2. 实现生产数据到统一目录的兼容迁移，同时实现全局查询、业务反查、详情和操作上下文。列表伙伴可据冻结契约开发，但 Mock 与真实联调结论分开。
3. 完成非生产与独立来源的登记及填报适配，同一实例在其来源列表、全局列表、关联对象下身份一致。所有来源纳入验收后，才称全来源统一管理完成。
4. 完成初始修订和稳定子表行身份，接通变更与作废的资格、申请确认、流程、结果回写及历史查看。
5. 完成导出、下游影响、迁移对账、性能和真实多角色验收。

每个切片须公布实际可调用路径、字段、错误码、能力范围及测试证据。接口尚未完成时返回明确不可用，不以空数组表示“已接通但暂无记录”。

## 15 联合验收清单

以下为目标验收，不是已经通过的测试记录。建议准备两个模板及各两个版本、两个工单、同工单两个生产对象、至少一份点检跨对象关联、一份清场多关系、一份独立表单、活动和完成及作废记录、历史缺失记录、两个权限不同账号。

### 15.1 全局列表和关系查询

- 不传 templateId 能看到所有授权来源；无生产权限但有点检读取权限者只能看到其有权点检记录。
- 一次列表请求即有模板名称编码显示版本、创建人时间、来源状态；浏览器不存在逐行请求详情或模板补列。
- 同模板两版本准确显示冻结信息，后续改模板名不改变旧记录展示。
- 工单查出下属对象实例；批次查询不带出同工单另一批次；SN 与批次之间无关系证据时不自动推导。
- 点检同时关联工单和批次仍只出现一条；totalElements 按实例去重；ALL_RELATED 与 OWNED 的差异可解释。
- 不同业务类型使用相同字符串 ID 不串号；多个关系条件按同条类型与 ID 配对，工单和对象矛盾被拒绝。
- 批次和 SN 使用 PRODUCTION_OBJECT 及明确 businessSubtype，列表、匹配关系和候选均返回子类型；类型筛选不依赖号码推测，类型与 ID 矛盾被拒绝。
- 关系摘要被截断时过滤仍命中完整关系；不可见关联对象不泄露名称、计数和路径。
- 完整实例号精确解析；模糊搜索不会自动打开第一条；缺记录或越权处理一致。
- 创建和更新时间、姓名与用户 ID、未知值、时区边界、多条件 AND 和多选 OR 与契约一致。
- 查询异常不显示空结果；排序稳定、分页去重，列表全状态范围与“仅可变更”过滤一致。

### 15.2 首次填报与继续填写

- 四类来源首次保存均获得统一号；相同请求重试同号，创建另一份新号。
- 未保存任务不进已编号列表，填报成功后目录能按约定可见；跨服务延迟有状态与补偿证据。
- 保存失败不产生可见半成品，审计失败符合事务边界；允许序列跳号，不允许重复号。
- 同模板不同工序及不同份不混淆；fulfilledBy 同份引用不重复发号，子表行不新增主实例号。
- 从统一列表继续填报定位原份；非生产来源不调用生产 API；已完成记录不能借 SAVE 绕过正式变更。
- 无表单流程的提交校验通过即完成且无审批任务；有表单流程在流程完成后才进入同一终态；均形成初始修订与审计，completionMode 能区分完成方式。
- 权限或并发版本在打开后变化时，提交被重新校验，用户草稿仍保留。

### 15.3 变更 作废与追溯

- 从工单到批次到实例再到申请完整链路，来源记录和修订由后端解析而非客户端猜测。
- 查询后另一人发起申请，当前用户确认时被锁冲突阻止；重复确认不会生成第二份申请或第二个流程。
- 缺有效初始修订、放行后范围、无候选流程、签名无效均给出具体原因。
- 申请期间原有效值、模板版本、创建信息不变；字段差异来自源修订，子表增删改和重排通过稳定行 ID 解释。
- 退回或受限撤回不切换有效修订；并行审批全部完成才汇合，任一退回按既有规则使本轮其他待办失效。
- 批准结果重复、乱序或超时重放只落地一次，保留旧修订、签名和哈希。
- 作废后编号和历史保留、无有效修订、普通详情明确历史状态；不删除 DHR 证据。
- 变更生效后目录显示新修订；固定历史引用仍显示原修订；下游重复消费不重复累计或重复冲销。

### 15.4 迁移 性能与交付证据

- 旧接口仍按原参数响应，旧 id 与统一身份映射可证明；历史补齐不重编实例号、不伪造创建信息。
- 按来源和关联对象比对去重计数、抽查冻结元数据、缺失清单及原 JSON 哈希；迁移重复执行保持幂等。
- 使用约定的数据规模和并发量验证列表、关联反查、精确号和导出；性能阈值由团队冻结并写入报告，不用少量夹具宣称大规模性能通过。
- 真实目标环境记录提交号、JAR 与前端构建、迁移、测试账号权限及 API 证据；源码检查、Mock、隔离测试与线上验收分列。

## 16 待冻结事项与明确建议

所有来源统一管理、全局列表元数据、按工单批次关联查询已确认。以下为进一步开发前需要分清责任的事项，不阻止本文作为完整场景设计交付：

| 事项 | 建议及依据 | 冻结责任 |
| --- | --- | --- |
| 正式修订是否沿实例号 | 建议同逻辑记录沿号，以 revisionId 区分历史 | 产品与实例及记录控制共同确认 |
| 统一 ID 与旧索引映射 | 建议复用并迁移稳定旧 ID 或建立唯一映射，禁止各端猜测 | 实例后端主导技术冻结 |
| 全局权限码和数据范围 | 读目录不绑定模板设计权限；与各来源数据范围组合 | 权限与各来源负责人 |
| 关系时态与派生路径 | 冻结直接归属、全部关联、历史关系的具体类型和有效时点 | 各业务来源与实例后端 |
| 初始修订及历史行身份 | 根据可信完成证据建修订，子表分配稳定行 ID | 填报与记录控制后端 |
| 活动表单作废 | 沿用已登记问题，不能把某一种建议当成已确认规则 | 产品确认 |
| 管理员重新分配签名 | 专门权限、原因与审计已确认，是否额外签名仍待定 | 产品与公共流程负责人 |
| 一申请对应几份实例 | 建议首阶段一份申请一份实例；批量申请另定原子性与审批语义 | 产品与记录控制负责人 |
| 具体新接口和数据量指标 | 本文目标路径、字段、分页与错误码联合冻结后发布契约 | 各端负责人和联合测试 |

需要产品决策的是业务语义；DTO 命名、旧字段别名、索引设计和 API 分工由技术伙伴共同完成，不把所有技术细节都推回产品。待冻结项应有决策记录，确认后更新对应章节与验收，不仅口头通知某个伙伴。
