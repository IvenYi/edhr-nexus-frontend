## 修复：Excel 单锚点图片尺寸丢失

`W2-IMPORT-EXCEL-IMAGE-EXTENT-001`，medium，已在本候选修复。入口是“表单建模→某版本设计器→模板导入”，文件由 `templateImport` 分流至 `importExcel`，最后替换当前 CanvasPage。

Excel有两种相关定位表示：双锚点以左上和右下坐标给出范围；单锚点以左上坐标加明确宽高给出范围。当前锁定 ExcelJS 4.4.0 读取后，前者在 `range.br`，后者在 `range.ext`；其 `ExtXform` 已将 EMU 除以9525转换为像素。原 `buildModernExcelImages` 只读前者，无 br 时计算出零，再套用原24像素最小值，180×72或49×101图片均被转换为24×24。

主侧用实际 ExcelJS Workbook 写出含图片的 XLSX，再重新读取来源锚点并调用真实适配器：来源 `ext={width:180,height:72}`，导入结果 `{left:125,top:72,width:24,height:24}`。原始文件及 JSON 在 main 原件包。不是根据截图猜测尺寸，也不是 mock 解析器结果。

产品只改 `importExcel.ts` 的5增/4减：补充 ext 类型并优先使用现成的像素宽高；缺失时仍走原双锚点差值。原最小24、坐标、媒体归属/内容、单表选择、列宽、字段/工作流、失败回退及保存/历史机制保持。没有新增UI控件、格式政策、权限、后端、数据库、知识定义或迁移；不自动修补已有模板和冻结历史。源图片不足24时仍遵循原行为，不把这个工程最小值升级为新业务规则。

同最终维护脚本对精确旧基线的真实适配器：Node10中4正对照通过/6尺寸失败；1440与390每宽4项中1双锚点正对照通过/3尺寸失败，无 pageerror。当前新10 Node和两宽8浏览器全过。旧结果只覆盖这些新脚本，不声称重跑旧全部回归。

## 性能取证：Word同表重复解析

`PERF-W2-WORD-TABLE-REPARSE-001`，父项 `PERF-DESIGNER-OFFICE-EXPANSION-001`，未修改产品，后续顺序已向用户询问。`parseBlocks` 先解析表格；`collectImageItems` 为同表每处图片再次 `parseTable`，末尾还为表格高度调用一次。表格内容已在本次导入上下文中存在，却未复用。

隔离 Chromium 使用实际 JSZip/Word转换，唯一本体外观察是在原 `parseTable` 入口加计数，不替换结果。合成XML包有一张两列表格，图片都指向同一份原图片内容，每组3次，保留全部600单元格和所有图片的输出断言：

| 表格行/图片处数 | 表格解析次数 | 转换耗时，三次中位数 |
| --- | --- | --- |
| 30/0 | 2 | 15.6ms |
| 300/0 | 2 | 58.5ms |
| 300/1 | 3 | 75.6ms |
| 300/10 | 12 | 322.5ms |
| 300/50 | 52 | 1212.3ms |

300/50包压缩约3.1KiB、正文XML约43.8KiB；三次约1139.6/1212.3/1258ms。瓶颈不只由文件字节数决定。该数字是合成输入的局部转换观测，不是正式Office兼容认证、整页用户延迟、峰值内存或生产SLA；300是表格行，不是DHR表单数，50是图片处数，不是数量上限。

建议后续在一次导入内复用已解析表格，保留文字/边框/合并、图片位置计算和原撤销应用边界；先做输出等价与容量对照再优化。此次只问后续顺序，不把用户尚未回答当授权，也不混进当前 Excel 修复。整ZIP并发解压、无关条目/全部工作表加载和媒体编码开销仍属原风险，未因图片尺寸正确而关闭。

## 大模块的具体提取建议

本批Excel适配器1,018行、Word965行；行数用于定位，不单独定性为缺陷，也没有实施大重构。

- Excel：图片的 `ModernExcelImage` / `buildModernExcelImages` / 坐标与编码可归纯 `excelImageAdapter`，输入worksheet/workbook及已算好的行高列宽，输出 `{medias,images}`；不重复获取工作簿或改渲染器。文本/富文本和单元格style/border转换归 `excelCellAdapter`。双锚点、媒体摘要和两屏测试先固定再逐步提取。
- Excel布局启发式（空白拆分、长文本扩展、合并边框）与文件读取分离为纯 `excelGridLayout`，输入cells/ranges/widths，输出原Grid；不在整理时改变启发式或clamp。真实复杂格式未测完前，保留原入口编排。
- Word：ZIP按需读取、结构XML与ParsedBlock解析、图文布局组装三层边界。优先建立本次调用内的已解析表格数据复用入口，明确XML节点归属与布局输入，不把缓存放入全局store；段落高度/图位等价需专门固定，不能以优化为由悄悄纠正其他布局。
- Shell仍拥有会话、提示和最终应用；适配器只产出CanvasPage，禁止在提取时另建保存/撤销通道。当前没有足够理由先造全局导入服务或大通用错误层。
