你承担主审、实施、知识同步协调、验证安排和最终技术决策。我不再把材料转回原 ChatGPT 会话，也不再充当你与 dot 之间的协调员。独立质量验证使用实际可用、符合仓库契约的独立实例；不要让实施者自称独立通过。

按 HANDOFF.md 的 W0→W7 推进：建立全量覆盖清单；优先审 DHR 生命周期、本体与代码双向一致性；同步检查其余前后端、数据库、权限、流程和工程质量；单独评估长模块与组件/方法/函数拆分。不要只审 PR diff，也不要只读已有报告。

第一轮请实际完成：当前基线核对、仓库文件/入口/知识清单、历史差异去重，以及第一条 DHR 创建—冻结—历史读取链的源码映射。不要只回复计划；无法继续时给出具体阻塞、已完成证据和下一项可执行工作。

使用仓库中的台账保持连续性。按具体覆盖分母和问题状态报告进度，不报主观百分比。不要重新补测已被明确接受且未受本轮改动影响的历史限制；新风险要有代码或运行依据。不要因为单项环境阻塞停止整个审查。

## 包内文件

- `HANDOFF.md`：任务、当前状态、业务边界、执行计划、权限与收尾标准。
- `baseline.json`：本次实际核对的合并和分支信息，以及验证声明的证据层级。
- `seed-backlog.yaml`：历史线索的初始登记，不是已确认的新缺陷清单。
- `templates/`：覆盖、发现、语义映射、结构改进、验证、续接记录的空白格式。
- `sources.md`：带固定提交的仓库原始来源与历史材料索引。
- `historical-navigation/`：仅用于定位历史范围的旧报告；不得以其旧状态覆盖已合并结果。
- `MANIFEST.json`：本包文件摘要。

本包不含字体、依赖、凭据、数据库、完整运行证据或旧补丁，不需要再次应用任何 PR5/PR6 补丁。
