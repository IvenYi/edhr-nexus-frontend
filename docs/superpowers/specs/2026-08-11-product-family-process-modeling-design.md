# 产品簇制程建模设计

## 目标

在 eDHR 中新增可用于产品制程兜底的产品簇建模能力。产品簇中的成员只来自物料管理中类型为“半成品”或“产成品”的物料；产品簇可以配置与产品管理完全相同的制程版本、工艺路线节点、DHR 表单和文档引用。生产工单/批次创建时，产品自身没有可用制程版本才允许使用所属产品簇的可用版本。

本功能遵循现有产品管理、工艺路线和其他建模页面的统一规范，不新增独立的“产品簇制程”交互体系。

## 已确认业务规则

1. 一个产品只能属于一个产品簇。
2. 产品簇成员只能是物料管理中类型为“半成品”或“产成品”的物料；产品管理是这些物料的派生视图，不能在产品簇页面新建产品。
3. 一个产品簇可以拥有多个并行制程版本；制程版本的版本号在同一产品簇内不能重复。
4. 产品制程版本和产品簇制程版本使用同一套版本字段、工序配置、表单/文档绑定、编辑器、状态计算和审计结构。
5. 产品有至少一个当前可用制程版本时，生产选择只展示产品制程版本，不展示产品簇兜底版本。
6. 产品没有可用制程版本时，才展示所属产品簇当前可用制程版本，并提示“当前产品未配置可用制程，以下为产品簇兜底制程”。产品自身只有失效历史版本时，不展示这些失效版本，也不因历史版本存在而阻断产品簇兜底。
7. 产品和所属产品簇都没有可用制程版本时，生产工单/批次创建必须阻断并给出明确提示。
8. 产品簇转移只影响后续生产对象；已经创建的工单/批次保存产品、产品簇、所选制程版本和配置快照，后续转移不得改变历史生产对象。
9. 将产品转移到另一个产品簇只需要二次确认，不要求填写转移原因。转移必须在一个事务中完成旧簇移除和新簇加入。
10. 从产品簇移除产品使用普通二次确认；成员弹窗固定展示一次提示：“移除后，若该产品自身没有可用制程版本，将无法使用产品簇兜底制程。”

## 方案选择：统一制程归属模型

采用方案 A：扩展现有 `product_process`，让它同时承载产品和产品簇的制程根。

### 归属字段

在 `product_process` 增加：

- `owner_type`：`PRODUCT` 或 `PRODUCT_FAMILY`。
- `owner_id`：`PRODUCT` 时为物料 ID，`PRODUCT_FAMILY` 时为产品簇 ID。

已有 `product_version_id` 保留为兼容字段。迁移时将已有记录回填为 `owner_type = PRODUCT`、`owner_id = product_version_id`，现有产品接口和历史数据不被破坏。新代码统一使用 `owner_type + owner_id` 查询和写入；兼容字段仅用于历史数据迁移和旧调用兼容。

增加唯一约束：`(tenant_id, owner_type, owner_id)`。一个归属对象只有一个制程根，制程根下通过现有 `product_process_version` 保存多个版本。

现有以下表保持复用，不复制产品簇版本表：

- `product_process_version`
- `product_process_operation_binding`
- `product_process_operation_form_binding`
- `product_process_operation_document_binding`

制程版本的唯一版本号约束调整为既有的 `(product_process_id, lower(version_label))`，因此产品和产品簇天然分别校验版本号重复。

### 成员关系

新增 `product_family_member`：

- `id`
- `tenant_id`
- `product_family_id`
- `product_id`，外键引用 `material.id`
- `created_by`、`created_at`、`updated_by`、`updated_at`

增加：

- `(tenant_id, product_family_id, product_id)` 唯一约束，防止同一簇重复成员。
- `(tenant_id, product_id)` 唯一约束，保证一个产品只能属于一个产品簇。
- `product_id` 只接受半成品或产成品物料；服务层必须按物料类型校验，数据库通过外键和唯一索引保护关系完整性，不能依赖前端筛选作为唯一保护。

## 后端接口设计

接口沿用 `/api/v1/master-data/process-modeling`，新增产品簇专用资源接口，但制程版本接口使用归属类型参数调用统一服务。

### 产品簇列表与详情

- `GET /product-families`
  - 继续支持 `keyword`、`status`、分页和排序。
  - 返回父行的成员数和制程版本数；不把成员或版本数组塞入列表分页数据。
- `GET /product-families/{id}`
  - 返回产品簇基本信息、成员数、版本数。
- `GET /product-families/{id}/audit`
  - 返回产品簇自身、成员变化和制程版本变化的审计记录，供详情页“数据审计”页签使用。

### 成员维护

- `GET /product-families/{id}/members`
  - 返回当前成员、可选产品和已归属其他产品簇的产品状态。
  - 只返回半成品/产成品物料。
- `POST /product-families/{id}/members/batch-add`
  - 请求体为产品 ID 列表。
  - 未归属产品批量加入当前簇；已属于其他簇的产品不能通过普通批量添加绕过转移流程。
- `POST /product-families/{id}/members/{productId}/transfer`
  - 在事务中删除旧簇关系并创建新簇关系。
  - 返回旧产品簇和新产品簇信息，供二次确认后的结果刷新。
- `DELETE /product-families/{id}/members/{productId}`
  - 删除成员关系；产品本身和制程配置不删除。

所有成员变更都要写审计：

- 产品对象：记录所属产品簇前后值。
- 旧产品簇：记录移除成员。
- 新产品簇：记录新增成员或转入成员。

### 统一制程版本接口

将现有仅面向产品的内部服务抽取为 owner-aware 服务，接口形式为：

- `GET /process-owners/{ownerType}/{ownerId}/workspace`
- `POST /process-owners/{ownerType}/{ownerId}/versions`
- `PUT /process-owners/{ownerType}/{ownerId}/versions/{versionId}`
- `DELETE /process-owners/{ownerType}/{ownerId}/versions/{versionId}`
- `GET /process-owners/{ownerType}/{ownerId}/versions/{versionId}/audit`

原有产品接口保留为兼容入口，内部转发到统一服务。产品簇页面使用统一入口，产品管理页面逐步切换到同一服务。统一服务必须校验 owner 存在、租户一致、版本归属一致和引用对象可引用；不能通过修改 URL 中的 owner ID 操作别的归属对象的版本。

### 生产侧查询契约

本仓库当前尚未有工单/批次创建模块，因此本功能先提供可被生产模块调用的查询服务：

`resolveAvailableProcessVersions(productId, atTime)` 的结果包含：

- `source`: `PRODUCT` 或 `PRODUCT_FAMILY`
- `fallback`: 布尔值
- `message`: 兜底提示或空值
- `versions`: 当前可用制程版本列表

可用状态严格复用 `RdoVersionStatusResolver`：生效时间晚于查询时刻，或失效时间小于等于查询时刻的版本均不可用；其余版本为可用。选择规则严格按“产品优先、无可用产品版本才兜底、两者均无则阻断”执行。真正创建工单/批次时由生产模块保存快照；产品簇页面不自行创建生产对象。

## 前端交互设计

### 产品簇列表及制程版本展开

新页面替换当前通用的“产品家族管理”页面，使用产品管理页面已有的父子表格布局和操作栏规范：

- 父列：产品簇名称、产品簇编码、成员数、制程版本数、更新人、更新时间、操作。
- 产品簇名称使用蓝色链接，点击打开详情抽屉；不在操作栏增加“查看父产品”图标。
- 父行可展开；无版本时展示空状态和“新增制程版本”入口。
- 父行操作栏按统一图标顺序展示“产品成员”“新增制程版本”“编辑”“删除”。
- 子版本行展示版本信息、路线版本、DHR 模板版本、版本状态、生效/失效时间、更新信息和操作。
- 子版本操作只保留与产品管理一致的查看、编辑、复制、删除等功能；数据审计作为详情页签，不增加审计图标。
- 列设置、固定操作栏、空白页、加载页、错误页和确认弹窗沿用产品管理/工艺路线的统一建模页面规范。

### 产品簇详情抽屉

详情抽屉包含：

1. `数据信息`：编码、名称、状态、描述、备注、成员数、制程版本数、创建/更新信息。
2. `数据审计`：产品簇自身编辑、成员新增/移除/转移、制程版本新增/编辑/删除及版本内工序/表单/文档配置变更。

版本详情的审计记录仍由版本详情页签查看，不增加独立操作栏按钮。

### 产品成员弹窗

- 左侧：可搜索产品列表；仅显示半成品和产成品。
- 右侧：当前产品簇成员。
- 当前成员显示选中状态。
- 已属于其他产品簇的产品置灰，显示原产品簇名称，并提供“转移到当前产品簇”动作。
- 未归属产品支持批量选择和一次性添加。
- 底部固定“取消”“保存/添加”操作；取消不改变已保存关系。
- 弹窗内固定显示兜底风险 Tip，不在每次移除确认中重复提示。

### 制程版本编辑器

产品簇调用与产品管理相同的 `ProductProcessVersionEditorDialog`，只替换顶部归属信息为产品簇名称/编码。路线选择、路线图、工序节点配置、表单选择/预览、文档选择/预览、PDF 起始页/结束页、保存/取消和改动确认全部共用，不允许出现产品簇专属分支布局。

## 审计与快照

审计动作继续使用通用 `CREATE`、`UPDATE`、`DELETE` 语义，不为每个具体功能新增动作枚举。审计快照需包含：

- 产品簇或产品成员关系变更前后值。
- 制程版本基本字段变更前后值。
- 工序配置的前后集合。
- 每个工序绑定的 DHR 目录项/表单版本、完成前配置。
- 每个工序绑定的文档版本、文档类型和 PDF 页码范围。

成员转移必须在同一事务中完成数据变更和三类审计写入；任意一步失败都回滚。

## 数据迁移与兼容

新增 Liquibase changeset，按以下顺序执行：

1. 新增 `product_family_member` 表和唯一索引。
2. 为 `product_process` 增加 owner 字段。
3. 将历史 `product_version_id` 回填为 `owner_type = PRODUCT`、`owner_id = product_version_id`。
4. 增加 owner 唯一索引；保留旧字段和旧产品接口兼容。
5. 不删除、不重建已有版本和工序绑定数据。

`product_process.product_version_id` 在 owner 字段回填后调整为可空，以便产品簇制程根不需要伪造产品 ID；旧产品唯一索引保留用于兼容历史数据，新 owner 唯一索引负责统一约束。产品簇删除仅允许在没有成员且没有制程版本时执行；否则后端阻断并提示先处理关联数据，避免遗留孤儿配置。

迁移必须可在已有数据库和空数据库上执行；测试需覆盖历史数据回填、重复成员、跨簇转移和回滚/失败事务。

## 知识本体同步边界

本功能确认并沉淀以下知识：产品簇、产品簇成员、产品簇制程版本、产品制程兜底关系、成员转移不影响历史生产快照。产品簇页面和统一制程服务实现后，将由本体建模角色更新 `docs/knowledge/`；“工单/批次创建时的真正快照落库”在生产模块实现前保持 `specified` 或 `planned`，不得提前标记为 `verified` 或进入运行时投影。

## 验收场景

1. 仅创建产品簇，列表可以展示，父行可展开并正确显示无版本空状态。
2. 产品簇新增、编辑、删除遵循统一建模页面规范；产品簇名称详情和数据审计可打开。
3. 产品成员弹窗只出现半成品/产成品；不符合类型的物料不能通过接口添加。
4. 未归属产品可批量添加，当前成员可重复打开并正确回显。
5. 已属于其他簇的产品显示原簇并置灰；转移二次确认显示旧簇和新簇；转移成功后两边数据和三类审计一致。
6. 产品簇可以创建多个制程版本，版本号重复时后端阻断；编辑器和产品管理页面视觉及交互一致。
7. 产品簇制程版本可选择路线、配置工序表单和文档；编辑后版本详情审计显示 `UPDATE` 及组成配置差异。
8. 产品自身有可用版本时兜底查询只返回产品版本；产品没有可用版本时返回产品簇版本和兜底提示；两边都无可用版本时阻断。
9. 生产模块接入前，产品簇转移不会修改任何已存在的生产对象；统一查询服务不会伪造快照。
10. 数据库迁移在既有数据和空库上均可执行，产品管理既有 CRUD 和版本配置回归通过。

## 不在本次范围

- 产品簇产品成员的多簇归属。
- 运行环境编辑本体或业务规则。
- 工单/批次页面本身的开发；仅提供统一查询契约和服务边界。
- 发布、审核、电子签名、放行和尚未实现的制程运行控制规则。
- 复制独立的产品簇制程表或独立编辑器。
