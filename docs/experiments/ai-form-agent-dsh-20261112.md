# DeepSeek Harness 表单 Agent 可行性验证

在 `codex/ai-experiments` 的 `75ea2fb7f0a5a8d8909c0659939011ddc2227815` 基线上验证 DSH。范围由用户确认，包括使用现有三张脱敏表、先用 OpenAI 调试、正式对比两家模型，以及插件启停、权限和中断恢复。运行使用独立数据库 `edhr_ai_dsh_20261112` 与现有后端和原生模拟填报。

## 接入方式

锁定 DSH 发布组件 `0.2.2-rc.1`。Agent 循环、Cordis 注册与卸载、工具调度及会话恢复由 DSH 提供。eDHR 侧的工作是挂载运行时、复用既有双模型连接、封装表单插件，并在插件内检查任务归属和许可、维护业务检查点。Java 继续执行原生模板写入。实际应用、数据库结构和权威业务知识未改动。

启动时显式装配所需模块，模型只获得表单工具。预览通过现有模拟填报页面生成截图，DSH 本地附件存储维护图片引用，模型适配器把截图发给当前运行所选模型。读取语义与统计用途继续遵循 v3 验证规则。

## 启停、权限和恢复

| 真实实验场景 | 观察结果 |
| --- | --- |
| 模型请求发出后卸载插件 | 注册被移除，迟到的保存调用未执行，原生数据无新增 |
| 同一运行时重新装载插件 | 重新提供表单工具，获授权后可执行 |
| 工具已声明后撤掉写许可 | 调用被拒绝，未建模板 |
| 客户能力未授权 | 工具不可见，旧调用不能创建模板 |
| Java 原生设计保存接口 | 匿名请求 401，无表单权限的真实账号 403 |
| 已确认保存后 SIGKILL 并重启 | DSH 恢复工具记录，eDHR 恢复检查点，续改同一个模板版本 |
| Java 创建完成、检查点未确认时 SIGKILL | 阻止自动重放，保留待核对模板 |
| 只读工具日志写入、检查点未换代时 SIGKILL | 修复后恢复入口拒绝开始任务，Java 版本前后相同 |

恢复专项中，首轮独立质量发现只读日志领先检查点会造成序号冲突，且冲突可能在 Java 写入之后才出现。修复在恢复入口发现这种情况并暂停。主侧 13 项边界检查通过，证据为 `output/ai-form-agent-dsh-20261112/boundary-dsh-1794492784443/boundary.json`。

实验许可为合成授权。401/403 断言只覆盖保存设计 PUT。生产部署还需对创建、查询、编辑的租户和用户权限做端到端验收，并落实事务内幂等、原子版本校验和业务审计。当前进程间恢复依赖 DSH 会话与本地检查点，写入结果不明时需要业务核对。

## 对比方法

OpenAI 清洁表调试成功完成知识查询、设计保存读回、局部修复和原生预览，裁切从 3 处降至 0，提出 3 个待确认问题。调试结果不计入正式对比。正式运行使用相同输入和工具协议，冻结哈希为 `b54f6e5fd113f2a188718f329bb4dab7a0701da975ce8d0fb199d8c722321630`。评估在模型上下文之外完成。付费运行启动后，代码变化限于恢复日志校验和新增故障探针，恢复修复单独通过无模型请求验证。

## 正式结果

| 模型与样本 | 核心填报位置 | 实际引用检查 | 原生静态文字裁切 | 待确认 | 结果 |
| --- | ---: | ---: | --- | ---: | --- |
| OpenAI 清洁 | 15/15 | 3/3 | 3 → 0 | 4 | 已保存，待业务确认 |
| OpenAI 标签 | 67/67 | 28/28 | 7 → 0 | 1 | 已保存，待业务确认 |
| OpenAI 报废 | 17/17 | 5/5 | 8 → 0 | 3 | 已保存，待业务确认 |
| DeepSeek 清洁 | 15/15 | 3/3 | 10 → 0 | 2 | 已保存，设备栏有多建 |
| DeepSeek 标签 | 67/67 | 28/28 | 4 → 0 | 0 | 已保存，独立核对不接受完成声明 |
| DeepSeek 报废 | 未保存 | — | — | — | 26 次模型请求后触及上限 |

五份保存结果均与 Java 当前版本的模型、画布和流程配置读回一致，控件范围无重叠。裁切测量针对原生模拟填报的静态原文字段，不能替代完整视觉验收。填报位置覆盖也不等同于业务配置正确。

- DeepSeek 标签保留工单、批次和日期追溯，遗漏四条物料编码追溯，也没披露实际使用数量的正式消耗职责待确认。OpenAI 保留四条追溯并提出消耗统计问题。
- DeepSeek 清洁保留原件固定的设备栏“无”，同时新增可填设备编号并绑到设备追溯。原件没有这项填写要求。
- DeepSeek 报废尝试保存 15 次。主要错误是把字段来源填成原文或不匹配的范围，导致独立日期位置检查失败。使用正确日期锚点的一次仍未通过整体布局与来源校验。没有创建模板，也没有原生预览。此前 v3 的同模型曾保存此表，单轮差异不足以归因给 DSH。
- OpenAI 的 8 个待问项也可收敛。真正影响业务绑定的是各表的正式统计职责、清洁与报废批号的实际含义，以及报废追溯日期采用哪一处。清洁表表头数量可保留为普通输入，等正式统计职责确认后再选来源。无尘布消耗作为可选扩展可以暂缓。

## 底座判断

建议把 DSH 作为 eDHR AI 的产品化试点底座。实测提供了可卸载工具、可恢复会话以及同一插件上的双模型运行。采用锁定版本与薄适配，客户授权、模板写入、并发控制和审计由 eDHR 实现。本次样本说明，底座可用与表单质量是两项验收。优先改善原表锚点与填写区域的结构化输入，以及完成前的业务用途检查。

原始证据保留在 `output/ai-form-agent-dsh-20261112/`，包括 `protocol.json`、六次 `runs/final-*/` 的模型原件和 DSH 会话、`assessment.json` 及 Java 读回。原生预览位于 `output/playwright/ai-agent-v3/dsh-final-*/`。开发者预览版本和插件机制见 [DSH 官方仓库](https://github.com/deepseek-ai/deepseek-harness)。

L2 独立本体核对为 `not-applicable`，知识基线保持 0.3.25。本轮只验证运行时接入与实验边界。新的独立质量实例复跑了 13 项边界验证和 13 项原 Agent 单测，并核对六次原始请求、冻结快照、DSH 会话、Java 读回和附件摘要。质量门禁为 `passed`，范围限于实验实现及证据。独立证据保存在 `output/ai-form-agent-dsh-final-qa-20261112/`。
