# 列表详情抽屉规范

这是列表行查看详情的开发及验收规范，与 [列表页规范](list-page-guidelines.md) 和 [普通表单弹窗规范](dialog-guidelines.md) 配套。适用于只读对象信息及数据审计；新建/编辑、全屏表单预览、执行工作台、签名和确认分别使用对应专用组件，不能混用外壳。

## 1. 组件及基准

- 新增或修复列表详情必须使用 `gmp-platform/frontend/src/components/DetailDrawer.tsx`。公共组件负责标题、关闭、两页签、背景、宽度和滚动；页面只传入数据内容、页签状态和必要的审计分页。禁止复制另一套 `Drawer` 头部或在页面覆写这些外壳样式。
- 默认可见标题固定为“信息查看”。对象名称、实例号等放在信息分组中，不能用长对象名替代标题。`label` 为领域可访问名称，例如“追溯项详情”；关闭图标及页签使用相应无障碍名称。
- 原始实现参考物料详情 `ProcessModelingPage.tsx`、`DhrDetailDrawer.tsx` 和填报记录详情 `FormFillingPage.tsx` 的共性。历史页面的局部差异不是新页面另起样式的依据；本规范与公共组件是新开发的约束来源。
- 2026-10-07在同一浏览器核验：物料详情标题16px/600、页签左边距16px、顶部58px；追溯项原实现为16px/400、页签顶部72px和白色头部。截取或缩放后的截图不能直接用于比较CSS尺寸；以相同视口、缩放和计算样式复核。

## 2. 外壳和布局（必须）

| 元素 | 约束 |
| --- | --- |
| 位置及尺寸 | 右侧抽屉；桌面宽560px；主题`sm`以下宽100vw；不超过视口，完整视口高度 |
| 外壳背景 | 标题、页签及内容区域连续使用`#f7f9fc`；禁止白色头部拼接灰色内容 |
| 标题区域 | 左右及顶部16px；标题与页签间8px；`subtitle1`、16px、600、`#303133` |
| 关闭 | 右上`IconButton size="small"`及24px Close图标；当前主题点击区域34px；Tooltip“关闭”，领域化`aria-label`；无底部关闭按钮 |
| 页签 | “数据信息”“数据审计”；与标题、分组左边缘同为16px；下边框`1px solid #e4e7ed`；使用主题默认48px高度和主色，不额外叠加左右padding |
| 内容 | 独立纵向滚动；左右和上下16px；分组间16px；`minHeight: 0`，分组不得因Flex剩余高度被压扁 |
| 滚动边界 | 标题及页签保持可见；只滚动内容。不要把整个标题、页签、内容包进同一个滚动Box；避免纸张和内容双重纵向滚动 |
| 审计分页 | 业务存在分页时放在`footer`，固定在滚动内容外；不新增无业务必要的操作底栏 |

公共组件在当前主题下页签顶部为58px（16px顶部+34px关闭区域+8px间距）。规范值由公共组件和主题实现，页面不得为凑截图增加局部偏移。主题修改相关值时须同步规范和实际视觉核验。

## 3. 信息分组和字段（必须）

- 信息分组复用 `FormDialogSection` 或同视觉结构的既有 `DetailSection`：白色内容、`1px solid #e4e7ed`边框、主题小圆角；分组标题背景`#f8fafc`、14px/600、左右12px/上下8px、下分割线；分组内容12px内边距。禁止为只读分组另套普通表单的20px弹窗标题。
- 字段使用两列响应式网格，各列 `minmax(0, 1fr)`，窄屏一列。普通短字段不随意跨列；描述及长内容允许明确跨列。当前修复页面字段间距12px。
- 字段标签使用`caption`（12px/1.4）、`#909399`，值使用`body2`（14px/1.5）、`#303133`，标签和值间距4px。状态继续使用 `StatusBadge`，不能重新发明状态色或解释。
- 长编号/名称允许换行，子容器`minWidth: 0`，不能撑宽抽屉；值为0必须显示0。空值沿用当前领域格式化规则，不因视觉迁移清空或改写数据。
- 内容可因业务不同分组，但标题、背景、边界及字段排版必须一致。表单内容在完整预览中查看，不能为了放下原表格而任意加宽详情抽屉。

## 4. 行为和数据边界

- 保留行点击及键盘Enter/Space打开详情、编辑阻止冒泡、打开新对象重置到“数据信息”的规则。关闭图标、Escape及遮罩关闭使用同一页面回调。
- 标题及页签在内容加载、空数据、失败和切换时保持稳定。沿用领域原有请求与错误/重试逻辑，视觉迁移不得顺带改变权限、接口、审计证据、来源快照或生产执行。
- 数据审计使用既有折叠记录和中文字段展示；不得把原始JSON或宽表作为窄栏审计内容。审计分页不得因为外壳迁移丢失。
- 只迁移外壳时，必须单独报告发现的既有领域审计转换缺口。外壳通过不能作为审计内容已合规的证据；需要改变字段翻译、状态解释或证据内容的修复按对应领域规则另行验证，不以样式调整静默改变审计语义。
- 来源预览保持只读，关闭后按页面既有流程返回：投影来源返回原详情，填报列表的完整预览返回列表。本次统一外壳不能改变预览与详情的状态切换。不能因统一标题丢掉对象识别信息，移入正文的名称/实例号必须继续可见。

## 5. 验收证据（必须）

使用组件或通过构建不能单独证明视觉一致。交付新详情或外壳修复时必须：

1. 在同一浏览器、同一视口和缩放下，对照至少一个已调好的普通/RDO详情及一个业务详情，核对顶部背景、标题字重、关闭尺寸、页签起点、首组边缘和字段字号。保留对照截图及计算样式；不把截图裁切/缩放差异归因产品。
2. 检查桌面（至少1280px宽）、短窗口及窄屏；验证560px/100vw、长值换行、内容独立滚动、标题/页签固定和必要分页可见，不出现水平溢出。
3. 实际点击行、切换两页签、打开另一个对象、关闭、打开来源预览并按页面既有流程返回。按本轮改动核对实际请求及数据显示，不能仅做源码字符串检查。
4. 报告未覆盖的页面及既有差异，不以某一页通过宣称全系统已经统一。非目标历史详情后续改动时遵循公共组件，不借本次修复批量改写业务页面。

## 6. 用法

```tsx
<DetailDrawer open={Boolean(selected)} label="追溯项详情"
  onClose={() => setSelected(undefined)} tab={tab} onTabChange={setTab}>
  {tab === 0 ? <FormDialogSection title="基本信息">{/* 领域只读字段 */}</FormDialogSection>
    : <FormDialogSection title="审计记录">{/* 既有折叠审计 */}</FormDialogSection>}
</DetailDrawer>
```

组件只统一展现和已有事件入口，不承接业务查询、权限、统计口径或审计转换。需要变更这些行为时应单独核对领域规则和验证风险。
