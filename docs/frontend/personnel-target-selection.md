# 转办与改派人员选择

适用：任务转办、集中转办/管理员改派、生产执行转办、表单审批列表转办。主体配置的多选用户/部门/角色仍由SubjectSelector负责，不把人员目标选择的领域资格套到主体建模。

用户确认见DEC-0095：全部符合当前入口既有资格的人员必须可继续查找和选择，不设总人数100上限。单批默认50、最大100仅为工程读取量；每批在数据库中完整应用原租户、状态、锁定、原候选、申请人回避和领域权限后排序分页，返回content/page/size/hasNext，不计算未消费总数。签署、状态和最终提交资格仍由各领域服务重新校验。

## Canonical UI Map

| Capability | Canonical owner | Source of truth | Allowed variants | Verification |
|---|---|---|---|---|
| Select/Listbox | components/identity/PersonnelTargetSelect.tsx（MUI Autocomplete） | 本规范、DEC-0095及各入口服务端资格 | 转办目标 / 管理员改派目标；默认50人一批，可继续加载 | 原生PG跨页与授权、test-personnel-targets-browser.mjs键盘/弹层/加载/错误/窄屏 |

视觉沿用DESIGN.md第10节、list-page-guidelines、dialog-guidelines和App.tsx的MUI主题。当前新增选择器不修改颜色、字体、弹窗祖先、滚动条或任何全局token；字体、边框、间距和主题色通过既有MUI组件继承。生产管理弹窗和任务签名密码链不在此次样式/签署整改范围。

选择器只接受服务端明确返回的人员ID。输入值与已选值分开；键入新搜索清除旧选择，300ms防抖，中文输入法组合期间不发搜索，清除立即执行。新关键词和任务身份使用独立查询键，旧请求取消或结果隔离。该弹窗中的临时人员搜索不放入URL或持久存储；关闭后不保留名单缓存。

采用明确“加载更多人员”按钮，保留已加载选项和当前选择。加载期间按钮禁用并显示进度；末页显示“已全部加载”，失败提供原位置重试，后续页失败时已加载人员仍可选择。显示已加载人数不冒称精确总数，不把当前一批当全部人员。

复用MUI组合框的方向键、Enter选择、Escape收起、清除及焦点规则；加载更多按钮可通过Tab到达，激活后回到输入以继续键盘选择。选项弹层跟随触发框宽度并限制高度，保留可操作滚动条；窄屏不引入横向页面溢出。操作完成沿用原弹窗提交、签名、通知和关闭流程。
