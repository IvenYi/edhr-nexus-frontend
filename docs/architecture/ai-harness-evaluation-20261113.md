# eDHR Harness 复用评估与 2A 边界

结论：DSH可作为优先候选，复用插件、工具注册、模型循环与会话机制；目前不能认定为已通过商用验收的底座。eDHR需要自己的薄控制层，掌握真实授权、业务任务、预算、回执及可读事件，不重写DSH推理循环。判断为工程建议，不是新的业务授权。知识保持0.3.25/P0/internal。

## 原始资料与版本

2026-11-13核对官方[发布页](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.2-rc.2)，该候选标为Pre-release；已知旧实验固定rc.1。发布页列出中断、重复提交、工具错误及SDK迁移相关变更，故升级必须回归，不能用版本号或模型成绩推定稳定性。本次固定rc.2，未声称它是npm最新版本。

[rc.2架构原文](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.2-rc.2/docs/architecture.md)明确插件可替换，正式应用通过profile启动；进程内装配属于独立类别。旧实验runtime.mjs是技术验证代码，不直接作为产品启动器。Python SDK仍启动DSH运行时，换Python不会消除版本、进程与恢复问题。

[sdk-minimal原文](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.2-rc.2/packages/bundle/sdk-minimal/README.md)默认带持久Shell和完整文件访问能力，并非面向业务的最小权限组合。[base原文](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.2-rc.2/packages/bundle/base/README.md)还包含广泛工具和独立日志上传路径。因此不能仅凭名称选择默认profile；正式组合必须显式禁用不需要的工具、遥测及会话上传，检查最终加载清单，禁止模型安装插件。此次适配模块没有启动任何profile。

[Session原文](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.2-rc.2/docs/subsystems/session.md)将交互历史建模为追加事件，持久化另有职责；whenIdle不是落盘承诺。DSH会话恢复不能证明Java写入未发生，业务结果以数据库回执和当前对象读回为准。

本地首次安装rc.1得到npm audit 8个high条目，其中根因是Zod依赖的传播，而非8个独立漏洞。依据[官方安全公告](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5)，修复版本为4.6.6。新模块改为rc.2后重新安装审计0项；不能因此宣称全供应链无漏洞。旧实验依赖未修改，不能用于产品发布。安装使用ignore-scripts。npm旧锁导致一次peer解析失败，保留旧生成目录到/tmp后重新生成新模块锁文件，没有使用force或legacy-peer-deps。

## 所有权与扩展结构

| 层 | 所有者 | 必须保持的边界 |
|---|---|---|
| 模型循环、工具注册、上下文与会话 | 优先复用DSH | 锁定版本，有限工具清单；仅持有本轮必要上下文 |
| Worker宿主与供应商适配 | eDHR Node模块 | 领取/续租/停止，预算预留，未知请求不盲重发；按部署允许的模型选择 |
| 能力插件 | eDHR各能力团队 | 表单、导入、问数分别声明依赖模块、权限、知识包和工具协议；禁用撤销执行资格 |
| 业务控制与事实 | Java/PostgreSQL | 当前身份与付费能力判定、幂等、修订、事务、审计、真实完成证据 |
| 用户协作与日志 | eDHR产品 | 统一任务时间线、待回答问题、成果导航、接手；不暴露内部会话原文 |

不采用每个功能一个自建Agent循环，也不提前引入图数据库、多Agent团队或Python服务。新能力复用任务协议，在各自领域服务执行动作。付费开关属于eDHR授权，DSH插件挂载状态不能代替授权；热插拔首先是能力启停，新代码仍需版本化发布。停止后保留原生成果。

运行日志分为三类：DSH技术会话用于恢复和诊断；产品事件用于可读进度；原生业务审计用于实际操作追溯。三者通过task/run/step/toolCall/operation关联，不能合并为任意模型文本。下一阶段映射开始、提交、失败、中断、未知结果；展示安全摘要及来源版本，禁止隐藏推理、密钥与完整原始附件直接进入用户日志。

## 已实现的2A候选

`gmp-platform/ai-worker`独立包提供Worker专用HTTP客户端和三项DSH工具：读取当前表单、创建本任务表单、保存当前设计。任务、轮次、代际绑定于宿主领取结果；模型不可指定身份和目标。保存先读当前修订；工具卸载中止本地请求，Java最终裁决执行资格。

写前持久化稳定操作标识，响应不明时阻断；重建适配器仍读取pending标记，宿主仅在获得匹配任务/操作回执后解除，404不证明未提交。回执不提供当前修订，继续保存必须重新读取。pending只记技术标识，不含表单和密钥；它不是产品操作日志。当前仅限单宿主、单任务串行适配验证；多实例占有、进程强杀、共享存储及重启完整编排未验收。损坏标记直接阻断，不能静默丢弃。

测试采用本地合成数据、HTTP替身及真实Cordis/DSH注册表；不连接Java服务器、数据库或模型。没有部署入口、自动领取轮询、模型请求或SUCCEEDED入口。原Java接口验收仍属1B历史证据，不能替代本轮未来真实连接测试。

## 继续采用前的验收条件

1. 通过正式profile启动最小工具集合；检查无Shell、文件、任意网络、插件管理和隐式上传；记录完整包清单及版本哈希。
2. 单任务独立进程/工作目录；限制CPU、内存、附件大小和出网；跨任务越权负例，停用及停止后迟到结果不得写入。不是靠提示词隔离。
3. 在隔离数据库跑真实Worker→Java；覆盖领取过期、新代际、断网、响应丢失、强杀、回执已提交但会话未落盘、重复恢复。不把会话恢复称为业务exactly-once。
4. 固定插件/协议/知识包/模型配置；版本不兼容拒绝续跑。升级保存历史会话夹具，回滚不损坏业务数据；无必要不追随上游自动升级。
5. 知识包投影门禁及来源哈希、适用关系检索；内部知识不自动发布。确定性语义检查、原生预览及当前修订读回共同支持完成判定。
6. 模型预算预留和有限重试接入；请求已发出但用量未知保留预算。调试OpenAI，冻结后用三张安速康表单及未见变体双模型验收，不只比较字段数量。
7. 持久可读日志、断线续读、敏感数据检查；容量、持续运行、备份恢复和升级回归在首批商用前完成，目标值按试部署环境测量，不虚构SLA。

上述1–4若无法在不fork大量上游核心的前提下闭环，重新比较其他运行时。替换时保持Java业务API、任务与回执协议；只替换DSH适配、会话桥与模型循环。该退出路径用于控制供应商依赖，不预建多个无用实现。

来源分级：用户对插件和稳定底座的要求为user-confirmed；官方版本资料、本地源码与实际测试为original-evidence；旧实验总结为secondary-reference；选择DSH为优先候选和分层方案为inference。当前结论仅支持继续工程验证，不支持商用上线。
