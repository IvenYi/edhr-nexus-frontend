# 事务、投影、追溯与 DHR 汇总业务边界

## 文档目的

本文件保存 eDHR 的核心业务规则，独立于任何表单模板设计器、Office 还原方式或表单渲染技术。模板模块由独立负责人持续实现；事务、生产执行、追溯和 DHR 模块只能依赖其受控契约，不能反向耦合某个画布、控件库或字段分类 UI。

## 模块职责与契约

| 模块 | 对其他模块负责的输出 | 不属于本模块的职责 |
| --- | --- | --- |
| 模板模块 | 已发布模板版本、模板版本 hash、表单实例、草稿/流程中/完成/作废生命周期、最终数据快照、签名和审计引用 | 事务处理、业务统计、DHR 汇总、追溯图计算 |
| 表单流程 | 任务状态、退回和再提交、最终完成事件、审批记录 | 在流程进行中发布最终业务投影 |
| 事务与投影 | 幂等投影批次、主线追溯索引、关系边、业务统计投影、DHR 候选证据 | 模板设计、原文还原、字段控件展示 |
| DHR 汇总 | 目录规则、实例-目录关系、汇总版本、完整性检查、审核和冻结状态 | 修改来源表单实例或重写历史投影 |

模板模块至少需要在其 API 或领域事件中提供：`templateVersionId`、`templateVersionHash`、`formInstanceId`、业务主体上下文（批次/SN/工单/工序/事务）、实例状态、最终数据快照或其不可变引用、签名/流程/审计引用，以及可供投影解释的业务语义绑定。这里的“语义绑定”是机器可读映射，不规定设计器应如何让用户配置。

## 投影时机

| 表单类型与事件 | 允许写入 | 禁止写入 |
| --- | --- | --- |
| 非流程表单提交成功 | 实例不可变快照、投影批次、追溯主线/关系、业务统计、DHR 候选 | 覆盖已存在的历史投影 |
| 流程表单首次提交 | 实例工作快照、流程任务和审计记录 | 追溯、统计、事务业务结果和 DHR 最终候选 |
| 流程表单退回、补正、再提交 | 更新进行中的工作快照和流程日志 | 任何最终业务投影 |
| 流程最终结束 | 最终快照、投影批次、追溯主线/关系、业务统计、DHR 候选 | 以早期提交值替代最终字段值 |

流程表单仅在最终结束时使用最终字段值投影。这是为了避免审核退回期间的临时数据进入业务统计和正反向追溯；非流程表单则在提交即完成的前提下立即投影。

投影执行必须以 `formInstanceId + finalRevision + projectionRuleVersion` 作为幂等键，并记录投影批次、输入快照 hash、规则版本、执行时间和结果。重复事件只能返回同一结果，不能重复累加数量、重复新增追溯边或重复加入 DHR。

## 追溯、业务统计与事务关系

一次有效投影可以形成以下不同用途的输出，不能只把所有结果塞进一张“事务总线”表：

- 主线追溯索引：按批次、SN、工单、产品、工序、设备、物料等业务主体建立可查询入口。
- 关系追溯边：表达消耗/产出、替换、拆分/合并、返工、报废、检验或事务前后关系。
- 业务统计投影：报工数量、良品/不良/报废、工时、检验结论、物料消耗、仓储等供生产执行和审核使用的读模型。
- DHR 候选：将合格的完成表单或事务结果标记为某一 DHR 实例的可聚合证据，不等同于已经进入已审核 DHR 目录。

冠骋把设备、产品、良品数、物料批号、仓储单号等概念混入 `EDHRFieldTypeEnum` 并由抓取服务分流。这证明投影需要稳定的业务语义，但不是我们照搬“基础/逻辑/追溯/业务字段”分类 UI 的理由。产品实现应把录入方式与语义绑定分离，且由模板模块决定其配置体验。

## 变更、作废与补偿

流程结束后的表单不应直接编辑；允许的受控路径是作废，或发起形成新修订的变更流程。任何已投影记录都必须可解释地撤销：

1. 原投影批次标记为失效或生成对应的冲销批次，保留原因、操作者、审批/签名和关联修订。
2. 主线索引、关系边和统计读模型按投影批次重算或冲销，禁止无审计地物理删除历史。
3. 已加入的 DHR 目录项标记为失效/待重汇总；未审核的汇总创建新版本，已审核或已放行的 DHR 必须进入受控变更流程。
4. 追溯查询默认展示当前有效链路，同时允许审计人员查看完整历史和失效原因。

## DHR 汇总规则

DHR 模板定义目录、每个目录的必需/可选证据条件和自动聚合规则。制程、批次和事务上下文决定 DHR 实例；已完成且有效的表单/事务记录按规则成为候选。人工补充只能增加带来源、理由、操作者和审计记录的证据，不能伪造来源。

汇总保存的核心不是拖拽，而是“DHR 实例 - 目录 - 来源表单/事务实例 - 来源版本/快照”的受控关系。汇总版本应冻结目录结构和成员清单；审核前执行完整性检查，至少覆盖必需证据缺失、来源记录仍在审核、签名缺失、实例已作废、异常/事务未关闭和版本不一致。DHR 审核、放行与归档只能消费已冻结的汇总版本。

## 当前非目标

- 不在本分支实现表单模板菜单、模板设计器、表单控件、Office 导入还原或表单填写页面。
- 不规定模板数据的内部 JSON、画布结构、字段类型体系或页面交互。
- 不以冠骋的物理删除策略处理作废；本产品要求历史投影、DHR 成员和审计记录可回溯。
