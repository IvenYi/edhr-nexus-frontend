# 作业、投影、追溯与 DHR 汇总业务边界

## 文档目的

本文件保存 eDHR 的核心业务规则，独立于任何表单模板设计器、Office 还原方式或表单渲染技术。模板模块由独立负责人持续实现；作业、生产执行、追溯和 DHR 模块只能依赖其受控契约，不能反向耦合某个画布、控件库或字段分类 UI。

2026-09-29：电子表单追溯与业务投影的配置体验、属性扩展、数据模型、工程落地及验收计划，集中在独立的[电子表单追溯与业务投影落地方案](form-traceability-projection-design.md)。该文区分已确认要求、候选实现与待确认口径；本文件继续维护跨模块职责及不变量，不因新方案文档而宣称功能已实现。

## 模块职责与契约

| 模块 | 对其他模块负责的输出 | 不属于本模块的职责 |
| --- | --- | --- |
| 模板模块 | 模板版本、使用时执行快照、表单实例、草稿/流程中/完成/作废生命周期、最终数据快照、签名和审计引用 | 作业处理、业务统计、DHR 汇总、追溯图计算 |
| 表单流程 | 任务状态、退回和再提交、最终完成事件、审批记录 | 在流程进行中发布最终业务投影 |
| 作业与投影 | 幂等投影批次、主线追溯索引、关系边、业务统计投影、DHR 候选证据 | 模板设计、原文还原、字段控件展示 |
| DHR 汇总 | 目录规则、实例-目录关系、汇总版本、完整性检查、审批和冻结状态 | 修改来源表单实例或重写历史投影 |

模板模块至少需要在其 API 或领域事件中提供：`templateVersionId`、`templateVersionHash`、`formInstanceId`、业务主体上下文（批次/SN/工单/工序/作业）、实例状态、最终数据快照或其不可变引用、签名/流程/审计引用，以及可供投影解释的业务语义绑定。这里的“语义绑定”是机器可读映射，不规定设计器应如何让用户配置。

## 投影时机

| 表单类型与事件 | 允许写入 | 禁止写入 |
| --- | --- | --- |
| 非流程表单提交成功 | 实例不可变快照、投影批次、追溯主线/关系、业务统计、DHR 候选 | 覆盖已存在的历史投影 |
| 流程表单首次提交 | 实例工作快照、流程任务和审计记录 | 追溯、统计、作业业务结果和 DHR 最终候选 |
| 流程表单退回、补正、再提交 | 更新进行中的工作快照和流程日志 | 任何最终业务投影 |
| 流程最终结束 | 最终快照、投影批次、追溯主线/关系、业务统计、DHR 候选 | 以早期提交值替代最终字段值 |

流程表单仅在最终结束时使用最终字段值投影。这是为了避免审批退回期间的临时数据进入业务统计和正反向追溯；非流程表单则在提交即完成的前提下立即投影。

投影执行必须以 `formInstanceId + finalRevision + projectionRuleVersion` 作为幂等键，并记录投影批次、输入快照 hash、规则版本、执行时间和结果。重复事件只能返回同一结果，不能重复累加数量、重复新增追溯边或重复加入 DHR。

## 追溯、业务统计与作业关系

一次有效投影可以形成以下不同用途的输出，不能只把所有结果塞进一张“作业总线”表：

- 主线追溯索引：按批次、SN、工单、产品、工序、设备、物料等业务主体建立可查询入口。
- 关系追溯边：表达消耗/产出、替换、拆分/合并、返工、报废、检验或作业前后关系。
- 业务统计投影：报工数量、良品/不良/报废、工时、检验结论、物料消耗、仓储等供生产执行和审批使用的读模型。
- DHR 证据：实际生产关联实例持续归集，未完成、失败、作废和替代历史仍保留；最终业务投影与 DHR 证据可见性分开，表单完成不等于检验合格。

冠骋把设备、产品、良品数、物料批号、仓储单号等概念混入 `EDHRFieldTypeEnum` 并由抓取服务分流。这证明投影需要稳定的业务语义，但不是我们照搬“基础/逻辑/追溯/业务字段”分类 UI 的理由。产品实现应把录入方式与语义绑定分离，且由模板模块决定其配置体验。

2026-09-29 用户明确：各报表统计模型由产品方预定义和维护，客户只选择字段并配置取值来源，不承担建立统计模型的工作；不是每张表都需要追溯或统计。已有零散用途及数量汇总代码属于允许被统一方案替换的试验实现，不能作为新设计的硬约束。该授权不等于删除历史证据；新增库存等业务动作仍另走需求。详细实现选择见独立方案，尚未作为运行能力发布。

## 变更、作废与补偿

流程结束后的表单不应直接编辑。允许的受控路径只有表单作废，或发起形成新修订的表单变更。变更不覆盖当前版本；作废不改字段值。详细设计见 `docs/superpowers/specs/2026-09-11-record-correction-and-void-design.md`。任何已投影记录都必须可解释地撤销：

1. 原投影批次标记为失效或生成对应的冲销批次，保留原因、操作者、审批/签名和关联修订。
2. 主线索引、关系边和统计读模型按投影批次重算或冲销，禁止无审计地物理删除历史。
3. DHR 自动检测有效来源变化并提示，阻断基于过时证据的批准；退回或新版本重审由人执行，已批准版本保留旧批准和快照，不自动退回、解冻或改变产品放行。
4. 追溯查询默认展示当前有效链路，同时允许审计人员查看完整历史和失效原因。

## DHR 汇总规则

2026-09-25 同一切片直接修订，设计为 `specified/internal`；详见 DEC-0063/0068/0071/0072 及主设计第 6～11 节。上文最终业务投影时机只决定最终结果发布，不决定 DHR 证据何时可见，不改变其他事务或追溯模型。

按生产对象持续自动归集目录、作业、自定义实际实例及受控附件，不以手选或完成状态过滤；空来源不造证据，应有缺项按适用规则阻断。未完成、失败、作废、替代及处置历史保持可查，不冒充合格完成，表单 COMPLETED 不代表检验合格。普通汇总整理和提交仍限生产正常完成，终止政策沿用 DEC-0069。

证据范围与目录展示解耦：默认位置可查，组/单份整理只调整展示位置、别名及顺序，取消自定义位置恢复默认位置，不删除证据或改变生产归属。作业/工序表单由执行上下文绑定生产对象；内容填错、自定义上下文选错及附件误关联分别核验，不设计普通跨批次搬运。

提交重核完整证据集合及来源版本，要求提交人逐项人工确认质量与异常、源审批签署和完整范围并填写说明；确认人/时间/说明冻结于 checkResult，不能将其误称为系统自动判读质量合格。全部证据、附件、检查结果、展示目录及审批绑定同版冻结；必填目录仅是检查之一，其他适用签署、质量结果、异常处置及未完成补录检查不得省略。审批任务附件下载经过任务授权且只限本冻结版本；审批、详情及整份/选定范围 ZIP 使用同一冻结基准，ZIP 包含来源生产执行审计和签名，部分导出不改变审批范围。NONE 不豁免法定审核、源签署或放行。实例日志与 DHR 数据审计分层关联，正常业务修订的旧版本及批准保留；当前工作树已有三项人工确认、任务附件门禁和 ZIP 来源追溯代码及聚焦测试，但任意质量结论、源签署有效性、主动通知和外部审计全集仍需验证。

2026-09-28 `revisionPrintableExport` 已确认按冻结档案目录勾选导出：中文 ZIP 含按档案顺序汇成的总 PDF、按实际来源分类的单实例原模板版式 PDF、对应实例的附件、根级汇总附件及追溯 JSON。附件内容不合入总 PDF，PDF 只保留索引，原件放 ZIP，Office 不转换；总 PDF 不替代含附件的完整档案，选定范围不冒充完整 DHR。不新增在线打印流程或第二套模板业务解释。发起修订在列表用纯图标及提示，查看弹窗直接显示按钮；沿原权限与原因基于最新定版先建 DRAFT 汇总中草稿，重新提交才形成下一冻结版本。草稿存在时旧版仍通过版本选择只读查看及按权导出，不能混入当前值或以数据审计替代正文。该切片仍为 specified/internal，PDF 渲染链、权限、附件完整性和端到端验证由主开发及后续独立质量收尾，不能借旧测试宣称已发布。

前期错误旧汇总按 2026-09-27 最新确认及 DEC-0063-09 转换或清理：备份旧汇总及关联，保留可用目录/位置/顺序/别名生成待核查草稿，清理错误旧冻结和其证据位置，不能转换者记录清理原因。不得覆盖已有当前模型冻结或草稿，原表单、生产对象、签署、原审计、附件文件及终止快照不得删除，生产完成状态和权限不变。旧 NONE/FORMALIZED 缺少 checkResult 不能冒充核查或合规完成；转换草稿须再次人工核查提交，不补造旧核查或审批，原审计保留并追加迁移事件。当前模型统一，移除 evidence_model_version 分支及旧兼容，version_no 正常定版修订仍保留。该迁移属于 product-core，本机迁移已按原始执行/回归日志、前后指纹及只读查询验证，用户再次核查/正式提交未做且本切片独立质量验证已通过，不改变上文正常受控变更、终止快照或追溯投影规则。
