# 产品 AI Agent 运行契约

状态：设计与分切片实现契约；不是已验证执行契约注册。来源为用户批准的[产品设计](ai-form-agent-product-design.md)与[决策包](ai-collaboration-slice-1-decision.yaml)。研发主开发、本体和质量角色继续遵守 AGENTS.md；本契约约束产品内 Agent，不给它研发工具、管理员权限或任意数据库访问。

## 商用工程评估与分期

现方案可作为商用工程建设依据：业务写入有确定性所有者，真实身份与工具执行隔离，停用与恢复有明确语义，原生成果不依附付费能力存续。尚不能上线商用：原生写入并发、生产选用边界、知识发布资格、实际故障和资源上限尚待逐切片验证。DSH实验结果不代替这些证据。

原切片1包含多个高风险修改，拆分为连续的1A与1B；拆分不取消原验收标准。

## 身份、能力与生命周期

- 默认单安装；安装ID由部署配置提供，账号必须属于现有默认租户0。不宣称多租户。
- 部署总开关与数据库能力开关共同决定启用，数据库初始关闭。切换接口复用现行 `system.settings` 权限；执行要求当前 `master-data.form-templates` 权限。两者均查数据库当前账号、锁定及角色权限，不信任旧JWT的授权快照。
- 用户只能读取和操作自己的任务。能力关闭仍允许有原数据读取资格的所有者读取历史；停用/锁定或撤销表单权限不继续读取。
- 任务保留历史发起人ID，不以新增外键阻断原有普通账号删除，也不级联删除任务和事件。账号删除后当前资格核验失败；原系统受保护账号的删除规则保持。
- Worker使用独立、至少32字符的部署凭据，只对 `/api/v1/ai/internal/**` 生效；它不能登录或调用原生业务API。该接口必须部署在TLS/内部网络后，不记录凭据。
- `Task`为持续协作容器；`Run`为一次执行。1A实现 `QUEUED → RUNNING → STOPPED/FAILED`；用户继续新建轮次，终态不复活。其他完成/待补答状态待对应证据与对象动作实现后开放，1A不以模型文本声明成功。
- 创建与用户动作使用范围内唯一请求键和摘要。相同内容重试返回同一结果；不同内容拒绝复用。停止指定当前轮次；旧标签不能停止新轮次。
- 领取代际由服务端递增产生。续期、预留和终止必须匹配当前轮次、未过期代际和运行时限。过期重领属于同轮，不延长本轮总运行时限；旧Worker返回仍无执行资格。
- 禁用时结束活动轮次；再次启用不复活旧轮次。部署总开关关闭或当前权限失效时拒绝继续执行，调度扫描收敛任务状态；没有开放业务写入的1A不产生占用。

## 持久预算与事件

任务创建时固定有限请求次数、单次输出上限、单次费用预留和总费用估算额度；每轮固定时限及运行配置版本。部署默认值是隔离工程验证参数，不代表客户套餐或供应商报价。

请求发出前在事务内预留；按轮次与稳定调用标识幂等。未知结果保留预留，不自动退款；成功获得用量后可幂等结算，累计请求不返还，实际费用超预留则记录真实值并阻止继续超额请求。重领、服务重启和新轮次不重置任务预算。1A只验证账本协议，不发生供应商调用，不把估算额度称为精确账单限额。

1A结算也要求有效执行资格；停止或代际过期后保留未知消耗的预留，不提供绕过执行资格的账单更新通道。停止后的供应商对账尚未实现。重领后返回的已有预留不代表可以重新发送模型请求，必须先核对原调用结果；实际供应商请求去重与恢复在模型接入切片验证。

事件保存任务/轮次、实际用户或Worker来源、动作和时间；用于任务运行解释，不冒充模板业务审计或电子签名。后续领域写入审计与回执必须同事务落库。

1A使用能力行→任务行→轮次行的固定加锁顺序，单能力事务短且串行。没有在数据库锁内执行模型、文件或浏览器操作。该选择适合单Worker首版；并发吞吐须测量后再优化，不承诺高可用。

## 知识、调用与实现关系

新增AI协作知识域；复用表单、追溯和统计的原有稳定ID。概念和规则表达语义，动作契约表达输入/输出、权限、前置条件、结果、幂等与失败语义，实现锚点连接Java方法、API、迁移和测试。SDK调用方式、部署参数和重试实现放工程文档及锚点，不全部升级为业务概念。

产品插件消费获准的能力知识包；记录源Git提交、知识版本、内容哈希、适用产品版本与投影清单。内部 `specified/implemented` 规则不因实验读取过而获得客户/运行资格。动态权限与目录查询不冻结为旧知识快照。

本体托管需要获准规则、类型明确的事实、确定性动作、版本依据及运行证据闭环；自然语言说明、代码链接和模型推断不授予动作权限。Agent回答默认仅影响当前任务；不自动改写权威知识或客户全局政策。

当前继续P0，按真实AI需求推进能力范围的P1查询与P2最小版本保障；不宣布全仓P1/P2完成，不新增图数据库或通用推理引擎。知识包发布与检索是切片2的明确交付，不以新增本体模块替代。

## 研发工作契约适用性

现有三角色、决策包、L2门禁、独立质量与来源分级可复用，无须新长期角色或第二套开发流程。新增约束是：产品Agent不得继承Codex工具权限；知识/工具/插件/模型版本与部署策略均属于测试输入；故障边界验收与模型质量验收分开；用户资料和附件不能注入工具授权。

本地验证继续使用隔离PostgreSQL、真实迁移与真实认证数据，固定可重复测试，不接生产数据。1A无需API key或模型费用；后续调试优先OpenAI，完整验证再双模型。上线前仍需部署备份恢复、附件保留、秘密配置、实际容量与生产选用范围的证据。
