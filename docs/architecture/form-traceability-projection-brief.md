# 电子表单追溯与统计：方案简版

供朋友评审 · 2026-10-15集成补正 · 当前知识0.3.25/schema1.2.0

**本分支围绕首次最终完成闭环开发，当前修正同时覆盖保存后的过程追溯。**客户用普通字段建表，再配置来源；已保存内容供追溯，最终完成且投影成功的正式数量供报工、报废及消耗报表。批次/工单最终产出联动、受控修订／作废（A12）、长期记录本、复杂谱系、AI 和客户试用未覆盖；不代表正式生产发布。运行与实际验证见[开发说明](../development/form-traceability-projection-running.md)。

**2026-10-10已落实的运行修正：**成功保存/暂存后可查询最新已保存内容，过程检索与正式统计分开；真实提交到审批后的阶段来自活动流程节点，原生产状态机不变。运行草稿不做阻断性业务完整性校验，但权限与证据安全保留。物料批号和单位可以不填，MVP不换算；空单位只在同用途、实际对象、工序和适用物料/批号等完整粒度一致的空单位组内合计。这不证明物理计量一致，也不把“没数据”当0。源码及本轮聚焦测试证据见[运行修正证据](../knowledge/evidence/form-traceability-projection-ownership-user-confirmed.md#2026-10-10-澄清后的运行修正切片)，独立质量结果与交付范围仍以收尾记录为准。

交互已按同一画布侧栏调整：字段直接关联追溯含义；统计主要从整子表配置，单列显示其整表来源与角色，编辑切换到整表；主表分散字段按一笔业务一次配齐。系统维护子表行身份，不让客户额外填写唯一明细编号。配置统一使用顶部“保存”，不再另点启用；模板保存校验配置完整性，运行填报草稿暂存仍可保留未完成值。自动带入其余规则及错误系统编号的最终处置仍待确认，依赖部分没有实现。

**MVP范围已确认：追溯支持可复用追溯项目录，业务统计保持预设报表；客户自定义业务报表留到二期。**目录支持文本、数字精确值和日期起止范围，九项预置不可删除；自定义项支持CRUD，有配置关联须先解除再删除，历史填报内容保留。其他生命周期、复杂OR及自定义引用兼容仍另定。当前决策导航为[DEC-0077](../knowledge/decisions/DEC-0077-form-traceability-projection-ownership.yaml)，历史同名编号映射见[集成核对](../knowledge/evidence/projection-integration-2026-10-15.md)。

2026-10-13最新页面要求：**表单追溯、报工记录、报废记录、消耗记录分别提供独立菜单页面，详情直接看来源原表单并定位字段或实际子表行。**本轮工程采用逐笔业务记录，撤下记录/合计二级切换而保留已有合计计算；不由同物料或同值合并来源。行定位沿所显示快照中的稳定身份，缺失/重复身份不猜测高亮。保存后追溯、最终完成统计、冻结来源、真实归属、DHR及原权限保持；新页面运行验收另行记录，不以此前QA或竞品静态材料代替，详见[本轮知识证据](../knowledge/evidence/form-traceability-projection-ownership-user-confirmed.md#2026-10-13-同切片增量独立记录页面与直接来源原表单)。

## 1. 想解决什么问题

客户照常建立文本、数字、下拉选择等普通字段。需要查询或统计时，再告诉系统：**要查什么、数据在哪里。**

查找与追溯、业务统计是两个并列可选任务：一张表单可以只配置批次号、设备号、工序等字段供查找，完全不生成业务统计明细；也可以只做统计、两者都配或都不配。画布入口同时覆盖两项任务，查找不隐藏在统计的高级设置里。

2026-10-09/10确认：预置“生产批次/SN”在有执行上下文时表示这张表单实际所属对象，字段填选另一个编号不改变生产或DHR归属；无上下文时可以登记系统内对象，已设自动带入则提示上下文缺失，登记不自动生成执行、统计归属或DHR成员，正式归入DHR需另走特别业务流程。无上下文独立登记与特别关联流程尚未建设。组合查询已按多个主表条件在同一表单、同一子表条件在同一实际行满足，不能跨行拼接。MVP开发旧数据可修复迁移或作废；本轮过程索引基线读取各自已保存快照，不改来源填写证据，也不把当前模板的新含义补给旧实例。未来正确数据继续按使用时快照解释。

例如输入物料批号找到显式配置追溯的字段记录和原表单；实际是否使用这批物料需有明确业务事实。按报废分类查看数量则属于业务统计。独立四页面及直接原表单定位已明确，结果保留命中位置、真实生产归属与授权DHR回查；“所有相关的报表”的其余跨报表导航仍待设计，“所有相关”限已有权限。

统计模型和规则由我们预先做好。客户负责选字段、核对结果。没有查询或统计需求的表单，照常使用。

## 2. 客户实际怎么配置

2026-10-03已确认：直接在画布点选字段或子表是主要配置入口，集中入口留给熟练后的总览与调整；页面有主次并渐进展示。此前集中配置优先的建议已替代。2026-10-05已开始改造，当前普通字段和整子表均有侧栏入口；使用时快照继续保留，客户易用性尚待试用。

首期来源形态已进一步确认：**子表是配置体验重点，主表多个分散字段组成一条业务明细也同时覆盖**。子表优先不表示只做子表。子表一次对应各列、对每行生效；主表一次选择描述同一笔业务的字段。内部数据对象和行ID不要求客户先行建模，低学习成本仍须客户试用证明。

在当前实现中，画布选中字段或整个子表后，打开左侧同级“查找与统计”入口：

1. **关联追溯项（可选，最多一项）。**选择这个真实字段记录的信息，例如物料批号；同一追溯项可被不同字段及表单复用。无需数量或单位，不改变填报方式。子表可直接选列关联，也可在整表中展开列的追溯设置。按用户最新授权直接清理旧多绑对应配置、无需兼容：移除冲突字段全部追溯映射，不任选保留第一项，合法单绑、其他字段和业务用途保留；后续导入或保存仍拒绝多绑。只清理模板对应配置，已有填写值、实例与冻结证据不删除。具体清理及验证结果另记，见[本轮确认与证据](../knowledge/evidence/trace-field-single-binding-2026-10-19.md)。
2. **配置业务统计（可选）。**选整张子表后，选择生产报工、报废或消耗等预设用途，再一次对应物料、数量等来源；点单列只查看它在整表统计中的角色，修改切换到整表。主表选择一笔业务并一次配齐相关字段；确有第二笔业务时再新增一笔。单位及物料批号可不配置。已配置、必需及错误来源外显，未配置可选来源收进“更多业务字段”；已撤下额外明细展示列入口，旧映射及正式事实不自动清除。
3. **核对并保存。**右上角“用途总览”可集中核对和模拟预览。顶部“保存”统一校验、保存配置，未配齐会提示补齐或移除，不另设启用按钮。生产实例使用时保存当时配置快照；现场暂存未完成填写值不等于模板配置可缺失必要来源。

当前字段、整子表侧栏和全表总览修改同一份配置，支持撤销和多行模拟预览；客户可维护的追溯项目录已贯通设计候选和查询条件，单列到整表编辑已互相定位。无需先把整张表归入某一种业务场景。2026-10-05的[交互改造记录](../development/form-projection-interaction-2026-10-05.md)保留历史实现说明，本轮实际差异以10-10运行修正证据为准。

配置通常在建模板或改版时完成；模板仍可按原方式编辑，已启动实例继续使用其创建时保存的配置。现场人员填表时，继续填写原来的字段。

部分字段应可配置从生产上下文自动带入。建议画布点选后分别设置取值来源与用途，带入不是第三种报表用途。系统统计归属来自实际执行，字段显示或修改不能替代它；未配检索用途也不影响统计归属。缺上下文分支已按上文明确，其他带入时点、证据持久化、刷新/编辑与多设备选择仍待定。

## 3. 用一个例子讲清楚

假设表单确实记录了：**生产批次 P 使用物料 M 的批次 L，实际用量 10 件。**这些编号已对应到正确的业务对象，以下数值仅用于演示。

| 系统需要的信息 | 客户选择的来源 |
| --- | --- |
| 生产批次 | 当前生产任务 |
| 使用物料、物料批号 | 表中的“物料名称”“物料批号” |
| 实际用量、单位 | 表中的“使用数量”“单位” |

填报完成后，有流程的表单还需等流程最终结束，系统按最终值生成一条消耗记录。之后可以：

- 在**消耗记录**查看这笔10件并直接打开来源原表单。
- 在**批次追溯**查看 P 使用了哪个物料批次。
- 在**表单追溯**按 L 找到这份表单。

过程追溯查看已保存的字段证据，正式消耗报表查看最终生效的数量事实，数量只计算一次。表单已由生产执行和作业关联到 DHR 时，也能沿这条实际关系回查。DHR 可以持续收录执行证据；相同批号文字不会自动建立 DHR 归属。

如果表上只有批号、没有用量，可以配置按批号找表，不能凭空生成消耗数量。只有文字编号时，也要区分“查到这个词”和“确认使用了这个业务对象”。

只配置设备号追溯的表单，成功保存/暂存后在来源权限内被找到，显示状态、准确实例及字段位置，不提前产生报工/报废/消耗统计明细。同字符串不同含义不混查，命中不自动证明设备使用关系或工序身份。当前过程索引独立于最终统计投影，真实保存到审批阶段的聚焦回归已执行；失效历史/A12视图仍另定。

另一个验收期望：批次B001、工序P10启动表单，统计事实归属由真实执行上下文确定，所配置的自动带入字段可以显示对应信息；不依赖额外手填批次/工序字段或配置检索用途。具体自动带入交互和生命周期仍待定。

批次最终产出按配置为最终产出的工序正式报工数量确定，工单汇总所属批次；不能把几道工序相加。报工来源字段要表达约定的产出含义，不强制取名或映射为良品数量。不良和报废按各自用途单独统计，不自动加减最终产出，也不需要额外的质量表单才能计算产出。没有采集或没有正式生效数据不代表实际数量为零；质量比率、对账和倒扣属于另行确认的需求。当前分支还没有批次/工单产出联动。

## 4. 新增客户需求时，怎样少维护

报工、报废、消耗页面使用产品固定筛选条件，业务筛选不依赖字段另配追溯用途。表单正向按真实工单、产品、生产对象等属性查支持来源内的有权已保存实例，未配追溯用途也可查；反向按明确绑定追溯项的最近保存填写值查表。DHR采用相同两向含义，多反向条件可由同一DHR内不同真实关联表单贡献；表单反向仍同表单/同实际子表行。反向打开完整DHR须标记命中表单及对应字段/实际行，其他证据保留供核对。上述查询和定位已有实现入口，具体本轮测试、浏览器及独立质量结果分别验收；不以内容编号建立归属，任意冻结汇总历史反向与A12仍另定。

例如，报废记录已经有“报废分类”，业务筛选和来源回查共用正式属性，不增加一种“追溯报废分类”字段类型。若还要按表单填写值反向查表，则显式绑定兼容追溯项，不因名字相同让业务条件变成客户追溯目录。

2026-10-05已确认将可复用的“追溯项目录”纳入MVP，配置和使用分为三步：

1. 管理员定义追溯项，例如“灭菌锅次”，类型限产品支持范围；常用项由产品预置。
2. 制表人员选中普通字段或子表列，关联该追溯项。不同名称、不同表单的字段可关联同一项。
3. 查询人员在追溯页面选择追溯项并输入锅次，查看有权限的来源表单和命中位置。常用条件固定展示，新增条件按需选择；实际生产批次/SN可输入筛选后选择对象。

定义的是查询含义，具体值在查询时输入；仅追溯无需数量或单位，命中不自动建立实体关系。九项预置中生产批次/SN、物料批号和工单号默认显示，其余六项是展开区固定条件；添加查询条件只含自定义项且默认隐藏。文本、数字及日期使用匹配控件，追溯日期由制表人明确绑定业务日期，不取创建时间。不同子表组合、复杂OR、其余目录生命周期与新含义历史补充覆盖仍分期保留。

业务统计由产品提供模型及属性，客户关联来源并查看预设报表；新追溯项不能自动成为所有指标的分组项。二期让用户基于已有正式事实设计报表，具体指标/维度、聚合、布局和权限另定，不等于客户自由建立业务模型或任意公式/联表。已撤下额外明细展示配置入口；旧映射只按其快照保留，不自动成为分组或重复计量。

这种扩展针对显示、筛选、分组。新的业务动作仍按新需求开发。

新增业务用途允许二次开发，目标是开发成本低、容易维护；不要求全业务零代码，不提前建设庞大通用规则引擎。建议共用配置和投影基础流程，由各用途独立实现业务语义，新增普通用途主要补定义、业务代码和测试。用途按业务事实定义，新报表优先复用已有事实；这项具体分工仍是建议。

用户认可不同表单提供指标、汇总到同一报表行的方向，需明确统计对象、范围和来源。例如同一范围表A良品90、表B不良5可以并列回查，不自动扣产出或计算良率；B无正式数据时不填0，A仍可展示。这是期望行为，尚非已实现声明。建议各来源先按目标粒度聚合再合并，避免多对多放大；同次事件的跨表单关联方式仍待定。

AI 可以作为后续助手，先提出字段对应关系供人核对；人工配置始终可用，首期无需依赖 AI。

竞品源码和产品可用于对照目标与能力，不照搬其交互。我们设计自己的低学习成本画布配置及易维护二开方式；本轮未验证竞品产品UI，不把用户交互评价或历史记录升级为本轮原始UI证据。

## 5. 安速康的真实表单能否适用

已核对的样本说明，需要支持几种不同情况：

| 表单情况 | 方案如何处理 |
| --- | --- |
| 清洁记录有酒精批号，没有用量 | 支持按批号找表；不生成酒精消耗数量 |
| 组件记录横向摆放多组物料、批号、数量 | 每组一起配置，预览检查对应关系 |
| 多道环节重复填写合格、不合格数 | 先确认哪一处用于正式报工，避免重复相加 |
| 复核记录没有统计需求 | 只保留表单及真实业务归属 |

样本支持这个方向，但还没有证明全部表单都已覆盖。报废单统计哪个阶段的数量、不良总数能否按原因拆分、长期记录本何时生效，都需要先确认口径。

**首期建议先打通表单查询、报工、报废、消耗，以及必要的批次和既有 DHR 关联。**不良原因统计在数量口径明确后接入。灭菌、检验、放行的完整过程追溯，以及长期记录本，还需要各自业务模块配合。

## 6. 怎样落地，怎样判断真的好用

先用代表性表单跑通“配置 → 填报完成 → 报表查询 → 回看原表”，再请没有参与设计的客户制表人员独立配置和修改。

重点观察：能否理解每项用途、能否选对来源、能否发现错配，以及需要多少次求助。多行、多列和重复数量的表单也要参与试用。

**目前能确认的是设计方向；低学习成本需要实际试用证明。**评审时最值得讨论的是：这样的配置过程是否容易理解，以及还有哪些真实表单难以表达。

配置项现在按查表、正式业务明细和必要时的分组逐步出现；这个顺序来自开发者试用反馈，尚未用客户使用频率数据验证。
