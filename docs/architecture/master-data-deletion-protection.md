# 主数据删除保护

本切片对应 DEC-0053，覆盖当前主数据页面及仍可调用的旧主数据删除接口。关联检查和原删除操作处于同一事务；成功删除沿用原有审计，阻断不产生成功删除审计。

## 页面与关系

| 删除对象 | 检查的主要关联 | 处理位置 |
| --- | --- | --- |
| 物料版本 / 派生产品 | 产品簇成员、制程配置版本、工单、作业适用规则 | 产品簇、产品管理、工单管理、作业模板 |
| 产品簇 | 产品成员、制程版本、路线、批记录模板、适用规则及历史定义 | 对应建模模块；历史数据联系管理员 |
| 制程配置版本 | 工单、生产对象 | 工单管理、批次管理；生产历史保留 |
| 工序 / 工序分类 | 路线节点、制程工序、适用规则、生产历史 / 分类下工序 | 工艺路线、产品管理、作业模板、工序管理 |
| 工艺路线及版本 | 制程版本、历史路线配置；父记录递归检查全部自有版本 | 产品管理、产品簇 |
| 文档及版本 / 分类 | 制程工序文档、SOP 引用 / 分类下文档 | 产品管理、产品簇、文档管理 |
| 表单模板及版本 / 分类 | 批记录引用、制程表单、作业图配置、执行快照、已保存实例 / 分类下模板 | 批记录模板、产品管理、作业模板、批次管理、表单实例 |
| 批记录模板及版本、目录、表单引用 | 制程版本、生产 DHR、工序表单绑定；目录仍需先处理下级目录和表单 | 产品管理、批记录模板及历史数据管理员 |
| 设备分类、类型、设备 | 分类下类型、类型下设备；设备当前无下游引用表 | 设备类型、设备列表 |
| 车间 / 旧计量单位接口 | 下级产线 / 工单 | 车间管理、工单管理 |

`DeletionRelations` 是当前已核对关系的显式清单，不是自动发现所有未来引用的机制。新增模块或引用字段时，应同时维护关联清单、数据库约束和回归测试。系统管理、生产对象删除、作业模板自身的删除规则不在本次入口范围内。

## 交互

用户点击删除后，先通过只读 `GET /api/v1/master-data/deletion-check/{type}/{id}` 检查关联。有关联时直接展示“暂不能删除”清单；无关联才显示原删除确认框。检查失败时显示错误及重试入口，不开放删除确认；取消检查后忽略迟到的结果。预检查不删除数据、不写删除审计，也不替代原生命周期限制。

用户确认后，正式删除接口仍在同一事务内复核实时关联。若确认期间新增阻断关联，返回 HTTP 409 和 `DELETION_BLOCKED` 结构化清单。弹框包含关联种类与数量、按模块分组的记录、版本、状态、所属配置路径、复制编号及处理入口；去掉顶部重复的删除目标名称、编号及当前菜单，位置使用业务名称和层级、不重复业务编号。每组分页显示，后端不截断关联记录。入口在新页面打开，处理后可在原弹窗刷新关联，不刷新整页；全部解除也不自动删除，仍需重新发起并确认。

关联组的只读 `dataType` 区分 `BUSINESS`（业务关联）、`RETAINED`（保留记录）和 `ORPHAN`（异常遗留）。默认业务关联包含实际工单、生产对象和有效配置；实例、历史生产记录及执行快照引用独立展示；业务配置所有者链缺失单独作为异常说明，不因没有定位页面就认定为法规追溯记录。同源表可拆成多个分类组。三个分类的真实引用均继续参与阻断；分类不改变生产对象不可物理删除等原契约，不新增强删、忽略快照或清理孤立数据的能力。纯审计记录不新增为待处理关联。

存在生产历史时不建议为删除主数据清空历史。原模块已有的停用或失效功能可继续使用，本切片不新增状态动作。不提供强制删除。缺少关联模块查看权限时只显示数量和联系管理员说明，不返回明细或入口。历史模块无对应现行页面时不提供误导性链接。

## 数据完整性与兼容

检查时锁定目标及拥有的子版本；数据库外键负责并发期间的最终完整性。原本随父记录清理的版本与设计内容仍属于所有权子项；它们存在外部引用时阻止父记录删除。目录单独删除继续要求先移除下级内容。

迁移 `0086-master-data-deletion-protection.sql` 使用 `NOT VALID` 添加缺失外键：既有孤立记录保留，新写入或修改后的引用必须有效，新的删除不能制造孤立引用。生成列将多态制程所有者和历史字符串 ID 映射为可约束的引用，不改原业务字段。旧分类名称引用使用延迟校验，以保留同一事务中的分类改名。

`deletion_form_reference` 仅是可重建的引用索引，不是新的表单实例或业务事实库。数据库触发器从作业图和生产执行快照同步表单版本引用，兼容字符串和数字 ID，消除 JSON 引用的并发漏检。历史源内容不重写。现有孤立引用不自动修复、不删除。

迁移前保留数据库备份。应用回退不应自动删除约束或业务记录；需要回退迁移时，必须先核对新产生的关联数据，并按迁移新增对象反向移除触发器、索引表、约束和生成列。禁止用还原旧数据覆盖期间的新业务数据。
