## 1. DHR 模块要解决的业务问题

DHR（Device/Batch History Record，在本项目中是面向生产对象的电子生产历史记录）不是一份简单的批次报告，也不是把多个表单值复制到一个新表里。它的核心是：

1. 以一个实际生产对象作为唯一业务锚点。
2. 在生产开始时锁定当时生效的工单、产品、制程、路线、DHR 模板和目录上下文。
3. 以生产对象及可信来源关系归集完整生产证据；模板目录是组织方式之一，不是 DHR 证据范围的唯一边界。
4. 保留证据的来源、版本、副本和审计关系，而不是破坏或复制原始表单。
5. 在生产完成、汇总、审核、发布/归档等阶段形成可追溯的生命周期闭环。

首版只先打通“生产开始 → DHR 实例 → 生产表单证据 → DHR 列表/详情 → 生产完成同步”的最小闭环，后续再加入汇总、补充、审批和发布。

### 2.2 首版调研时的缺口（历史时点，非当前待办）

调研时系统还缺少一套完整的 DHR 实例管理闭环，主要缺口是：

1. 没有生产对象到唯一 DHR 实例的持久化关系和唯一约束。

## 3. 冠骋功能矩阵的参考内容和本项目的解释

用户提供的功能矩阵包含四块：DHR 填报、DHR 汇总、DHR 审核、DHR 列表。它是重要的竞品/参考输入，但不是当前实现清单。

### 3.1 DHR 填报

参考矩阵的行为是：针对批次/SN 下没有 DHR 的情况创建 DHR，然后进入填报界面。

本项目的收敛决定是更严格地把创建时点放到生产事务中：

- BATCH 和 SN 都属于首版正式支持范围。
- 首次合法 `START` 时系统自动创建 DHR。
- 不允许通过一个事后手工按钮绕过生产开工创建 DHR。
- 首版页面先提供列表和只读详情，不把“DHR 填报”误做成一套独立的自由编辑表单。

未来如果需要“DHR 填报”，它应解释为对目录证据完整性和人工补充的受控处理，而不是任意修改已冻结来源表单。

### 3.2 DHR 汇总

参考矩阵描述了：

- “待汇总”和“已汇总”两个页签；
- 待汇总可进行汇总处理；
- 已汇总可查看详情或退回重新整理；
- 将生产预处理、生产事务、返工、附录、检验、检验事务、检验附录、灭菌、记录本、批次拆分、关联表单和关联 DHR 等候选证据放入目录；
- 汇总完成后可直接汇总，也可进入审核流程，并由开关控制。

本项目只借鉴目录导航、实例查看与可收起侧栏，不再采用“作业/自定义必须手动拖入目录才属于 DHR”的策略。原始截图不能证明竞品完整导出、证据保留或合规行为，本次不把竞品作为法规依据。

现行语义分为三层：

- **证据归属**：由生产对象、来源实例和受控附件关联确定，自动归集。
- **目录编排**：决定已有证据如何展示、命名和排序，人工可选。
- **导出范围**：决定本次 ZIP 输出哪些记录，不修改证据归属或审批对象。

### 3.3 DHR 审批

现行页面名称为 DHR审批，沿用我的待审／我的已审。审批对象为经核查后冻结的完整证据版本，不是手工目录中碰巧选中的几份表单。审批人可从目录或来源分类查看同一版本，检查缺项、异常处置、来源变更及签署信息。

来源有效变化自动标记、通知并阻断过时批准，但不自动执行退回。人工退回或重新整理生成新草稿、新提交版本；已审批版本及其原结论保留。详细规则见第 6.4 节。

### 3.4 DHR 列表

参考矩阵要求所有 DHR 可查看详情，并覆盖生产、灭菌、物料等模块。

本项目首版先提供基于生产对象的 DHR 列表和只读详情；只有当其他模块提供真实、可追溯的证据来源契约后，才逐步加入跨模块详情。

参考矩阵中可能存在“进行中主动创建/作废”等操作，但本项目首版不据此新增手工创建或作废状态。任何新增生命周期动作都必须单独完成状态机、权限、审计和用户确认。

## 4. 首版之前已经收敛的用户决策

以下是首版开发时已经确定的边界，后续上下文不得重新推翻或偷偷扩大：

### 4.1 BATCH 和 SN 同期支持

旧 PRD 中“批次优先、SN 后续”的表述已经落后于当前生产执行和表单实例能力。用户确认：

- DHR 首个正式切片同时支持 BATCH 和 SN；
- 两者使用同一套 DHR 实例、目录、证据和生命周期模型；
- 不能为 BATCH 和 SN 建两套逻辑；
- 验收必须同时覆盖 BATCH 和 SN。

### 4.2 DHR 创建时点和唯一性

- 生产对象是 DHR 的唯一业务锚点。
- BATCH/SN 在首次合法 `START` 时自动创建一个 DHR。
- 创建与生产开工在同一事务中，任一环节失败则整体回滚。
- 每个租户 + 生产对象最多一个有效 DHR。
- 拆分、未开工或取消阶段不创建有效 DHR。
- 首版禁止手工创建 DHR，避免绕过生产执行上下文。

### 4.3 创建时冻结上下文

DHR 创建时冻结：

- 工单和工单号；
- 产品和产品编码；
- 生产对象和对象类型；
- 产品制程版本；
- 工艺路线版本；
- DHR 模板版本；
- DHR 模板目录快照。

后续发布新模板或修改制程配置不能改写已经开始生产的 DHR。

### 4.4 首版证据聚合

- 自动聚合的首版来源是同一生产对象下的 `PRODUCTION_EXECUTION` 表单实例记录。
- 只有快照中有 `dhrItemId` 的记录才能自动匹配目录项。
- 每个 `copyId` 单独保留，不能把不同副本合并成一份。
- work-bound 和 direct-form 复用同一个来源实例时只引用一次。
- 没有目录映射的记录进入未映射区或不自动纳入有效目录项。
- 当前首版不是跨所有业务模块的正式汇总器。

### 4.5 生产完成阻断

- 进入 DHR 闭环的生产执行必须具有关联 DHR。
- 全部工序完成时必须同步把 DHR 置为 `COMPLETED`。
- 如果关联 DHR 缺失，完成动作必须失败并回滚生产状态，不能静默跳过。

### 4.6 首版页面、权限和菜单

- 首版提供 DHR 列表和只读详情。
- 菜单权限：`records.dhr-management`。
- 查询权限：`dhr.instances.view`。
- 初始化默认只授予 `ADMIN`。
- 首版不提供汇总审批、退回、发布、归档、作废、拖拽补充和人工证据挂载。

### 4.7 历史数据策略（明确选择不回填）

用户明确选择方案 A：忽略历史数据，不回填历史 DHR。

这表示：

- 功能上线前已经开工或完成的旧 BATCH/SN 不强制生成 DHR；
- 不在本体知识中增加历史兼容或历史回填策略；
- 不伪造旧操作员、旧创建时间、旧审核状态或旧汇总结果；
- 只保证新 DHR 建立后，新生产数据和新功能正常闭环；
- 首版交接时曾记录数据库 `dhr_instance` 为 0，这不是本轮数据库观察结果，也不代表当时迁移失败。

此前讨论过的 `SYSTEM/BASELINE` 是受控回填的解释，不是当前实现要求；除非用户未来重新确认，否则不要实现。

## 6. 现行汇总与审批方案（2026-09-25 直接修订）

### 6.1 目标、范围和非目标

为生产整理人员、质量审批人和查阅人员提供自动形成的完整记录集合，人工主要处理缺项、异常、附件补充和需要的交付目录，不要求逐份手工“纳入”。

保留 DHR填报、DHR汇总、DHR审批、DHR列表四个菜单，不增加同义菜单；汇总在本方案中指完整性核查及版本确认。配置、来源记录控制、审批运行时分别复用所属模块，不能把业务规则散落在页面中。

本次文档修订包括自动归集、核查、目录整理、实例/DHR审计入口、附件、冻结审批、版本详情与 ZIP 导出。暂不做打印，不新增跨批次移表、不自动放行、不自动重开生产、不改变已确认的已终止 DHR 政策，也不建立“AI 判定合规”。

成功标准：一个无缺项、无未处置异常的正常生产对象，不做任何拖拽也能核查并提交；详情、审批和完整导出解释同一证据版本。

### 6.2 证据范围与目录展示必须分离

| 对象 | 决定什么 | 不决定什么 |
| --- | --- | --- |
| 生产来源关系 | 哪份真实记录属于哪个生产对象、工序、节点/创建项 | 显示名称、展示排序 |
| DHR 证据范围 | 关联实例、附件及其版本/状态/追溯关系 | 一份记录是否已合格、是否允许放行 |
| 汇总目录编排 | 默认位置或自定义位置、别名、同级顺序 | 是否从 DHR 删除证据 |
| 核查结果 | 缺项、待完成、签署、异常处置等检查是否通过 | 通过改目录或少导出几份消除问题 |
| 导出选择 | 本次包为完整版本或选定范围 | 审批对象、原记录和 DHR 证据范围 |

1. 目录、作业、自定义来源实际存在的生产关联实例自动进入可追溯证据范围；受控关联的附件同样有默认位置。
2. 来源状态与证据存在是两个维度。未完成、待审批、失败、作废、被替代记录不能静默消失，也不能被计为合格完成证据；失败检验与复检、变更前后和处置关系须可追溯。
3. 零实例只是来源定义，不产生虚构表单或空 PDF。若该来源按冻结配置必须留记录，显示“缺项”并阻断；非适用项应能解释适用判断依据。
4. 默认目录由基础目录及作业／自定义／附件来源分区构成，所有证据都有可达位置。人工创建目录、拖拽组或实例、别名及排序只修改展示编排，不修改生产启动快照。
5. 同一版本每份证据具有唯一身份与一个有效展示位置；来源分类是检索视图，不是重复存储或重复计数。移动后默认视图通过真实身份定位同一证据。
6. 从自定义展示位置移除，动作应叫“恢复默认位置”，而不是“删除证据/未纳入”。删除非空自定义文件夹前必须明确其内容将恢复默认位置，不连带删除原记录。
7. 保留按具体作业节点或自定义创建项分组，不按模板合并不同来源。组与单份操作均可整理位置；部分整理的 x/y 只能表示已调整位置数量，不表示部分属于 DHR。
8. 现有 DIRECTORY 固定基础归属规则保留；可调整草稿显示名但不改变原模板/生产快照。根级自定义目录及子目录是展示层，不回写基础目录。
9. 已冻结版本只读；修改展示编排也通过新草稿及新版本，不就地修改曾审批或导出的目录。审批是否必需仍按适用受控策略执行。

### 6.3 核查流程与未完成记录

自动归集 → 自动检查 → 人工处理缺项/异常及补充附件 → 确认提交 → 冻结完整证据与核查结果 → 按策略审批或完成本次汇总。

- 自动关联在生产记录形成时持续发生；普通汇总整理/提交仍以生产正常完成为前提，不把“自动归集”误解成在生产中自动结案。已终止对象不进入普通汇总通道。
- 不强制人工逐条选择已自动关联的记录，也不要求为正常来源逐条写“纳入理由”。
- 检查范围不能只覆盖已创建表单：应结合冻结模板、工序/作业配置识别应有记录、数量约束和适用要求。
- 必填目录缺项、适用必需记录未完成、要求的签署或源审批未完成、来源关系无法确认等必须阻断；显示具体记录、原因和处理入口。
- 选填记录不因“选填”自动成为可以隐藏的记录。已经创建但未完成时保留状态；是否阻断按源业务和适用核查规则，不能一律要求全部完成，也不能因生产已结束直接放行。
- 已存在的未完成补录阻断保留；普通选填完工确认不自动构成 DHR 或产品放行豁免。
- 作废/替代记录保留历史与处置关系，不可替代当前应有的有效记录；不在此重新定义表单作废资格。
- 表单流程“已完成”不等于检验结论“合格”。检查应读取可识别的质量结果和处置依据；系统尚不能解释的业务字段由授权人员核查，不靠状态绿标自动判定质量通过。
- 提交时服务端重新核查证据集合及来源版本，覆盖新增实例/附件，不只检测既有实例内容变化。核查到提交间发生变化应拒绝陈旧提交并提示刷新，不能静默漏掉新记录。
- 核查结果必须包含规则依据/版本、检查时间、问题定位、处置及确认信息。自动检查不能声称判断全部生产事实真实或替代质量人员判断。

### 6.4 审批对象、状态和变化处理

保留制程版本配置 NONE/REQUIRED、REQUIRED 绑定已发布 DHR_SUMMARY 定义及版本、首次开工冻结绑定；操作员不能在汇总时临时改流程或免审。

| 情形 | 系统处理 | 人员处理 |
| --- | --- | --- |
| 检查未通过 | 阻断本次提交，定位缺项/异常 | 回来源处理或补充适用证据 |
| 检查通过、NONE | 冻结汇总版本，完成本次核查汇总 | 不产生虚构批准人或放行结果 |
| 检查通过、REQUIRED | 冻结版本并原子创建对应审批任务 | 按冻结流程进行审批 |
| 审批中来源发生有效变化或范围新增 | 标识差异、通知并阻断对过时依据的批准；不改旧快照 | 人工退回整理，提交新版本 |
| 已批准版本后出现有效变化 | 保留原批准与旧版本，显示当前证据与批准基准不一致 | 根据适用策略人工发起新版本及重审，不自动撤销历史批准 |
| 提前结束／已终止 | 沿用已确认终止和只读留证规则 | 本轮不增加终止后补录/异常结案通道 |

NONE 只是不单设 DHR 汇总审批，不能跳过源表单签署、其他适用质量审核或产品放行要求。配置责任在有权限的质量/制程管理角色，不因此文档默认所有企业均可免审。

批准必须关联精确汇总版本、审批流程版本、处理人、时间、结论和适用签署。签名如适用，应与签署时内容可靠关联，不以签名图片替代身份与签名控制。源变更申请尚未生效不等同于原证据已变更；申请状态可提示，生效与批准并发必须由服务端防护。

生产状态、汇总版本状态和产品放行状态分别显示；DHR“已完成”不得被解释为“汇总已获批准/产品已放行”。列表详情应清楚指出正在看实时资料还是具体汇总版本。

### 6.5 页面、目录、实例和日志

- 顶部：DHR/生产对象、当前版本及状态、保存/提交；概览可收起，优先展示真实表单份数、附件数和待处理问题，零问题不制造醒目警告。
- 左侧：完整记录导航；默认目录可直接工作。自定义整理为辅助操作，批记录模板同款图标和对齐；根目录新增放在“汇总目录”标题处，子目录新增放行内。
- 中间：当前实例内容预览；状态与预览入口紧邻表单标题，不把全局来源按钮塞进当前表单标题区。
- 实例列表：目录右侧独立窄面板，按需展开；单实例也支持入口，行点击默认预览首份。行操作 hover/focus 才显示，紧凑右对齐，无不存在操作的空槽；键盘可聚焦。
- 右侧：独立来源入口及可收起面板，用于按来源检索和整理，不是“待纳入 DHR 候选池”；组内“查看实例”可逐份预览。展开/收起过渡不能阻断操作或造成重复拖拽落点。
- 表单预览提供“实例操作日志”：显示填报、提交、签署、表单变更/作废等来源事件，并能定位历史版本；日志不能代替原始失败记录或变更前内容。
- DHR 列表详情的“数据审计”及汇总工作区快捷入口查看 DHR 层日志：目录编排、别名、附件关联/解除、核查确认、提交、审批、退回、新版和导出。审计关联 DHR ID、版本、操作者、时间、动作及必要前后差异/理由。
- 已提交/已批准详情默认展示该冻结版本的汇总目录；可切换来源分类，但两种视图的实例集合、别名和版本一致。查看实时资料需显式切换并提示差异，不能用实时值冒充当时审批内容。
- UI 复用 ListTableShell、TableStateCell、FormDialog、ConfirmDialog 及既有表单画布/日志组件。没有现成接口的入口须随功能实现，不做空壳按钮。

### 6.6 附件和纸质历史资料

- 委外报告、外部证书、纸质原始记录扫描件可作为受控附件；自定义表单可承载结构化信息并引用附件，但不能伪造一份在线填报替代已发生的纸质原件。
- 复原空白表单模板是未来电子填报配置，不是将历史纸质填写重新录入并冒称当时在线完成。
- 附件关联需记录稳定文件/版本标识、原文件名、类型、大小、摘要、上传者/时间、来源/用途、相关生产对象及核验信息。纸质件须区分原记录形成时间和扫描/上传时间，并可追溯原件保管位置；不倒签创建时间。
- 同一文件如真实适用于多个对象，可分别建立有依据的关联；摘要相同不等于业务重复，不能只按文件名或哈希全局去重。
- 上传、替换、解除关联实行权限和审计；替换生成新版本，不覆写历史原件。未通过文件安全和可读性检查的附件不冒充可用证据，限制类型/大小、校验实际内容、受控存储下载。
- 错误关联处理只解除该对象的关系，记录原因及原关联，不删除其他对象合法使用的文件。对审批中或已批准版本的影响执行第 6.4 节，历史版本仍可追溯原文件。
- 原件真实性、纸质转录核验、保管责任由企业 SOP 明确；软件保存过程和证据，不自动认证外部报告真假。

### 6.7 ZIP 导出（本期不做打印）

提供“完整 DHR 版本”和“选定范围”两种 ZIP 导出。后者仅选择交付范围，不改变 DHR 证据集合或审批对象；可以结合人工目录满足常见客户交付目录需求，不承诺覆盖所有特殊报表、签章或监管格式。

建议包内结构（工程方案，具体文件格式可在实现时定稿）：

- 说明与索引：DHR/生产对象、版本、核查/审批状态、导出类型、操作者、时间、文件清单和范围说明。
- 可读表单记录及必要电子数据：逐实例保留身份、来源版本、签署含义/时间和引用，不仅输出一张缺少元数据的截图。
- 原始附件：保留版本和来源对应关系。
- 追溯信息：必要实例/DHR审计、替代/作废关系及核查/批准依据可随包交付；内含机器可读清单、摘要和路径映射便于检查一致性。

完整包覆盖所选版本的全部证据，不按当前筛选器静默漏项，也不重复拼装目录和来源分类中的同一实例。部分包在包名、说明和清单标明“选定范围/非完整 DHR”；即使恰好选全，也不伪造已批准的完整包语义。

导出权限与数据访问、附件下载权限共同检查；完整包发现缺件、越权或不可读版本必须失败并明确原因，不默默跳过后报成功。特殊遮蔽/脱敏另行定义，不能把少内容包称完整。

一次导出固定同一证据版本，不混入执行期间新增或变更的内容；失败保留可定位的任务结果，重试不混版。路径防穿越、同名文件消歧、摘要与文件数量校验、下载授权均属验收项。草稿/实时预览导出若后续开放，必须标为“未确认”，不能冒充正式版本。

### 6.8 “错批次”的准确边界

original-evidence：ProductionExecutionService 在当前生产对象事务中取执行快照；FormInstanceRecordService.saved 以 objectId + operationId + copyId 定位记录，并从快照解析 formId。作业与工序来源不是用户手工选一个批次归属后随意建单。自定义 ATTACH_FORM 也绑定当前生产对象/工序，人工选择的是在何处创建及引用什么模板。

因此不将“正常自动创建会随意串批”作为已发生事实，也不据此设计跨批次搬运表单：

| 场景 | 性质 | 处理边界 |
| --- | --- | --- |
| 在 A 批次页面录入 B 批次测量值 | 归属正确、内容录错；自动表单也可能发生的人为风险，不是已证实事故 | 回来源按状态允许的填报修改或表单变更处理，保留原内容和审计 |
| 在错误生产上下文追加自定义表单 | 人工创建位置/业务适用性错误 | 按来源记录控制的资格处理；本设计不决定活动记录作废边界 |
| 给 A 批次上传 B 批次外部报告 | 附件关系错误 | 受控解除错误关联并正确关联；历史与审批影响保留 |
| 自动来源归属真的错误 | 异常系统/接口问题，尚无本次复现证据 | 定位来源绑定与数据修复方案，不提供普通用户拖拽换批次 |

目录拖拽绝不能用于纠正生产事实、改变 objectId 或工序归属。
