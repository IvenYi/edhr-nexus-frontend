# 生产执行多份表单设计与验收

状态：规则已确认，实现、聚焦测试与隔离浏览器验收已完成；独立质量复验 passed。新实例调度限制与原服务未更新的边界见下方验证记录。
决策包初始基线：0.3.12；本体更新后为 0.3.13。权威规则见 docs/knowledge/rules/production-form-copies.yaml。

## 用户已确认

- 左侧“填报”下方展示“当前填报表单”、表单名称，以及表单编码、表单版本、表单份数、当前序列、表单模板分类。
- 表单份数表示同一表单创建的份数；当前序列表示正在查看的第几份，不是工序表单列表中的序号。
- 由操作员在填报时按需新增份数，不采用固定配置份数。
- 提交本份与结束填报分开：提交一份后仍可新增，操作员通过“结束本表单填报”明确结束本阶段；必填检查所有份已完成，非必填提示并保留未完成份进行中，再让外层作业继续。
- 必填表单：所有已创建份均需完成，才能允许工序完工。
- 非必填表单：工序完工时告知存在未完成表单，未完成表单维持进行中，不得因工序完工而变为已完成。
- 非必填表单后续应有补填入口；本轮先设计状态保留，入口开放作为后续阶段。
- 本功能恢复项目门禁，涉及多份实例、生产完工规则、状态与追溯，按 L2 管理。
- 每份记录本份新增数量，按当前工序累加；第一份良品 10、第二份良品 12，汇总为 22。

## 交互与实现边界

- 表单名称使用紧凑选择入口；长名称换行。下方键值信息沿用标签居左、值居右的样式。
- 为当前表单提供“新增一份”和份序列选择。每份持有独立标识、数据、流程节点、保存/提交/审批状态；切换时保留现有未保存提醒。
- 新增使用该生产执行快照内的表单版本，避免同一批次因主数据更新而混用版本。
- 表单组状态与各份状态分开。只要存在未完成份，组状态就不能是已完成；某份已经完成的记录不得被整体回写为进行中。
- “完成”沿用既有表单流程的最终完成状态；保存不算完成，有审批流程时仅提交也不自动等同完成。
- 工序完工检查返回必填未完成项作为阻断项，非必填未完成项作为提示项。提示需要列明表单名称和未完成份序号。
- 工序完工只更新工序自身状态，不自动完成、删除或清空未完成的非必填表单份。
- 后续补填建议保持原工序完工时间与执行历史，新增可追溯的补填动作；不隐式重开工序。
- 历史执行数据保留原数据、状态、签名和审计关联；旧在途单份在下一次有效填报动作中建立份组，统一使用显式结束；已完成旧单份不重开，不撤回既有作业节点。

## 决策收敛与范围限制

1. 数量汇总已确认采用各份增量累加；再次保存某份替换该份数值，不把保存事件重复累加。
2. 作业流程中的表单节点：用户已确认显式“结束本表单填报”后才推进外层作业。实现时须核对原有完成传播，避免首份完成后无法新增，或使非必填表单通过“作业未完成”间接阻断工序。
3. 非必填使用明确告知确认对话框，列出表单名称和未完成份；待审批也属于未完成。
4. 后续补填的对象状态边界、人员权限、签名与审计，以及关闭/取消/已冻结对象的处理，尚未定义；不能直接解除全局完工后的写入限制。
5. 新执行快照冻结表单模板分类。历史快照没有该字段时兼容展示模板当前分类，并注明来源；不回写旧快照。

## 本轮实现方案

### 左侧当前表单

从上到下为“当前填报表单”、可切换的完整表单名称、五项键值信息：

| 标签 | 展示示例 | 来源 |
| --- | --- | --- |
| 表单编码 | FR-001 | 执行快照中的表单编码 |
| 表单版本 | V1.0 | 执行快照中的表单版本 |
| 表单份数 | 3 | 当前表单绑定下已创建的份实例数 |
| 当前序列 | 第 2 份 | 当前选中的份实例，可切换 |
| 表单模板分类 | 生产记录 | 新执行使用冻结分类；旧快照兼容展示当前分类 |

示例数值仅说明布局，不是默认业务值。键值区域后放紧凑的“新增一份”入口；不铺开所有份的卡片。序列选择项同时标明“第几份 · 进行中/已完成”，避免份数多时撑高左侧。右侧展示所选份的内容及原有保存、提交、审批等动作。

### 提交本份与结束本表单

用户已确认新增“结束本表单填报”动作。以下为该动作的交互及实现细化：

1. 新增一份只创建独立数据实例，不从上一份复制业务值、签名或审批状态。
2. 提交本份只推进这一份原有的表单流程，不代表操作员不再新增。
3. 结束本表单表示当前生产阶段不再新增份。必填表单的所有已创建份须已完成；非必填表单允许在提示未完成份后结束当前填报阶段。
4. 结束阶段和完成数据是两个不同事实。存在未完成份时，表单组仍为进行中；不得以“已结束新增”替换表单完成状态。
5. 作业绑定表单在结束本表单时才推进对应的外层表单节点；不会顺带完成后续人工确认或其他作业节点。
6. 工序完工仍检查其余作业与前置条件。对非必填表单的宽免不能变成跳过整个作业流程。
7. 在途旧单份沿用原标识纳入份组，不自动撤回已经推进的外层作业节点。

### 工序完工提示

- 必填示例：“无法完工：内毒素检验记录，第 2、3 份未完成。”点击可定位具体份。
- 非必填示例：“无菌检验记录，第 2 份仍在进行中。工序完工后保留该份未完成状态。”显示具体表单及份，避免只有笼统数量。
- 两类同时存在时，优先显示阻断项；不能通过确认非必填提示绕过必填阻断。
- 无未完成份时不新增提示步骤。
- 完工判断以服务端同一修订号下的实例集合为准；确认提示后若他人新增或修改，重新校验，避免只检查页面旧数据。

### 数据契约建议

- `formId` 继续标识配置中的表单绑定；新增独立 `instanceId` 标识某一份，`sequence` 是该绑定内的稳定展示序列。
- 表单名称或模板版本相同不代表同一份，不能以名称或版本号作为写入目标。
- 每份分别保存 values、流程状态、当前节点、审批候选、保存时间及签名引用。
- 表单组另外保存是否结束本阶段新增的事实；聚合完成状态从各份最终状态计算。
- 服务端创建序号和实例标识，复用现有事务锁及 revision 校验，防止两个操作员新增出相同序列。
- 保存、提交、审批、退回以及文件与签名证据校验必须定位具体份；历史记录应显示“表单名称 · 第 N 份”。
- 已有单份数据保留原关联，不通过重建空白份替换旧记录；读写兼容与迁移策略需在实现前验证。

### 验收用例

| 场景 | 预期 |
| --- | --- |
| 新增第 2 份并保存 | 第 1 份数据、审批与签名不改变 |
| 必填共 3 份，第 2 份仍待审批 | 表单组进行中；不能工序完工 |
| 必填全部份最终完成 | 不再由该表单阻断，其他工序条件继续校验 |
| 非必填存在未完成份 | 完工前具体提示；允许按规则继续，未完成份仍进行中 |
| 必填与非必填同时未完成 | 不能通过确认提示绕过必填阻断 |
| 作业内非必填表单结束阶段 | 只推进该表单节点，后续作业动作仍需执行 |
| 新增份前切换存在未保存内容 | 沿用未保存保护，不丢失草稿 |
| 两人同时新增或提交 | 不重复序列、不覆盖他人数据，旧 revision 请求明确失败 |
| 工序完工后查看非必填未完成份 | 仍能区分工序已完工与表单进行中；本阶段不伪造可补填入口 |
| 重读历史单份对象 | 原值、状态、记录和签名关联保持可追溯 |
| 多份数量投影 | 良品 10 + 12 = 22；第二份改为 13 后为 23，不重复累计保存事件 |

## 影响分析

- 直接影响：执行表单由一个绑定对应单份状态，扩展为一个绑定下的多份实例；份序列、动作目标、状态聚合、前端选择与完工提示均需调整。
- 传递影响：作业表单节点推进、直接表单与作业表单的 fulfilledBy 关联、产出汇总、记录类型中的份定位、签名与文件引用。
- 潜在影响：DHR 完整性及冻结规则、追溯读取、后续补填入口；本轮未授权直接改变这些模块。
- 不受影响：工艺路线前置依赖、SOP 阅读与版本、扫码对象选择。不得借此扩大重构范围。
- 兼容与迁移：保留现有单份事实；区分新对象与在途/完工对象，保证旧签名及审计仍可定位原表单。
- 快照：保持生产执行引用的表单版本与字段用途固定；新增份引用同一受控依据。
- 审计：新增份及各份动作需能定位批次/SN、工序、表单绑定、实例和序列，不能只记录模板名称。
- 权限：每份继续使用既有字段权限、审批和签名约束；后续补填需独立范围校验。
- 验证：覆盖必填/非必填、多份状态混合、保存与审批、工序提示/阻断、作业节点推进、跨份串写、并发新增与提交、数量重复计入、历史单份兼容、审计与签名关联。
- 扩展路径建议：product-core + standard-action。实例与状态规则归生产执行内核；新增份及将来的补填是明确动作，不靠页面临时数组模拟持久化。

## 实现证据

- `gmp-platform/frontend/src/api/production-execution.ts`：增加 formCopies 可用动作、份标识集合及实例控制；命令支持 instanceId 和 acknowledgeIncomplete。
- `gmp-platform/backend/src/main/java/com/zencas/edhr/production/service/ExecutionSnapshotBuilder.java`：按工序绑定与作业节点构造表单，并通过 fulfilledBy 关联直接表单与作业表单。
- `gmp-platform/backend/src/main/java/com/zencas/edhr/production/service/ProductionExecutionEngine.java`：formAction 定位具体份；新增组仅显式 END_FORM 推进外层表单节点；必填逐份阻断、非必填告知、其他作业继续校验。
- `gmp-platform/backend/src/main/java/com/zencas/edhr/production/service/ExecutionFormCopies.java`：formGroups 保存 instanceIds 和 ended 事实；原 forms 保留各份状态，旧单份保留原标识及签名，不撤回已推进的旧作业节点。
- `gmp-platform/backend/src/main/java/com/zencas/edhr/production/service/ProductionExecutionService.java`：生产对象和工单状态进一步限制写入，完工工序的表单不可操作。
- `gmp-platform/backend/src/main/java/com/zencas/edhr/production/service/ExecutionOutputSummary.java`：按当前工序各份已保存用途字段累加，忽略 fulfilledBy 别名，不改批次最终数量。
