# DHR 提前结束生命周期设计与实施记录

日期：2026-09-23。知识基线：0.3.24。执行级别：L2。

本文先形成产品方案；2026-09-23 用户确认按本期推荐边界实施，正式决策见 DEC-0069。下文保留设计时的证据、取舍和暂缓范围；实际实现状态以第 11 节及验证记录为准，不替代 DEC-0062、DEC-0063、DEC-0068。

适用对象：生产负责人执行提前结束，填报人理解为何不能继续填写，质量人员追溯终止时证据；系统管理员不因管理身份绕过记录控制。适用现有 eDHR 部署与权限模型，无 AI 决策功能。成功标准是同一 DHR 在页面、接口和可执行动作上的含义一致，且终止前后的真实证据不丢失、不被误标为批准。

## 1. 问题与结论

用户确认的问题：DHR 页面显示关联生产对象的“提前结束”，DHR 自身却仍为 IN_PROGRESS，会让客户误解；各页面状态名称、标签和可用动作必须一致。

建议：生产提前结束时，关联 DHR 同步进入真实的“已终止”状态。它表示这份生产记录停止正常推进，不表示已有记录无效，更不表示审核通过或产品放行。用户只执行一次生产对象的“提前结束”，不再去 DHR 页面补点一次“作废/结案”。

当前实现只是统一了生产状态的展示，尚未闭合 DHR 生命周期；不能继续用展示层覆盖掩盖这个差异。

## 3. 面向用户的一套 DHR 状态

列表、填报工作台及详情中，只要展示的是整个 DHR，统一字段名为 **DHR 状态**。生产对象仍有自己的生产状态，但不再冒充 DHR 状态。

| DHR 状态 | 业务含义 | 主要操作 |
| --- | --- | --- |
| 填报中 | 生产尚在进行，按节点权限采集记录 | 填报、查看 |
| 待汇总 | 生产正常完工，尚未开始整理证据 | 汇总；符合既有权限时追加补录 |
| 汇总中 | 正在整理当前汇总草稿，包括退回后的草稿 | 整理汇总 |
| 待审核 | 汇总已提交，等待审核 | 查看；审核人在审核菜单处理 |
| 已完成 | 当前汇总已正式定版 | 查看；按已有规则人工发起新版本 |
| 已终止 | 关联生产对象提前结束，这份 DHR 停止正常推进 | 查看记录、终止原因和历史 |

正常路径：填报中 → 待汇总 → 汇总中 → 待审核 → 已完成。

- 冻结审核策略为 NONE 时，提交汇总可由汇总中直接到已完成；详情显示“按配置免审核定版”，不能写“审核通过”。
- 人工退回：待审核 → 汇总中，保留退回原因；不增加含义重复的总体状态。
- 人工重新整理正式版本：已完成 → 汇总中，旧正式版本及其审批历史不变。已完成不是永久禁止产生新版本的意思。
- 异常路径：填报中 → 已终止。终止不自动走汇总、审批或放行，不恢复生产。
- “已完成”和“已终止”均不等于产品已放行。
- 审核菜单的“处理状态”属于审核任务，可保留；不应为表面一致而强行改成 DHR 状态。

实现建议：新增持久化 DHR 终止状态（建议代码 EARLY_TERMINATED）。正常路径兼容现有 DHR.status 与 summaryStatus，由后端统一产出 displayStatus 与允许动作；所有列表过滤、计数和详情使用同一规则，禁止各页面自行推导。原始 COMPLETED 仍只是生产采集结束，不能直接翻译成总体“已完成”。非法组合返回明确的状态异常与追踪信息，不静默兜底为正常状态。

## 4. 提前结束动作及记录保留

1. 用户在已有生产对象入口发起提前结束，填写原因。确认框说明：“将停止该批次/SN的生产和 DHR 填报；已保存记录保留，DHR 标记为已终止。”
2. 后端在同一事务完成生产对象结束、DHR 终止、终止记录留存及必要的执行阻断。失败全部回滚，不能一边成功一边仍收集。
3. 保存操作者、服务端时间、原因、原状态、关联生产动作和版本标识。相同命令重试不覆盖首次终止事实。
4. 原表单实例、已完成状态、签名及审计历史保留。未完成记录不得标成已完成或自动作废；在 DHR 上下文明确显示“未完成 · 已停止”。尚未实际产生的实例不能补造。
5. 留存终止时服务端已保存的数据（包括已暂存但未提交审批的内容）和证据引用，能还原当时的目录及三类来源、不同实例。不得把浏览器未保存内容当作证据。终止留存不是 DhrSummaryVersion，不产生“已审核汇总”。具体采用已有不可变记录版本引用还是独立快照，在实现时核对可用能力，不能只存可变引用。
6. 终止后，普通填报及生产执行入口都不能继续修改。所属生产执行及普通表单流程的待办须停止可执行性并记录原因；不能仅把 DHR 按钮隐藏，而保留通用表单/审批接口绕过路径。这不禁止后续独立发起的受控记录变更/作废审批，其资格由记录控制模块判断。共享证据不按整个表单模板或关联批次进行批量作废；共享实例需逐项识别其所属执行上下文。

本期只覆盖既有生产对象提前结束及工单聚合，不顺便新增工单级直接提前结束命令，也不改变已正常完成的其他批次/DHR。

## 5. 终止后还能做什么

| 行为 | 建议边界 | 是否改变“已终止” |
| --- | --- | --- |
| 查阅已有表单和终止记录 | 保留原有数据范围及查看权限 | 否 |
| 表单受控变更/作废 | 由已有记录控制模块判定资格、权限、签名和审批；DHR 不另建一套规则 | 否 |
| 终止后的追加补录 | 不在本期默认开放。若确认需要，只记录终止前真实发生且遗漏的事实，新增实例并保留补录时间、事实发生时间及原因，不能恢复生产 | 否 |
| 恢复生产、把终止改成正常完成 | 本方案不提供 | — |
| 异常结案审核 | 如企业 SOP 要求，单独明确目标和责任后设计；不能把终止自动等同“质量已结案” | 待单独决策 |

终止后的表单受控变更不得替换终止时留存版本；详情保留终止时视图，对后续有效变化给出提示并提供单独查看入口。原始记录状态与“在本 DHR 中是否还允许操作”是两个维度，应分别解释。

本期不新增菜单；低频补录不升级为所有页面的主按钮。正常完工后的既有补录、审核中证据影响阻断、人工退回与新版本机制不变。

## 6. 页面与交互

- **DHR 列表**：统一 DHR 状态查询及右侧固定状态列；已终止可被筛选和查看，不隐藏历史。状态使用公共 StatusBadge，不另造视觉体系。
- **DHR 填报**：默认聚焦填报中；切换状态可查历史。可填报行沿用填报图标，只读终止行使用已有预览图标与“查看记录”提示，不能继续叫“打开填报”却不给原因。
- **DHR 详情**：顶部“已终止”，紧邻简短说明“批次于……提前结束，已保存记录保留供查阅”。原因、操作者、时间可展开查看。不要整屏警告或铺满禁用按钮。目录、作业、自定义及可收起实例列表保持现有结构。
- **DHR 汇总/审核**：终止记录不进入普通待汇总/待审核队列；通过旧链接访问时展示只读原因，不产生假草稿或假待办。
- **生产页面**：继续使用“提前结束”。详情用一句“批次提前结束，DHR 已终止”说明关联，不让客户理解内部 IN_PROGRESS 枚举。
- 复用 ListTableShell、StatusBadge、FormDialog、ConfirmDialog 及项目既有预览/填报图标；不改变通用列表首列字重和查询区规范。

## 7. 影响与实现风险

extensionStrategy：`product-core` + `transaction-orchestration`。生产模块拥有终止命令和生产状态；DHR 模块拥有记录生命周期、状态投影及终止留存；表单/工作流模块拥有实例控制和任务动作，禁止页面散落客户特例。

- 直接影响：DHR 实体状态、查询 DTO、允许动作、四个 DHR 页面及生产终止事务。
- 传递影响：通用填报/审批入口、执行待办、共享表单、汇总候选查询、审计与状态筛选计数。
- 潜在影响：现有工作流任务与运行时投影的边界、记录变更后的历史版本读取能力；实现前核对，不假设独立待办系统已完整存在。
- 不受影响：制程版本绑定、DHR_SUMMARY 冻结策略、不可变汇总版本、基础目录、三种实例来源、产品放行语义。
- 并发：沿用工单→生产对象等既有锁顺序，补齐 DHR/证据提交的串行化边界；终止与保存、正常完工、审核动作竞争只能产生一个合法结果。发现已汇总/已正式版本与生产进行中冲突时阻止自动转换，不能覆盖正式历史。
- 权限：查看权限不等于终止权限。复用生产终止权限；是否需额外签名/质量批准取决于确认后的业务制度，不因本方案私自免除或新增。
- 审计：记录真实事件和上下文，终止后补充、更正另记时间及责任人，不回写原事实。
- 数据保护：当前按默认单租户部署设计，不宣称已实现多租户隔离；多租户能力属于后续统一架构范围。终止记录与原始表单须遵循企业确定的留存期限、备份恢复及授权导出要求，不因终止降低保留要求或开放下载权限；相关能力的现有覆盖程度须在实施时核对。恢复数据时须同时保持生产状态、DHR 状态、终止留存和审计关联一致，纳入实施验证。
- 历史迁移：仅对明确的“生产已提前结束、DHR仍IN_PROGRESS、无汇总草稿/版本”的记录做可审计、幂等修正。冲突记录列清单人工核对。旧数据缺少终止时快照/操作者时明确标缺失，不能用迁移时数据冒充过去现场；保留已有记录，不重建数据库。

## 8. 验收条件（实施后执行）

1. 批次和 SN 提前结束后，刷新所有 DHR 页面均显示已终止；接口真实状态也已终止。
2. 操作只需一次生产确认；事务任一步失败，生产与 DHR 均不留下部分成功。
3. 原已完成表单保持已完成；未完成实例标明已停止；未产生实例不伪造；多实例不会丢失。
4. 终止时目录和已保存数据可追溯；后续有效变更不覆盖终止留存。
5. DHR、生产、通用表单及工作流接口均不能绕过终止限制；共享实例不被误作废。
6. 终止 DHR 不进入普通汇总/审核待办，旧链接可说明原因并只读查看。
7. 正常生产完工显示待汇总，而非已完成；REQUIRED 与 NONE 两条定版路径正确。
8. 正常退回、正式版本重新整理和证据影响机制仍保持原历史不变。
9. 并发保存/终止/完工、重复命令和过期版本请求不产生双重状态或覆盖首次终止时间。
10. 其他已完工批次及其 DHR 不受影响；权限隔离和无权访问仍有效。
11. 历史修正可重复执行且有审计；存在汇总版本冲突或历史证据不足时不臆造信息。
12. 列表标签、过滤结果、计数、只读提示、图标语义一致；终止信息不挤占正常目录与表单查看空间。
