# 自主查知识的表单 Agent 实验

这是内部实验脚本，不是已发布的产品 Agent。使用同一工具协议，让 DeepSeek 与 OpenAI 自主检索本仓库知识并操作现有表单 API。不开发页面，不连接生产库。第一轮固定知识包和证据保留在 `scripts/ai-form-feasibility` 及其输出目录。

## 输入与执行边界

- 复用三张空白脱敏 Excel 的确定性导入结果。模型看文字、原网格尺寸及合并范围；本轮未给模型原件图像、边框样式或视觉截图。静态样式由本地编译器保留。
- `knowledge.mjs` 从 Git 跟踪的 `docs/knowledge/*.yaml` 及子目录建立 ID 索引，排除 schema；保留记录状态、可见性、父项、来源提交/文件摘要与显式引用。它是内部读取适配器，不是客户知识发布服务。
- `tools.mjs` 提供搜索、按 ID 读取、概念/引用邻接查询、实际目录/候选/当前模板关系查询、保存和读回检查。模型不能执行任意文件、HTTP、SQL 或命令。
- `layout.mjs` 将局部比例位置落实为现有画布支持的真实细分行列；复合原文拆分必须保持全部非空白字符和顺序。这里未新增前端渲染能力。
- 固定写入 `127.0.0.1:18092` 的独立实验后端；模板写目标由实验会话创建。使用实验管理员，不能将该验证解释为租户隔离或生产权限验收。保存前比较旧设计只能检测已发生的外部修改，不是原子 CAS。
- 模型没有评估标准答案、旧配置脚本或其他模型结果。独立评估脚本不可加入工具、检索目录或模型提示词。

## 本机运行

依赖沿用项目安装的 Node、Java 21、PostgreSQL、前端 ExcelJS/esbuild/yaml；无需新增 SDK。

1. `.env.ai.local` 中配置 `DEEPSEEK_API_KEY` 和 `OPENAI_API_KEY`，保持 Git 忽略及 `0600` 权限。
2. 在新数据库上启动与当前源码对应的后端，明确设置 `SERVER_ADDRESS=127.0.0.1`、`SERVER_PORT=18092` 和 `SPRING_DATASOURCE_URL`。此次数据库名为 `edhr_ai_agent_20261112_b`，不可把端口指向业务库。
3. `node --test scripts/ai-form-agent/agent.test.mjs`
4. `node scripts/ai-form-agent/assess.mjs --freeze`：固定验收文件后再跑正式样本。
5. `node scripts/ai-form-agent/run.mjs`：三表 × 两模型 × 两次。可传具体任务名，如 `clean-openai-1`。会调用收费 API。
6. `node scripts/ai-form-agent/assess.mjs`：评分真实保存结果；另在既有设计器里检查版式及模拟填写。

Node 不自动使用 macOS 系统代理。如本机既有代理为 `127.0.0.1:7890`，可在上述模型命令前设置 `NODE_USE_ENV_PROXY=1 HTTPS_PROXY=http://127.0.0.1:7890 NO_PROXY=localhost,127.0.0.1,api.deepseek.com`。代理地址应以实际本机配置为准；不修改系统网络设置。

当前模型为 `deepseek-flash` 与 `gpt-6.1-sol`，均使用 `high` 推理，最多 26 轮，每次最多 20,000 输出 token。每任务设置约 3 美元的保守估算停止阈值；估算不是账户账单或供应商硬消费上限。DeepSeek 估算采用峰时价，OpenAI 将输入保守按 cache-write 价格计算。网络/供应商错误保留失败，不无限重试收费请求。

输出在 `output/ai-form-agent-v2-20261112`：固定协议、源码快照、验收、连接探针、每次响应和工具调用、保存/读回、结果、独立评分及专业门禁。协议改变后拒绝复用目录；中断任务不会被静默重跑。要开新批次应使用新的实验目录和数据库，保留旧失败证据。

## 本批次源码与补充验证

12 次正式运行使用同一份初始协议和已加载源码，保存在 `protocol.json` 与 `source-snapshot.json`。当前脚本含运行中发现的适配器修正，因此不能用当前脚本覆盖本批次重新生成结果：原先引用依据只接受标签单格，现接受合法范围及工作表限定坐标；重命名操作原先强制先调用特定检查工具，现直接读取实际目标再修改；布局编译器补充未占用空白格的合并；预算预估补计固定指令及工具描述。

补充验证使用独立副本，不计入 12 次模型比较：

- `continue.mjs`：同一表单的后续自然语言改名，核对其他模型、布局、用途和流程完全相同。首次 OpenAI 未在六轮内完成，保留失败；适配器修正后 `--retest` 的两模型均完成。它验证绑定目标后的连续编辑动作，不代表已实现长期会话记忆。
- `replay-layout.mjs`：将相同模型输出用修正后的布局编译器生成两份新副本，断言业务模型完全不变并真实保存读回；没有再次调用模型。浏览器仍发现细网格与文字裁切，不能视为版式验收通过。
- `agent.test.mjs`：六项聚焦检查；实际调用、审计与浏览器证据另存输出目录。

脚本使用固定批次目录及模板编码。已有批次只读取证据；新批次须先改为独立目录/数据库并重新固定协议，不能把复测覆盖成原始成功结果。

## 结论边界

核心字段覆盖沿用第一轮独立定义（15/67/17），不等于完整准确率。`coreBinding=false` 可能是缺失、正确暂缓或错误配置，必须结合问题和业务依据人工区分。合成值的 projection-preview 只验证投影函数，不证明真实引用授权、正式签署、生产提交或统计归属。两次重复只用于发现波动，不能给出统计意义上的模型排名。
